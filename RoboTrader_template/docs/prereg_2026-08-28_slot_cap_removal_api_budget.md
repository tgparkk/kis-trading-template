### P1 — 슬롯 거부 소멸 · 등록 수 항등식 (발효 첫 거래일 D)

> **예측 (동결)**
> ① `grep -c "최대 관리 종목 수" logs/robotrader_template_<D>_*.log` = **0**
> ② `[E6] 다중 전략 후보 등록 완료: X종목` 의 X = **Σ_s (`[E6] {s}: 후보 N종목` 의 N)** — 즉 §3-0 스크립트의 `IDENT` 가 `warn = 0` 인 채로 참
> ③ `slots = boot + new` 와 `polled N` 이 **같다**
> ④ `slots` = **§3-0-b 로 사전 산출한 그날의 수요**(`|부팅 코드 ∪ 전 전략 후보 풀 코드|`), 오차 0

**기대값의 사전 산출법** (D 당일 09:05 에 계산 가능):

```
pool_s   = screener_snapshots(D-1, s) 를 rank 순으로 훑어
           로그 `후보 제외` 에 나온 코드를 빼고 앞에서 10개
Σ후보    = Σ_s |pool_s|
등록수   = Σ후보                                  ← P1-② 의 기대값 (경고 0 이므로)
신규슬롯 = |{ pool_s 의 모든 코드 } \ { 부팅 복원 코드 }|
slots    = |부팅 복원 코드| + 신규슬롯             ← P1-③ 의 기대값

침묵     = |{ (코드, s) : 코드 ∈ pool_s 이고 s 가 그 코드를 이미 보유 }|
코드중복 = |{ (코드, s) : 코드 ∈ pool_s 이고 그 코드를 «다른» 전략이 이미 등록 }|
09:00 「선정 완료」 줄 수 = 등록수 − 침묵          ← 부수 확인용
```

🔑 **`등록 완료` 는 침묵분을 «포함»한다** — `bot/candidate_loader.py:203-207` 이 `success == True` 를 세는데, 침묵 경로(`core/trading/order_execution.py:126-127`)도 True 를 돌려준다. 08-28 의 `48 = 43줄 + 침묵 5` 가 그 뜻이다. 따라서 경고가 0 이면 **등록수 = Σ후보** 이고, 08-28 조건이면 **58**이다. 침묵은 「선정 완료 로그가 안 남는 분」일 뿐 등록 실패가 아니다.

**④ 의 검증 절차** — 발효일 D 의 로그에 §3-0-b 스크립트를 돌리면 `demand` · `N` · `warn` 이 한 줄로 나온다. 예측은 **`demand == N` 이고 `warn == 0`** 이다.
그날 수요가 120 을 넘으면(관측 14세션엔 없었다) `warn > 0` 이 되고 `demand > N` 이 된다 — 그때는 **예측 실패가 아니라 안 C 의 한도가 실제로 물린 것**이므로 §6 Q1 로 되돌아간다. 두 경우를 로그에서 «구분»할 수 있다는 점이 이 형태를 고른 이유다.

### P5 — 매매 «룰» 결과는 가용성 경로 외로 바뀌지 않는다

이 변경은 후보 «선정»·진입 룰·청산 룰·사이징 코드를 **한 줄도 건드리지 않는다.** 결합은 두 개뿐이고 둘 다 관측 가능하다.

> **예측 (동결)**
> ① 후보 산출 계층 불변 — 각 전략의 `[E6] {s}: 후보 N종목` 과 `안전성 필터: A건 조회 → B건 통과 (C건 제외)` 가 **D-1 스냅샷 + `후보 제외` 로그로 완전히 재구성**된다(§3-0 SQL).
> ② 굶지 않았던 전략에도 **같은 식**이 성립: 첫 라운드 `매수검토` = `|pool_s|` − `|pool_s ∩ 자기 보유|`.
> ③ 코드중복 조기반환 유지 — `09:00 선정 완료 줄 수` − `09:00 과거 데이터 수집 시작 줄 수` = 전략 간 코드중복 수(08-28 조건이면 3).
> ④ **`median(매도검토)` ≤ 63.** 직전 5세션(08-24~28) 실측은 **31 · 37 · 40 · 40 · 37**(평균 37.0), 08-10 이후 14세션 분포는 **25 ~ 62**(최댓값 62 = 08-11)다.
> 🔴 **임계를 60 이 아니라 63 으로 잡은 이유(m11)** — 60 이면 **귀무에서 이미 1/14 이 초과한다**(08-11 의 62). 귀무가 넘는 선을 임계로 쓰면 판별력이 없다. 63 = 14세션 관측 최댓값 «바로 위» ⇒ 「과거 최악(62)까지는 허용, 그걸 넘으면 굶김 해소가 포지션 폭증으로 번진 것」으로 읽는다. 그래도 1회 초과만으로 단정하지 않는다 — **2세션 연속 초과**를 신호로 본다.
> ⚠️ 초안의 「직전 5세션 36~41」은 **틀렸다** — 그건 세션 1회 로그(`손익절 체크 시작`)의 값 36/28/36/41/40 이었고 범위도 28~41 이었다(B3·B8).

🔴 **유일하게 인정하는 결합 = 타이밍이다.** N 이 80→90 이 되면 모든 전략의 손익절 점검이 **8.6%**(12.64→13.73초) 늦어지고, 그것이 체결가를 바꿀 수 있다.
⇒ ***이 변경 전후로 페이퍼 성적을 이어 붙여 비교하면 안 된다*** (§5-2 R7).
