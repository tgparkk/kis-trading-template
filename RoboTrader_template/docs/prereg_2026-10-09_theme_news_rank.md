A 종목은 「2차전지(소재/부품)」 테마 소속이다. 10-19 15:30 ~ 10-20 09:00 사이 그 테마의 **A 를 뺀 다른 종목들**에 붙은 언론 기사가 14건인데, 지난 20거래일 같은 시간대 평균은 3건이었다 → 열기 = (14+1)/(3+1) = 3.75. 그날 적격 테마 250개 중 이보다 열기가 높거나 같은 테마가 4개뿐이면 p = 5/250 = 0.02, A 의 적격 테마가 2개면 p = 0.04 → S = 1.40. 후보 36개를 S 로 줄 세운 순서와 «T 시가에 샀다면 T 종가에 몇 %» 순서가 얼마나 같은지(순위 상관)를 매일 재서 60거래일 평균을 본다.

## 2. 정의 (동결 대상)

### 2-1. 날짜·시각

- **T** = 매수일(KOSPI 거래일) · **D** = T 의 직전 KOSPI 거래일(= 그날 후보의 `scan_date`). 달력 = `daily_prices` 의사티커 `KOSPI` 의 `date` 열(REGISTRY 공통 제약 SSOT · `date` 는 text 라 문자열 비교 · SQL (CAL) §2-7).
- 모든 시각은 **KST**. `news.created_at`·`published_at` 은 tz 없는 KST(세션 `TIME ZONE 'Asia/Seoul'` · q01 · `created_at` 기본값 now()). 러너는 창 안 행의 `created_at ≥ 2026-03-09`(UTC 결함 구간 밖)를 단언하고 어긋나면 중단한다.

### 2-2. 후보 · 경기장

- 전략 3개: `book_pullback_ma20` · `minervini_volume_dryup` · `daytrading_3methods_breakout`(09-11 결정 · NW1 와 같은 3전략 «풀링»).
- 후보 = `screener_snapshots` 의 `scan_date = D` 행 **전부**(룰 통과 전부 저장 — `docs/prereg_2026-09-24_screener_fullpass_snapshot.md` · scan_date 09-23 부터). 라이브가 읽는 상위 20 판은 인쇄만(§9).
- **경기장 a = (전략 g, T)**. 같은 종목이 두 전략의 후보면 두 경기장에 각각 든다(겹침 개수 인쇄).

```sql
-- (K) 경기장 후보 · 그 (scan_date, 전략)의 가장 이른 저장 묶음 · 결과 열 없음
SELECT s.strategy, s.stock_code, s.rank_in_snapshot, s.params_hash, s.created_at
FROM screener_snapshots s
WHERE s.scan_date = :D
  AND s.scan_date <= :D_end          -- §2-7 상한
  AND s.strategy IN ('book_pullback_ma20','minervini_volume_dryup','daytrading_3methods_breakout')
  AND s.created_at = (SELECT min(s2.created_at) FROM screener_snapshots s2
                      WHERE s2.scan_date = s.scan_date AND s2.strategy = s.strategy);
```

- 후보 원장은 이것이다(`ledger8`·EOD «전부 샀다 치고» 와 같은 출처). `candidate_ledger/`(과거 617일 재현 원장)는 쓰지 않는다.
- 저장 경로 `db/repositories/candidate.py:147-152` 는 `ON CONFLICT (strategy, scan_date, params_hash, stock_code) DO UPDATE` 로 **`rank_in_snapshot`·`score` 를 덮어쓴다**(`created_at` 은 안 바뀜) → 같은 날 재실행이 있으면 상위 20 판의 순위가 첫 실행과 다를 수 있다. «가장 이른 묶음» 규칙은 첫 실행에 들어온 종목만 고르지만 덮어쓴 순위는 되돌리지 못한다 → 재실행 흔적(같은 (D, 전략)의 created_at 묶음 > 1 또는 params_hash ≥ 2) 개수를 인쇄한다(주 검정은 순위를 쓰지 않으므로 무관 · 상위 20 판만 영향).
- 종목코드는 문자열 그대로 조인한다(영숫자 코드 포함 · 6자가 아닌 코드 수 인쇄).

### 2-3. 테마 소속 (PIT)

```sql
-- (M1) T 에 쓸 회차: T 09:00 KST 전에 끝난 'ok' 회차 중 snap_date 가 가장 최근
SELECT run_id, snap_date FROM theme_snapshot_run
WHERE status = 'ok'
  AND finished_at < ((:T)::date + time '09:00') AT TIME ZONE 'Asia/Seoul'
ORDER BY snap_date DESC, finished_at DESC
LIMIT 1;
-- (M2) 그 snap_date 의 소속·이름 — T 09:00 KST 전에 받은 행만(같은 날 늦은 채움 회차 제외)
SELECT m.theme_no, m.stock_code, d.theme_name
FROM theme_member_daily m
JOIN theme_daily d ON d.snap_date = m.snap_date AND d.theme_no = m.theme_no
WHERE m.snap_date = :S
  AND m.fetched_at < ((:T)::date + time '09:00') AT TIME ZONE 'Asia/Seoul'
  AND d.fetched_at < ((:T)::date + time '09:00') AT TIME ZONE 'Asia/Seoul';
```

- `snap_date < T − 3일(달력)` 이면 그날은 **무효 일**(§5 G1). `snap_date < T` 이면 «묵은 소속표» 플래그(개수 인쇄).
- **적격 테마 E(T)** = 이름이 정규식 `밸류업|지주사|SPAC|스팩|신규상장|여름|겨울|코로나` 에 걸리지 않고 소속 ≥ 2 인 테마 — 패턴은 `theme_rank/membership.py:15` `EXCLUDED_NAME_PATTERNS` 와 **같은 7개**(이름만 보고 정한 사건·분류형 · 지주사형 거대 테마 포함). **크기 상한·N_cut 은 두지 않는다** — 앞으로 측정은 소속표가 PIT 라 «나중에 생긴 테마» 미래 참조가 없고, 큰 업종형 테마는 §2-5 기준선 정규화가 스스로 낮춘다. (N_cut 547 판은 인쇄만.)
- 편입 사유(`reason`)·테마 설명·`theme_daily` 등락률 열은 **쓰지 않는다(인쇄도 안 함)**.
- 후보 c 의 **동료** = 같은 테마의 c 아닌 종목. **m_c** = c 가 속한 적격 테마 중 동료 ≥ 1 인 테마 수.

### 2-4. 기사 집합 · 창 · 건강

- **소스 = 언론 3개 고정**: `naver_finance` · `hankyung` · `mk_news`(q05 실측 «종목 연결 있는 비-DART 소스» 전부). 표본 중 새 소스가 붙어도 넣지 않는다(개수만 인쇄). **DART 는 주 신호에서 뺀다** — 공시는 회사 사건(NW1·NW2 소관)이고 정기·지분 보고(R 계열) 비중과 분기 계절성이 커서 «테마 서사» 신호를 흐린다. DART 사건형(D·E 계열, `_defs/dart_cls.sql`)을 더한 판은 인쇄만.
- **창 W(T)** = `published_at ≥ D 15:30` **∧** `created_at < T 09:00`. 시작은 발행 시각(D 장 마감 뒤에 나온 기사 — 단 그중 상당수는 D 장중 움직임의 **사후 보도**일 수 있어 «D 종가에 없는 새 정보» 와 같지 않다 · 그 몫은 §7-2 부분 IC 인쇄가 가른다), 끝은 **DB 에 실제로 있던 시각**(PIT). 현 KSIC 섹터 뉴스 점수 창(D 15:30 ~ T 09:00, q04)과 같은 자리라 «같은 층의 테마판» 이다. mk_news 의 `published_at` 은 수집 시각으로 대체돼 있어(§11) 그 소스만 시작 경계가 «수집 시각» 기준이다.
- **연결 종목 수 k**(그 기사의 `news_stock` 행 수)가 **1 ≤ k ≤ 10** 인 기사만 센다 — k > 10 은 시황 묶음 기사(REGISTRY 「기사 하나가 41종목에 걸리면 종목 촉매가 아니라 시황 기사」). 같은 기사는 테마마다 1번(`news.id` 고유).

```sql
-- (A) 창 안 언론 기사 · 종목 연결 — 제목·본문·점수 열 선택 0 · k 는 러너가 news_id 별 행 수로 센다
SELECT n.id, n.source, ns.stock_code
FROM news n JOIN news_stock ns ON ns.news_id = n.id
WHERE n.source IN ('naver_finance','hankyung','mk_news')
  AND n.published_at >= ((:D)::date + time '15:30')
```

- **건강한 창** = (A) 에서 1 ≤ k ≤ 10 인 서로 다른 기사 ≥ **100**(q06 실측 248~461 의 절반 아래 · 수집 장애 판별용). 건강하지 않은 T 는 무효 일, 건강하지 않은 과거 창은 기준선에서 뺀다.

### 2-5. 신호 S_news

각 T 에서(소속·적격·동료는 §2-3 의 T 소속표 하나로 고정):

1. **오늘 동료 기사 수** `N_{θ,−c}(T)` = 창 W(T) 에서 §2-4 규칙(언론 3소스 · 1 ≤ k ≤ 10)을 통과한 기사 중 테마 θ 의 동료(≠ c) 1개 이상에 연결된 기사 수. **c 와 동료에 함께 연결된 «공동 언급» 기사도 센다**(동료에 연결돼 있으므로) — 그만큼 후보 자기 뉴스(NW1 축)와 겹친다. 공동 언급 비율과 «c 에 연결된 기사를 뺀 엄격판» 은 인쇄(§9).
2. **기준선** `B_{θ,−c}(T)` = T 직전 **20 KOSPI 거래일** t_1..t_20((CAL) 에서 고름) 각각의 창 W(t_j) 에 같은 규칙(같은 동료 집합 · 같은 소스·k 규칙)을 적용한 기사 수의 평균 — **건강한 과거 창만**, 건강한 과거 창 < 15 이면 T 는 무효 일. (20 = 약 한 달 · 언론 종목 연결 실질 시작 2026-08 · naver_finance 온보딩 드리프트(NW1 §1-2) 구간을 기준선에 덜 넣는 길이.)
3. **열기** `H_{θ,−c} = (N + 1) / (B + 1)` · 단 `N_{θ,−c} < 2` 이면 그 테마는 «열기 없음»(p = 1 · `theme_rank` 의 k ≥ 2 와 같은 최소 사건 수).
4. **그날의 기준 분포**: 적격 테마 전부에 대해 동료 제외 없이(소속 전체) 같은 식으로 `N_{θ'}(T)`·`H_{θ'}(T)` 를 만든다(`N_{θ'} < 2` 이면 H = 0). 그날 «열기 있음» 테마 수 `K_T = #{θ' ∈ E(T) : N_{θ'}(T) ≥ 2}`(§4-1 교정이 읽는 유일한 신호 쪽 숫자).
5. **테마 p**: `p_{θ,−c} = (1 + #{θ' ∈ E(T), θ' ≠ θ : H_{θ'} ≥ H_{θ,−c}}) / |E(T)|` — «그날 이 테마보다 뜨겁거나 같은 테마의 비율». 날 안 순위라 **주말·연휴 창 길이 · 수집량 드리프트 · 과산포에 둔감**하다(포아송 꼬리를 쓰지 않는 이유).
6. **후보 S**: `S_news(c,T) = −log10( min(1, m_c × min_θ p_{θ,−c}) )` — 테마 수 보정(테마 많은 종목이 유리하지 않게 · `theme_rank` §4-1 과 같은 꼴). `m_c = 0` 이면 `S_news = 0`(«테마 없음/단독»). 주 테마 = argmin p(인쇄용).

### 2-6. 결과 Y (주 결과 · h = 1)

- `Y(c,T) = close_T / open_T − 1`(원시 `daily_prices` · 🔴 `adj_factor` 를 가격에 곱하지 않는다) — «T 시가에 샀다 치고 T 종가 평가» · 전부 샀다 치고 · 일봉 근사. `ret_net = Y − 0.25%p`(경기장 안 순위에는 영향 없음 · 돈 인쇄용).
- **유효 봉** = T 행 존재 ∧ `volume > 0`(봉인 단계에서 Y 없이 판정 · SQL (G5)) · 개봉 단계에서 `open`·`close` 가 결측이거나 0 이하면 추가로 뺀다(개수 인쇄 · 기대 0). 유효 봉이 없는 후보는 그 경기장에서 뺀다(§5 G5 비대칭 인쇄).
- **h = 1 을 주 결과로 고른 이유**(🔒 사장님 Q4 확정): ① 창이 T 09:00 에 끝나고 재료 수명 1~3일(테마 층 스펙 §10 실전 고수) ② 3전략 보유 중앙 2일 · 하루 안 청산 42~46%(메모리 09-14 실측 인용) ③ **날짜 사이 결과 창이 겹치지 않아** 60일 표본에서 날짜 상관이 가장 작다(SR1 critic 「블록 수」 교훈). **NewsQuant 10-07 의 «탐색 h0(익일 장중) 음(−)» 이 같은 결과 창의 가격판 관측임을 알고 골랐다**(§10-(A)-2). h = 2·5 와 daytrading 밴드 재현 진입은 인쇄만(§9).
- 시가→종가는 같은 날 값이라 분할·병합 권리락이 끼지 않는다(h = 1 에는 기업행위 제외 규칙이 필요 없다 · 인쇄용 h ≥ 2 에만 §11 X3).

### 2-7. 분석 시각 고정 (D_asof)

- **T_start = 2026-10-19(월)** · **T_end = T_start 를 1번째로 센 60번째 KOSPI 거래일**(예상 ≈ 2027-01-13 · 12-25·12-31·01-01 휴장 가정) · **D_end** = T_end 의 직전 거래일 · **D_asof_print = T_end 뒤 4번째 KOSPI 거래일**(h = 5 인쇄용 · 예상 ≈ 2027-01-19).

```sql
-- (CAL) 달력 — 상한 고정

WHERE stock_code = 'KOSPI' AND date >= '2026-08-01' AND date <= :D_asof_print

-- (Y) 결과 — 개봉 단계에서만 (인쇄용 h = 2·5 는 date ∈ [T, T+4] 로 같은 상한)
```

## 4. 검정

### 4-1. 통계

1. 경기장 a 마다 `IC_a = Spearman(S_news, Y)`(평균 순위 · `theme_rank/stats.py::spearman`). **유효 경기장** = 유효 봉 후보 ≥ 5 ∧ S_news 서로 다른 값 ≥ 2(봉인 단계 · Y 없음) — 개봉 단계에서 Y 서로 다른 값 < 2 인 경기장은 추가로 뺀다(개수 인쇄 · 기대 0 · `theme_rank` §4 와 같은 제외 규칙). 개봉 단계에서 이 때문에 **유효 경기장이 0 이 된 날**의 수도 인쇄한다(그날은 평균에서 빠짐 · critic 사소 18).
2. 날짜 IC `IC_T = Σ_a n_a·IC_a / Σ_a n_a`(그날 유효 경기장 · n_a = 유효 봉 후보 수).
3. **TN1 통계량 = 유효 일의 `IC_T` 평균** · Newey-West HAC t(`theme_rank/stats.py::hac_t` — NewsQuant `metrics.hac_t` 와 같은 식) · lag 사다리 **(2, 4, 6)** (= h+1 의 1·2·3배 · `theme_rank` 의 11·22·33 과 같은 규칙).
4. **도구 교정(개봉 단계 · 진짜 IC 보다 «먼저» 실행하고 파일·로그 순서로 증명 · SR1 선례 · critic F1 반영)**: 가짜 신호 400개.
   - j = 1..400 마다 `default_rng([20261019, j])` 로 적격 테마(표본 기간 합집합)별 AR(1) 표준정규 잡음 z(φ = 0.9 · `theme_rank/stats.py::ar1_noise`)를 유효 일 축에 만든다.
   - 날마다: 그날 E(T) 에서 z 상위 **K_T** 개(§2-5-4 · 날마다 숫자 1개)를 «가짜 열기 있음» 으로 두고, 그 테마의 `p̃_θ = (1 + #{θ' 가짜 열기 있음, θ' ≠ θ : z_θ' ≥ z_θ}) / |E(T)|`, 나머지 테마 `p̃ = 1`. 후보 `S̃ = −log10(min(1, m_c × min_θ p̃_θ))`(동료 ≥ 1 인 적격 테마 전부 · m_c = 0 이면 0) — 실제 S 와 같은 구조(날 안 순위 · 테마 수 보정 · 그날 열기 테마 «개수») · `theme_rank/stats.py::fake_s` 와 같은 원칙(«동료 ≥ 1 테마 전부에 잡음»).
   - 🔴 **가짜 신호는 실제 N·B·H·p·S_news 의 테마별·후보별 값을 읽지 않는다.** 읽는 실제 값은 소속표(적격·동료·m_c)와 날마다 K_T 하나뿐이다(어느 테마가 뜨거웠는지는 잡음이 정한다). v1 의 «실제 N_{θ,−c} ≥ 2 마스크 그대로» 는 실제 신호 성분이 새어 «기사 있음–Y» 관계가 가짜 400개에 실리는 결함이라 **삭제했다**(critic F1 · 테마 층 스펙 §5-3 «결과 수익과 실제 신호를 함께 보지 않음» · `calibrate.py:3`).
   - **러너 테스트(필수)**: ① 가짜 신호 함수의 인자에 N·B·H·p·S_news 가 없다 ② 같은 K_T 를 유지한 채 실제 테마별 N 을 테마 사이에서 섞어도 가짜 S 가 바이트 동일 ③ **봉인 산출물(유효 일 · 유효 봉 후보 목록)을 입력으로 고정한 채** 실제 S_news 를 임의 값으로 바꿔도 `calib.json` 이 바이트 동일.
   - 교정의 날짜 축·후보는 봉인 산출물로 고정하고, 경기장 조건 중 «S 서로 다른 값 ≥ 2» 는 **가짜 S̃ 로 다시 적용**한다(`theme_rank/stats.py::daily_ic` 와 같음 · 실제 S_news 의 서로 다른 값 수를 쓰지 않는다). 봉인 인쇄에 «가짜 S̃ > 0 비율(400개 평균) vs 실제 S > 0 비율» 을 둔다(수익 열람 0 · 희소 구조가 맞는지 확인용).
   - 가짜 S̃ 와 **실제 Y** 로 1~3 을 돌려 p<0.10(|t| ≥ 1.645) 거부율이 **[0.07, 0.13]** 인 첫 lag 를 쓴다(mode = hac · p = 정규근사 양측 · 95% CI = 평균 ± 1.96·SE_HAC(그 lag)). 셋 다 불합격이면 mode = empirical: p = (1 + #{|t_fake| ≥ |t|})/401(lag 2 의 가짜 t) · 95% CI = 평균 ± q·SE_HAC(**lag 2**) (q = lag 2 가짜 |t| 의 95 백분위) — `theme_rank/calibrate.py::choose·calibrated_p` 와 같은 꼴.
5. 날짜×테마 이중 군집·K2 는 쓰지 않는다(그룹 신호에 미교정 — `theme_rank` §8).

### 4-2. 실질 임계 θ_IC = 0.05

- 근거: 정규 근사에서 «S 상위 1/3 − 하위 1/3» 수익 차 ≈ 2.18·ρ·σ_Y. σ_Y(소형주 하루 시가→종가 표준편차)를 **가정 3 · 4.5 · 6%** 로 두면 ρ = 0.05 ↔ 0.33 · **0.49** · 0.65%p — REGISTRY 공통 ε = 0.5%p 에 맞춘 값(σ_Y 4.5% 가정). σ_Y 는 결과 값이라 **재지 않았다**(가정). S_news 는 0 동률이 많아 3분위가 정의되지 않으므로 이 환산은 근사다.
- **ε 에 대응하는 지표는 «상·하위 1/3 차(≈ 2.18ρσ)» 이고 판정은 θ_IC 로만 한다.** §9 돈 인쇄(상위 1/5 − 경기장 평균)는 다른 지표라 같은 ρ = 0.05 · σ 4.5% 에서 ≈ 1.40ρσ ≈ **0.31%p** 다 — 돈 인쇄 숫자를 ε 0.5%p 와 맞대지 않는다(critic 사소 11).

### 4-3. MDE (가정 격자 · 결과 분산 열람 없음)

`SE_day ≈ 1/√(그날 유효 후보 수)`(순열 귀무에서 상관의 분산 = 1/(n−1) · 동률과 무관) · `MDE = 2.80 × SE_day × √(DEFF / 유효 일 수)` (K = z0.975 + z0.80 = 2.80 · m = 1).

| 하루 후보 n | 유효 일 | DEFF 1 | DEFF 2 | DEFF 4 |
|---:|---:|---:|---:|---:|
| 50 | 40 | 0.063 | 0.089 | 0.125 |
| 50 | 60 | 0.051 | 0.072 | 0.102 |
| 75 | 40 | 0.051 | 0.072 | 0.102 |
| 75 | 60 | **0.042** | **0.059** | 0.083 |
| 100 | 40 | 0.044 | 0.063 | 0.089 |
| 100 | 60 | 0.036 | 0.051 | 0.072 |

- **DEFF 의 주원인은 «하루 안 같은 테마 후보들의 S·Y 동조»** 다 — 같은 테마 후보는 같은 S 를 받고 같은 날 같이 움직인다(테마 층 PREREG 서술값: 돌출도 상위 3 안 같은 주 테마 2종목 이상인 날 466/617). 그날 IC 가 사실상 «몇 개 테마»의 성적이 되어 1/√n 보다 커진다. 날짜 간 진짜 IC 변동·테마 지속도 더한다(HAC·교정이 실제 값을 반영). 봉인 단계에서 **경기장별 «S > 0 후보의 서로 다른 주 테마 수»** 분포를 인쇄한다(Y 0 · critic 사소 19).
- «실질 효과 없음» 라벨(§6)은 95% CI 가 (−0.05, +0.05) 안에 들어야 하므로 점추정 0 근처에서 `SE < 0.0255` 가 필요하다 — n ≈ 75 · 60일이면 **DEFF ≲ 2.9** 에서 도달 가능.
- 사전 예상: 테마 층 퀀트 추정 «그럴듯한 효과 IC 0~0.02» 는 이 MDE 아래다 ⇒ **「판정 불가」 또는 「실질 효과 없음」 이 사전 최빈**이다. 🔴 **「판정 불가」 는 «효과가 없다는 근거» 가 아니다** — 종결 근거로 쓰지 않는다(§7-3·§12 · critic F2). 이 측정의 쓸모는 «IC 0.05 급 쓸모 있는 효과가 있는지 / 없다고 말할 수 있는지» 다.
- 봉인 단계(§14)에서 실제 유효 일·후보 수로 이 표의 해당 칸을 다시 인쇄한다(Y 0).

### 4-4. 다중비교

주 검정 m = 1(Holm 불필요). §9 인쇄 항목은 **점추정과 n 만** 인쇄하고 p·CI·판정 언어를 쓰지 않는다(REGISTRY 규칙 2·4 · NW1 Q7 선례 — 인쇄에 귀무를 붙이지 않는다).

## 6. 판정 문형 (대칭 · 게이트 탈락 우선)

**순서**: ① G1 ② G2 ③ G4 — 하나라도 탈락이면 다른 조건과 무관하게 **판정 불가**. ④ G3 mode 로 p·CI 산출 — 통계량·SE·t 중 하나라도 유한하지 않거나(NaN·분산 ≤ 0 · 유효 일 < lag + 2) CI 를 못 만들면 **판정 불가(도구)**(`theme_rank/PREREG.md` §5 선례 · critic 사소 2) ⑤ 아래 표.

| 라벨 | 문장(조건을 문장에 포함) | 조건(모두) |
|---|---|---|
| **양(+)** | 「10-19~(60거래일) **3전략 풀링(가중 = 봉인 단계 실측 · 유효 경기장 후보 수 합 기준 · 결과 전 추정 daytrading ≈47·ma20 ≈40·minervini ≈13%)** 후보 안에서 T 09:00 전 테마 동료 기사 열기가 높을수록 **h=1(T 시가→종가)** 성과가 높았다(IC ≥ +0.05)」 | p < 0.05 ∧ 평균 IC ≥ **+θ_IC** |
| **음(−)** | 「…(같은 범위 문구)… 높을수록 h=1 성과가 낮았다(IC ≤ −0.05)」 | p < 0.05 ∧ 평균 IC ≤ **−θ_IC** |
| **실질 효과 없음** | 「…(같은 범위 문구)… 양·음 어느 쪽으로도 IC 0.05 이상의 차이는 없었다」 | 95% CI ⊂ **(−θ_IC, +θ_IC)** |
| **판정 불가** | 사유를 함께 적는다 | 게이트·도구 탈락(우선) · 그 밖 전부(유의하나 \|IC\| < θ — 「유의·실질 미만」 · CI 가 ±θ 를 걸침 등) |

- **겹침 우선순위(critic 사소 1)**: CI ⊂ (−θ, +θ) 이면서 p < 0.05 인 경우(CI 가 0 을 빼고 ±θ 안 — `SE < 0.0128` 이 필요해 사실상 도달 불가)는 **「실질 효과 없음」** 으로 두고 문장 뒤에 «작은 유의 효과(부호 ±) 병기» 를 붙인다. 「유의·실질 미만(판정 불가)」 은 CI 가 ±θ 밖으로 나가는 경우만이다.
- 방향 가설(+) 기준 읽기: 지지 = 양(+) · 기각 = 음(−) 또는 실질 효과 없음 · 판정 불가 = 미결. **양·음 조건은 거울상**이다(SR1 critic 「판정 비대칭」 반영). **어떤 라벨도 범위(§1) 밖 — ① 스윙 지속력 · ④ 대장주 · h ≥ 2 — 에 대한 판정이 아니다.**
- G5·G6 병기는 라벨을 바꾸지 않고 문장 뒤에 붙는다.
- **판정문에는 가족 FWER 을 반드시 병기**한다(REGISTRY 규칙 5 · `REGISTRY.md:38`): «가족 FWER(보정 없음) — 개봉 시점 등재 m = … · 1 − 0.95^m = … · 실행된 N1 기준은 그보다 크다»(§13 표 · critic 사소 4).
- 전략별·h 별 라벨은 만들지 않는다(주 검정 아님).
