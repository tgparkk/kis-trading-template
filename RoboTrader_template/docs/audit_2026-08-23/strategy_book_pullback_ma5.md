## §2. 이탈 상세 (증거)

### 2-1. 🔴 「20일 내 +20% 급등」은 책에 없다 — 인용이 아니라 발명

원저작 7편 판독 노트(`reports/books_research/trading_legends/raw_notes/notes_*.md`)를 「5일선·눌림·20%」로 전수 검색한 결과, 이 기법의 **정량 조건(+20%·20일)은 한 줄도 없다**(「20%」의 유일 히트는 `notes_081-100.md:14` 의 손실률). 정성 서술은 아래 셋 외에도 있다 — 특히 캐리의 *"전날 상한가를 친 종목 … 눌림목이 나왔다가 재차 상승할 때 진입"*(`notes_101-120.md:21`, 또 `:60`·`notes_041-060.md:27`·`notes_001-020.md:69`)은 「급등→눌림→재상승」의 정량 앵커이지만, 그것은 `report.md:52` 가 **`prev_limitup_pullback` 이라는 별도 룰로 이미 코드화**한 것이라 `+20%/20일` 의 출처가 되지 못한다. 대표 인용 셋:

- 방배동선수(PART4): *"매수는 눌림목, 매도는 쏠릴 때. 시장의 리듬을 읽고, 주가가 잠시 숨을 고르는 눌림목에서 진입하라"* (`notes_061-080.md:68`)
- 불개미(PART1): *"기술적으로 **5일/10일선까지 하락하지 않고 5일선 위에서 반등하며 다시 상승하는 패턴**이 나타남"* (`notes_041-060.md:19`)
- 신정재(PART2): *"조정 기간은 길면 20~30분, 짧으면 10~15분"* → **분봉 이야기**이고, 진입점은 *"이평선 정배열 초입, 즉 상승 파동이 시작되는 초기 부분"* (`notes_021-040.md:89-90`)

연구 산출물인 `report.md` 의 A4 항목조차 「+20%」를 쓰지 않는다 — *"상승 추세 종목이 5일선/10일선까지 안 빠지고 5일선 위에서 반등하거나, 상승 후 조정 눌림에서 양봉"*(`report.md:55-57`).

🔑 ***즉 「최근20일 내 +20% 급등 이력」은 「상승 추세 종목」을 정량화하려다 «코더가 고른 임계값»이다.*** 정량화의 불가피한 대가일 수는 있으나, `README.md:13` 과 `config.yaml:3`(「백테스트 검증값 1:1 반영」)이 이를 **책에서 온 조건처럼 제시**한다. 그리고 §2-3 이 보여주듯, 그 발명된 조건은 구현되면서 「상승」이라는 뜻마저 잃었다.

### 2-2. ⚪ 원저작이 「일봉 눌림목 전략」이 아니라는 점은 연구 문서가 이미 인정한다

`report.md:12` — *"9인 중 8인이 분봉/호가창 스캘퍼"*. `report.md:133-140` 최종 판정은 **CANDIDATE 부적격**이며, ma5_pullback 에 대해 *"유일한 강한 수치는 **신규 알파가 아님** … Book 14 강창권 `ma5_10`·`ma20_pullback` 의 재확인일 뿐"*(`report.md:136`)이라고 명시한다. `README.md:30` 은 이 중 「Sharpe 0.63」과 「BULL 청산 의존」만 옮겼고 **「CANDIDATE 부적격」이라는 판정 자체는 옮기지 않았다**.

### 2-3. 🔴 재검증 ① — `_recent_surge` 는 «급등»이 아니라 «방향 없는 변동폭»을 잰다 (**확인됨**)

```python
# strategies/books/trading_legends/rules_daily.py:49-58
def _recent_surge(df, lookback, surge_pct) -> bool:
    """직전 lookback 봉(마지막 봉 제외) 내 저점 대비 고점이 +surge_pct 이상 → 급등 이력."""
    seg = df.iloc[-(lookback + 1):-1]
    seg_low  = float(seg["low"].min())
    seg_high = float(seg["high"].max())
    return (seg_high - seg_low) / seg_low >= surge_pct
```

`min()`·`max()` 만 쓰고 **두 값의 시간 순서를 보지 않는다.** 창 안에서 고점이 저점보다 «먼저» 와도(=급락) 조건은 참이다. docstring 은 "급등 이력"이라고 쓰여 있어 **주석과 계산이 다른 말을 한다**.

**실측(§3-B)**: 매수 110건 중 **56건(50.9%)이 고점 먼저 = 하락이 만든 폭**. 창 순수익 중앙값 **−1.7%**, 58건(52.7%)이 상승조차 아니었다(최저 **−54.4%**).

⇒ ***이 조건은 「급등 후 눌림」의 «급등»을 재는 데 실패한다. 절반은 「폭락한 종목」이다.*** 이 축이 두 전략(`ma5`·`ma20`)의 **첫 조건**이므로 「누가 후보가 되나」 전체가 영향을 받는다.

### 2-4. 🔴 재검증 ② — `touched`(저가)와 `above`(종가)를 같은 봉에서 따로 재면 진폭 큰 봉이 자동 통과 (**확인됨**)

```python
# strategies/books/trading_legends/rules_daily.py:286-291
surged  = _recent_surge(df, self.surge_lookback, self.surge_pct)
touched = _touch_ma(last_low, ma5, self.touch_tol)      # ← 저가가 MA5 ±2%
above   = last_close >= ma5 * (1.0 - self.below_tol)    # ← 종가가 MA5×0.98 이상
bullish = _is_bullish(last)                             # ← 종가 > 시가
if surged and touched and above and bullish:
```

`touched` 는 **저가**로, `above` 는 **종가**로 판정한다. 봉 하나의 range 가 크면 「저가가 MA5 를 스쳤다」와 「종가가 MA5 위다」가 **자동으로 동시에 참**이 된다. 개념상 「MA5 에서 지지받고 반등한 작은 눌림봉」과 「MA5 를 훌쩍 뛰어넘은 상한가급 장대양봉」이 **구분되지 않는다**.

**실측 사례 — 메모리 단서의 정정판.** 메모리는 「8/18 `003010` 종가 +28.3%」로 기록돼 있으나, 재현되는 것은 **`003010` 2026-08-14 봉**이다:

| 항목 | 값 | 룰 판정 |
|---|---|---|
| 시가 / 고가 / 저가 / 종가 | 7,550 / 9,690 / 7,550 / 9,690 | — |
| 당일 등락률 | **+29.89%** (상한가급) | — |
| MA5(5봉 종가평균) | 7,442.0 | — |
| `touched` = \|7,550 − 7,442\| / 7,442 | **1.45%** ≤ 2% | ✅ |
| `above` = 9,690 ≥ 7,442 × 0.98 (= 7,293) | 132.9% | ✅ |
| `bullish` = 9,690 > 7,550 | — | ✅ |
| `surged` (직전 20봉 저점→고점) | ≥ 20% | ✅ |

**4조건 전부 성립** → `screener_snapshots` 실측: `book_pullback_ma5` 가 `003010` 을 **2026-08-14 스캔에서 rank 2 후보로 선정**했다. 「저가가 5일선을 스치고 그날 **+29.89%** 마감한 봉」이 **「5일선 지지 눌림 반등」으로 읽힌 것이다.**
(8/18 봉은 +14.34%이고 저가 9,400 vs MA5 8,472 = **10.95% 이탈**이라 `touched` 불성립 — 메모리의 날짜·수치는 정정이 필요하나 **현상 자체는 실재하고 더 강한 형태로 재현된다**.)

**구성비 실측(§3-C·E)**: 진입봉 당일 등락률 **≥ +10% 가 20/110(18.2%)**, ≥ +5% 가 46/110(41.8%), 최댓값 **+25.91%**. 진입봉 일중 진폭 중앙값 **11.65%**, **67/110(60.9%)이 10% 이상**.

⇒ ***「눌림」을 사겠다는 전략이 실제로는 「크게 움직인 봉」을 사고 있고, 그 비율이 5건 중 1건이다.***

### 2-5. 🔴 재검증 ③ — 손절 −3% 는 이 기법의 수치가 아니다 (**확인됨**)

책에서 **−3%** 가 나오는 유일한 자리는 PART9 **뭐라도되겠지 = 상따(상한가 따라잡기)** 트레이더다:

> *"독특한 방식 — **평균 3.3배 레버리지**를 활용한 미수 매매를 하면서도, **-3% 손절 원칙**을 철저히 지키고…"* (`notes_121-140.md:46`)
> *"보통 **27~28% 구간**에서 매수하며, 매수 후 **10초 안에 상한가에 도달하지 않으면** …(=손절)"* (`notes_121-140.md:57`)

즉 −3% 는 ①상한가 직전 27~28%에 진입해 ②**10초** 단위로 판정하는 ③**3.3배 미수** 기법의 손절폭이다. 눌림목 트레이더(방배동선수)는 손절 **수치를 말하지 않는다** — *"자신의 시나리오와 현실의 괴리가 명확해졌을 때"*(`notes_061-080.md:59`)라는 정성 기준뿐이다.

**코드 자신이 이 귀속을 알고 있다**: `rules_daily.py:126` 주석 *"2. 상한가 따라잡기 (뭐라도되겠지) — 짧은 보유·**타이트 손절(-3%)**"*, `rules_daily.py:137` *"run 스크립트 RULE_SL_OVERRIDE 로 -3% 타이트 손절"*. 그리고 백테스트 러너의 override 대상은 **`limit_up_follow` 하나뿐**이다:

```python
# scripts/run_trading_legends_daily.py:57-60
# 상따(limit_up_follow) 책 명시 -3% 타이트 손절 — variant 무관 강제 override
RULE_SL_OVERRIDE = { "limit_up_follow": 0.03 }
```

그럼에도 `config.yaml:32` 는 `stop_loss_pct: 0.03  # 손절 -3% (타이트 — 상따/단기 트레이더 손절)` 라고 **「상따」라는 출처를 적어둔 채** ma5 에 적용한다.

⚠️ 부수 효과: `core/trading_decision_engine.py:655-658` 의 `STOP_LOSS_FLOOR = 0.03` 과 정확히 동치라, **8전략 중 이 전략만 손절 하한선 위에 얹혀 있다** — 더 좁힐 여지가 원리적으로 없고 하한 적용 로그도 안 찍힌다.

### 2-6. 🔴 라이브 청산 파라미터는 백테스트 **어느 variant 와도** 일치하지 않는다

`README.md:30` 이 인용하는 **Sharpe 0.63 / +33.66%** 는 `report.md:120` 의 **variant B** 행이다. variant 정의:

```python
# scripts/run_trading_legends_daily.py:48-55
"A": dict(stop_loss_pct=0.08, take_profit_pct=0.99, max_hold_bars=100, use_trail=True),
"B": dict(stop_loss_pct=0.08, take_profit_pct=0.12, max_hold_bars=20,  use_trail=False),
"O": dict(stop_loss_pct=0.05, take_profit_pct=0.99, max_hold_bars=1,   use_trail=False),
```

| 파라미터 | variant **B** (Sharpe 0.63 출처) | variant A | **라이브** (`config.yaml:31-34`) | 일치? |
|---|---|---|---|---|
| stop_loss | 8% | 8% | **3%** | ❌ 어느 쪽도 아님(상따 수치) |
| take_profit | 12% | off(99%) | **15%** | ❌ 어느 쪽도 아님 |
| max_hold | 20봉 | 100봉 | **30거래일** | ❌ 어느 쪽도 아님 |
| trail_ma | **없음** | 5 (`run_trading_legends_daily.py:68`) | **5** | ❌ B 아님 / A 것 |

⇒ ***라이브는 「A의 트레일 + 다른 룰의 손절 + 어디에도 없는 tp/mh」를 합친 혼종이고, 그 조합은 한 번도 백테스트된 적이 없다.***
그런데 `config.yaml:3` 은 *"『트레이딩의 전설』(Book15) ma5_pullback 실전판 — **백테스트 검증값 1:1 반영**"* 이라고 선언한다. **이 문장은 진입 룰에는 참이고**(`strategy.py:194-195` 가 `rule_ma5_pullback` 을 그대로 호출) **청산에는 거짓이다.**

참고로 trail 을 켠 유일한 variant 인 **A 의 성적은 +0.25% / Sharpe 0.12**(`report.md:119`)로, 인용된 0.63 과 5배 차이다.

### 2-7. 🟢 재검증 ④ — 매수·매도 룰 동시 참: **구조적으로 가능하나 실측 0.9%** (rs_leader 와 다르다)

- 매수 조건 3 (`rules_daily.py:288`): `close >= ma5 × 0.98`
- 매도 trail 조건 (`strategy.py:243`): `ret > 0 AND close < ma5`

두 부등식의 교집합은 **`0.98·MA5 ≤ close < MA5`** 라는 **2% 폭의 실재하는 구간**이다. 즉 `below_tol = 0.02` 가 「MA5 아래 2%까지 지지로 인정」하는 만큼, 그 구간은 동시에 「MA5 이탈 = 청산」 구간이다. **구조적 중첩은 실재한다.**

다만 `rs_leader` 와 두 가지가 다르다:

1. 매도 쪽에 `ret > 0`(진입가 대비 수익 중)이라는 **포지션 의존 조건**이 붙어 있어 **봉 하나만으로 동시 참이 확정되지 않는다**.
2. `strategy.py:137-138` 이 보유 종목을 매도 분기로 먼저 보내므로 **같은 종목을 사면서 팔지는 않는다**.

**실측(§3-F)**: 매수 110건의 신호봉 중 이 중첩 구간에 있던 것은 **1건(0.9%)** 뿐이고 **109건(99.1%)은 종가가 MA5 이상**이었다.

⇒ ***판정: 「무조건 겹치는 `rs_leader` 계열」이 아니다.*** 겹칠 수 있는 구조이나 실측 발현이 희소하다. **`below_tol` 을 키우는 변경이 오면 즉시 커지는 종류**라 등록만 해둔다.

### 2-8. 🟡 청산 실행 경로 — README 가 나열한 4개 청산 중 실제로 도는 것은 다르다

`strategy.py:133-134` 는 `timeframe != "daily"` 면 **무조건 `None`** 을 반환한다(분봉 whipsaw 방지 — 의도된 것). 그런데 `core/trading/position_monitor.py:360` 은 전략 매도 신호를 **`timeframe='intraday'` 로만** 호출한다.

⇒ **`position_monitor` 경로에서 `evaluate_sell_conditions` 는 원리적으로 도달 불가**이고, 그보다 먼저 놓인 범용 손익절(`position_monitor.py:310` tp · `:325` sl — **실시간 현재가** 기준)이 항상 선행한다. 전략 고유 청산은 `strategies/base.py:694-701` 의 `on_tick` **일봉** 매도 루프에서만 발화한다.

실측 개입률 **9.4%**(§3-D)는 `docs/2026-07_전략고유청산_공백_재해석.md:30` 의 관측(`0/46` → owner 키잉 수정 후 `3/20`)과 정합한다.

⚠️ 추가 관측: 매도 106건 중 **5건이 「트레일링 스톱 매도: 현재가 … 최고가 대비 …」**다. 이 경로는 `position_monitor.py:292` 의 `if strategy_for_sell is None:` **안에만** 있다 ⇒ 그 5건은 **소유 전략이 해소되지 않은 포지션**이었다는 뜻이다(owner 키잉 결함 계열의 잔존 흔적). **원인 미규명.**

## §5. 한계

1. **표본이 작고 기간이 짧다** — 매수 110건 / 매도 106건, 2026-06-10~08-21 의 약 **2.5개월 · 51거래일(매매 활동일 47일)**. 어떤 비율도 «전략의 성질»이 아니라 «이 창의 성질»일 수 있다. §3 의 어떤 수치도 사전등록된 검정을 거치지 않았다 — **전부 기술통계(관측)이지 검정된 명제가 아니다.**
2. **「고치면 좋아진다」는 한 건도 재지 않았다.** D1·D2 는 「개념과 코드가 다르다」를 보인 것이지 「고치면 수익이 는다」를 보인 것이 아니다. 방향 필터·이봉 통합이 성적을 어느 쪽으로 옮기는지는 **미측정**이며, 기존 계열 관측(기준선이 무작위를 못 넘는 일이 네 번)에 비추면 **개선 방향조차 예단할 수 없다**.
3. **D1 과 D2 는 같은 함수·같은 룰 안에 있다.** 동시에 고치면 원인 분리가 불가능하다 ⇒ 「한 번에 한 축만」 원칙상 **사전등록을 각각** 해야 한다.
4. **`daily_prices` 는 살아 있는 표다.** 봇이 매일 09:00 에 과거 ~103봉을 덮어쓰고 EOD 에 전 행을 재도장하므로, §3 의 신호봉 재구성은 **오늘 시점의 표**를 읽은 것이다. 매수 당시 봇이 본 값과 다를 수 있다(특히 `adj_factor ≠ 1` 종목). 다만 **110/110 이 룰 4조건을 재현**했으므로 이 창에서는 실질 차이가 없었다고 본다.
5. **메모리 단서의 정정** — 「8/18 `003010` 종가 +28.3%」는 재현되지 않았다. 실제는 **2026-08-14 · +29.89%** 이고, 그것은 **스크리너 rank 2 후보**였고, 검증에서 더 강한 사실이 나왔다 — **라이브 전략이 8/18 09:03:57·09:09:07·09:14:13·09:19:21 에 반복해서 매수 시그널을 냈다**(`robotrader_template_20260818_074007.log`: `[PAPER] 매수 시그널: 003010 @ 9,690 … ma5_pullback ma5=7442.00 low=7550.00 close=9690.00`). 즉 룰 자신이 통과시켰고 하류에서 막혔다(익일 시가 10,140 = 기준가 9,690 대비 **+4.64%** 로 진입밴드 +1% 초과). 밴드 스킵 사유는 `core/trading_decision_engine.py:411-416` 이 문자열로 반환만 하고 유일 소비처 `bot/trading_analyzer.py:92` 가 `logger.debug` 라 **INFO 로그에는 원리적으로 안 남는다** — 「확인하지 않았다」가 아니라 「현 로그로는 확인 불가」다.
6. **밴드 밖 체결 8건**(상단 초과 3 · 하단 미만 5)의 **원인 미규명.**
7. **읽기 전용 검수다.** 코드를 실행하지 않았고(라이브 트리 금지), 룰 재현은 **SQL 로 산술을 복제**한 것이지 `rule_ma5_pullback` 을 호출한 것이 아니다.
8. **책 판독 노트가 원본이 아니다.** 캡처 판독본이며 `report.md:96-106` 이 tl_060·069·136 **본문 잘림**과 *"일부 손절수치 디테일"* 유실을 명시한다 ⇒ **「책에 −3% / +20% 가 없다」는 「판독된 140장에 없다」로 읽어야 한다.** 다만 방배동선수 구간(tl_064~072)은 표지·면책 포함 **전량 확보**돼 있어, 이 기법의 정량 룰 부재는 신뢰도가 높다.
9. **축① 「대장주 vs 중소형」 판단은 정성 대조다** — 책은 시총 기준을 말하지 않으므로 「반대 방향」은 해석이다. 다만 백테스트가 `top_volume` 대형주 유니버스(러너 기본값은 50 `run_trading_legends_daily.py:15` 이나 **실제 산출물은 `top_volume:100`·99종목**, `report.md:110`; `README.md:28` 의 「50」도 같은 오기)에서 돌았다는 사실은 **모집단 불일치의 객관적 근거**이며 `README.md:28-29` 가 이를 이미 자백하고 있다.
