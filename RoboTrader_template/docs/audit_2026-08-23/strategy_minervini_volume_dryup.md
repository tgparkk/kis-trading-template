## §2 이탈 상세 — 증거

### 2-1. 🔴🔴 A-1 「매수 방아쇠의 방향이 반대」 — **재검증 결과: 여전히 참**

> ※ **기존 단서의 재검증**이지 새 발견이 아니다. 출처: 메모리 작업목록 트랙 A-1, `backtest/concept_axes/minervini/CONCEPT_WIRING_AUDIT.md §3-2`.

**원저작**: `research.md:40` — 「돌파 트리거 | 종가 > 피벗 + RVOL ≥ 1.5x」. 즉 **거래량이 «터지는» 순간**에 산다.
**라이브**: `strategies/books/minervini_vcp/rules.py:321-335` —

```python
recent_avg = float(vol.iloc[-self.recent_window:].mean())
base_avg   = float(vol.iloc[-(self.recent_window + self.base_window):-self.recent_window].mean())
ratio = recent_avg / base_avg
if ratio <= self.ratio_max:            # 0.70
    return RuleResult(triggered=True, side="buy", ...)
```

거래량이 **줄어든 것 자체**가 매수 신호다. 셋업(dry-up)을 사고 방아쇠(돌파)를 기다리지 않는다. **현행 코드에서 참임을 확인.**

**추가로 확인한 구조적 이유** (`rules.py:325`): `vol.iloc[-self.recent_window:]` 는 **마지막 봉을 포함한다**. 라이브에서 마지막 봉은 `_drop_unconfirmed_today_bar`(`core/trading_context.py:143-175`) 때문에 **D-1 확정봉**이다. 따라서 dry-up 과 돌파를 «같은 봉»에서 동시에 요구하면 **dryup 이 그 돌파봉 거래량의 상한을 정하게 되어** RVOL ≥ 1.5 와 원리적으로 충돌한다. 원저작에서 dry-up 과 돌파는 **순차**인데 이 룰의 구조는 **동시**다.

🔑 대조: `rule_vcp_breakout`(`rules.py:103-104`)은 `base = df.iloc[-26:-1]`, 돌파봉 = `df.iloc[-1]` 로 **분리**돼 있어 순차 구조가 이미 코드에 존재한다. 다만 **라이브에 배선돼 있지 않다.**

## §5 한계 — 정직하게

1. **후보 집합 변화는 한 건도 재지 않았다.** F-1~F-3 를 고쳤을 때 매수 종목이 어떻게 바뀌는지는 **코드 독해와 20건 실측에서 «추론»한 것**이고 측정한 것이 아니다. 라이브 트리에서 실행이 금지돼 있으므로 이 검수에서는 원리적으로 잴 수 없었다.
2. **TT 판정은 c1~c7 만이다.** c8(RS 백분위)은 그날 유니버스 전체가 있어야 계산되므로 SQL 로 재현하지 않았다. 다만 이는 **통과율을 낮추는 방향으로만** 작동하므로 「19/19 FAIL」은 하한이 아니라 **확정**이다. `279570` 은 상장 이력이 108봉뿐이라 측정에서 제외했다(20건 중 1건).
3. **표본이 작고 단일 국면이다.** 매수 66건·매도 63건·거래일 57일. §3 의 비율(1.6% · 61.4% · 53.8% · 10.6%)은 **관측이지 검정된 명제가 아니다.**
4. **6월과 7·8월은 다른 체제다.** §2-9 의 tp/sl 표류와 §3-4 의 밴드 미발효가 **둘 다 6월에 몰려 있다** ⇒ 6월을 포함한 집계(§3-2 의 청산 63건 포함, 트레일링 6건 전부 6월)는 **두 체제의 혼합**이다.
5. **「왜」는 규명하지 않았다.** 트레일링 6건에 owner 가 안 붙은 이유, 8월 먼지 비율이 오른 이유(현금 소진? 미청산 누적?)는 **원인 미규명**이다. ⚠️ 메모리 규칙대로 ***안 재고 고치면 엉뚱한 데를 고친다.***
6. **성과 비교를 하지 않았다.** 이 문서는 「개념 ↔ 코드」 충실도 검수이지 「어느 쪽이 돈을 버는가」의 검정이 아니다. `D`/`DT`/`T` arm 판정은 `backtest/concept_axes/minervini/RESULTS.md` 가 정본이고 **Holm 보정 후 어느 것도 「유의」로 선언되지 않았다**(README `:15-19`).
7. **`daily_prices` 는 「살아 있는 표」다.** 봇이 매일 09:00 에 과거 구간을 원주가로 덮어쓴다는 기록이 있다 ⇒ **이 문서의 SQL 결과는 2026-08-23 시점에 읽은 값**이고 재실행하면 달라질 수 있다. dry-up 재현이 원장 `reason` 과 **20/20 일치**한 것은 그 위험이 **이 표본에서는 실현되지 않았다**는 증거다.
8. **`position_monitor` 는 읽기만 했다.** 청산 우선순위(§2-7 표)는 코드 순서에서 읽은 것이고 **실행 순서를 계측한 것이 아니다.** 다만 §3-2 의 사유 분포(62/63 이 프레임워크 문구)가 그 순서와 정합한다.
