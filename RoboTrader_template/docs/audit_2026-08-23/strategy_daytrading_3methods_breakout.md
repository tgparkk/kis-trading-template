**파생 ⓑ max_hold 오프바이원**: 전략은 `hold_days = count_trading_days_between(...) - 1`(`strategy.py:305`) 로 세고 `>= 10` 에 판다.

### 2-5. ⑤ K=5 가 지켜지지 않는다 — 결함(원인 미규명)

가드는 `strategy.py:134-135` 의 `len(self.positions) >= self._max_positions` 하나뿐이고,

### 2-6. ① 유니버스 — 2026-06-25 의 구멍은 «닫혀 있다»

②발동해도 수용 전략의 `base_filter` 를 태운다(`candidate_loader.py:174-181`, 어댑터 없으면 **빈 풀** = fail-closed `candidate_loader.py:258`)

### 2-7. 거래량 룰이 읽는 volume 은 조정값이다 — 경로 확인 완료, 단 상류에 미해소 결함

## §5 검수 한계 — 못 본 것

0. 🔎(검증 추가) **진입 밴드 거부는 로그로 관측 불가** — 전 로그에 「밴드」 0회인 이유는 `bot/trading_analyzer.py:92` 가 `buy_reason` 을 `logger.debug` 로만 남기기 때문. §3-C 의 「상한 발효 중」은 *초과 체결의 부재*라는 간접 증거뿐이고, §2-3 의 형제 문서 인용(밴드 거부→되돌림 체결 21건)은 로그로 재현 불가.

1. **개념 축소(D6)가 후보 집합을 얼마나 바꾸는지 «한 건도 재지 않았다».** 15→20봉, 「2회 실패」 추가, 「+22% 장대양봉」 추가가 각각 후보를 몇 % 줄이는지 **미측정**. §2-1 은 코드 독해와 책 인용뿐이다.
2. **D2 의 `strategy_for_sell is None` 이 언제 참이 되는지 규명 못 했다.** 6건이 2026-06-11~22 에 몰려 있다는 사실만 안다. 당시 커밋 이력을 추적하지 않았다(git blame 미수행).
3. **D4 의 K 초과 «원인»은 미규명.** 동일코드 중복 가설만 기각했다(§3-F). 다른 후보(비동기 체결 순서 · 복원 누락 · `ctx.buy` 재시도)는 **손대지 않았다.**
