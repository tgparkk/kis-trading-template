## 4. 주장 원장 스키마

한 행 = **저자의 주장 하나**. 글 하나가 여러 행을 낳을 수 있고, 최소 1행은 반드시 낳는다.

| 열 | 타입 | 내용 |
|---|---|---|
| `log_no` | str | 네이버 글 ID. 재수집으로 원문 복원 가능 |
| `post_date` | date | 게시일 (KST) |
| `category` | int | 28 / 29 |
| `claim_id` | str | `{log_no}-{순번}` |
| `topic` | enum | `①후보선정` `②앵커` `③분할매수` `④분할매도` `⑤데이터기반` `⑥국면대응` `⑦프로그램·상품` `⑧기타` |
| `claim` | str | 한 문장 서술 |
| `numbers` | str | 등장 수치 **원문 표기 그대로** (`;` 구분) |
| `quote` | str | 근거 인용 **40자 이내** |
| `para_idx` | int | `text28/*.txt` 내 문단 인덱스 |
| `image_ref` | bool | 본문이 이미지를 가리키는가 → ④단계 대상 선별 |
| `vs_v1` | enum | `new` / `agree` / `conflict` / `revision` / `none` |
| `v1_anchor` | str | `agree`·`conflict`·`revision` 일 때 METHOD 1판의 해당 절 (예: `§1-③`) |

### `revision` 을 `conflict` 와 나누는 이유

저자는 같은 규칙을 몇 년에 걸쳐 반복 서술하고, 그때마다 수치가 바뀐다.
1판이 이미 잡은 예 — 누적 통계 **1만 건 이상(2025-08) → 12,500여 건(2025-10) → 13,503건(2026-07)**
(`METHOD.md:107`). 이를 `conflict` 로 묶으면 **저자의 버전업이 우리의 모순으로 기록**되고,
무시하면 **마지막에 읽은 글이 이긴다**. 원장이 시계열을 들고 있어야 사후 판단이 가능하다.

### `topic` 에 `⑥국면대응` 을 둔 이유

1판 §1-④가 이미 *"하락장에서는 HDR을 좁히고 그 초입에서 전량 또는 보유의 70~80% 매도"*
(`METHOD.md:87`)를 잡았다. 국면별 대응 규칙이 실재하며, 그것이 [29] 시황이슈 정리에 더 있을
개연성이 [29]를 범위에 넣은 근거다. 전용 `topic` 이 없으면 `⑧기타` 로 흩어져 병합이 안 된다.

### 「글당 최소 1행」 강제

방법론 주장이 없는 글도 `topic=⑧기타, claim="방법론 주장 없음", vs_v1=none` 행을 남긴다.
없으면 *에이전트가 배치를 건너뛴 것*과 *그 글에 주장이 없던 것*이 구분되지 않는다.
⇒ **V2가 성립하는 전제조건**이다.

## 5. 검증 5종

각각이 **서로 다른 실패 방식**을 잡는다. 하나가 다른 하나를 대체하지 않는다.

| | 검사 | 잡는 실패 | 실패 시 |
|---|---|---|---|
| **V1** | 카테고리 API `postCnt` ↔ 목록 API logNo **집합** ↔ 저장 파일 **집합**, 3중 대조. 두 집합 간에는 **차집합 0 assert** | 페이지네이션 조기 종료 / 본문 수집 누락 | 중단·보고 |
| **V2** | 원장의 distinct `log_no` 수 == 수집 파일 수 | 에이전트가 배치 일부를 조용히 건너뜀 | 해당 배치 재실행 |
| **V3** | METHOD 1판의 서술 항목을 열거해, 각각이 원장에서 `agree`/`conflict`/`revision`/**미등장** 중 무엇인지 판정 | **정독이 얕음** | 미등장 항목의 원문 재확인 |
| **V4** | 무작위 12건을 **독립 에이전트가 재정독**해 원장과 대조, 놓친 주장 수 실측 | ③단계의 추출 누락률 | 누락률을 2판에 **명시** |
| **V5** | 같은 `topic` 의 `numbers` 시계열 정렬 → `conflict` 로 분류된 것이 실은 저자의 버전업인지 재판정 | 저자의 개정을 우리 모순으로 오기록 | `revision` 으로 재분류 |

### V1 에서 `postCnt` 가 안 맞으면

카테고리 API 의 `postCnt` 와 목록 API 가 실제로 주는 글 수는 어긋날 수 있다(비공개·삭제 글 등).
⇒ **어긋남 자체를 실패로 처리하지 않되, 사유를 규명하기 전에는 「전수」라는 표현을 쓰지 않는다.**
분모는 목록 API 집합으로 확정하고, `postCnt` 와의 차이를 **수치로 기록**한다.
(목록 API 집합 ↔ 저장 파일 집합의 차집합 0 은 **무조건 강제**다. 이쪽은 우리 책임이다.)

### V3 이 이 설계의 판별력 게이트다

V1·V2·V4는 전부 **「많이 모았나」**를 잰다. V3만 **「명백히 알아야 할 것을 놓쳤는가」**를 잰다.
1판이 73건으로 알아낸 사실이 432건 원장에서 안 나오면 그것은 수집이 아니라 **정독의 실패**다.

`changelog-2026-08-04-tasso-prereg-v3-corrections` 의 규칙을 그대로 적용한 것이다:

> 🔑 게이트의 판별력을 「통과했다」로 확인하지 말고 **「명백히 나쁜 설계도 통과시키는가」**로 확인하라.

**V3의 씨앗으로 쓸 기지(旣知) 불일치 1건** — 1판 내부에 이미 있다:
`METHOD.md:25`·`:177` 이 계산기 캡처를 **52장**이라 하는데 `calc_table.csv` 는 **51 데이터행**(실측,
헤더 제외)이다. `TASSO_OVERVIEW.md` 는 **51장**으로 적는다. 2판은 이 불일치를 **해소하거나,
해소 못 하면 불일치로 명시**한다. ⚠️ 단 *52장을 읽었으나 1장이 판독 불가였다* 도 가능한 설명이므로
**1판이 틀렸다고 단정하지 않는다.**

### V4 의 표본 12건이 무엇을 보장하고 무엇을 보장하지 않는가

12건은 **누락률의 점추정**을 준다. 432건 중 12건(2.8%)이므로 신뢰구간은 넓다.
⇒ 2판에는 **"놓친 주장 없음"이 아니라 "표본 12건에서 놓친 주장 N건"** 으로 적는다.
이 트랙의 규칙 *「비율이 재현된다고 분수가 맞은 것이 아니다 — 분자·분모를 각각 세라」* 를 따른다.
