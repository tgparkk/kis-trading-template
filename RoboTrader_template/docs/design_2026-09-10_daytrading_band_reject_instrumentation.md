## ① 목적과 측정 질문 — 계기를 켜면 «무엇이» 세어지나

계획서 §4-(e) 는 daytrading 에서 **못 재는 것 넷**을 적었고 그중 첫째가 이것이다: *「밴드가 «거부»한 횟수 — `47f0397` 이전은 원리적으로 관측 불가, 이후도 **스로틀·전략명 부재**로 완전한 계수가 아님」*.

계기 보강 후 **처음으로 계산 가능해지는 수 넷**:

| # | 질문 | 지금 | 보강 후 |
|---|---|---|---|
| Q1 | **전략별 밴드 거절 비율** = (그 전략의 밴드 거절 발화) ÷ (그 전략의 진입 시도) | ❌ 줄에 전략명이 없다 | ✅ `strat=` 필드로 직접 |
| Q2 | **상한 축과 하한 축을 나눠서** 세기 | ❌ 하한 거절은 «다른 이름»으로 샌다(②-2) | ✅ `why=` 사유 코드 |
| Q3 | **패딩봉(D3)이 만든 발화** — `090150` 같은 사례가 «거절된» 쪽에도 있나 | ❌ 체결된 것에서 역추정만 했다(`daytrade_진입밴드_조사` §9-3) | ✅ `z0=`(창 안 volume=0 봉 수) · `vr=`(거래량 배수) |
| Q4 | 스로틀에 **억제된 진짜 건수** | ❌ 인쇄된 줄만 보인다 | ✅ 15:35 요약의 `발화=` |

🔴 **이 계기가 «하지 않는» 것**: 밴드 «값» 불변 · 하한을 켜지 않는다(🔒 결정 3) · 매매 판단에 0줄 관여. 🔑 계획서 §1-1 원칙 3 그대로 — **「왜 안 샀는지」를 먼저 셀 수 있게 만든다.**

### ②-2. 🔴 하한 축은 «다른 이름»으로 새고 있다 (이번 조사의 새 사실)

`core/trading_decision_engine.py:411-413` 의 「진입가 밴드 **하회**」는 **7세션 전부 0건**이다. 이유가 둘이고 **둘 다 daytrading 때문이 아니다**:

⇒ 하한 거절은 이 줄로 나간다 — **전략명 없음 · 스로틀 없음**:

## ③ 새 로그 줄 스펙

**고정 태그** `[밴드거절]` (기존 `[매수거절]`·`[신호없음]` 과 같은 대괄호 관례). **`k=v` 공백 구분 · 순서 고정 · 결측은 `-`.**

```
[밴드거절] strat={폴더키|-} code={종목} why={BAND_UP|BAND_DOWN|STOP_UNREACHED} px={현재가} lo={하한|-} hi={상한|-} ref={기준가|-} dev={+0.00%|-} win={창봉수|-} vr={거래량배수|-} z0={0봉수}/{창} hit={당일누적} site={analyzer|context}
```

예 (설계 예시):
```
[밴드거절] strat=daytrading_3methods_breakout code=090150 why=BAND_UP px=9000 lo=- hi=8580 ref=8330 dev=+8.04% win=20 vr=13.59 z0=18/20 hit=1 site=analyzer
[밴드거절] strat=book_pullback_ma5 code=051980 why=STOP_UNREACHED px=1044 lo=1051 hi=1116 ref=1083 dev=-3.60% z0=- hit=1 site=context
```

| 필드 | 출처 (읽기만) |
|---|---|
| `strat` | analyzer = `bot/trading_analyzer.py:104` 의 `strategy_name` 파라미터(**이미 스코프에 있다** — `core/trading_context.py:515` 가 `strategy_name=self._strategy_key` 로 넘긴다) · context = `core/trading_context.py:68` `_strategy_key`. 레거시 경로(`main.py:617`)는 빈 문자열 → `-` |
| `px` | context = `:440` 지역변수 `live_price` · analyzer = 엔진 사유 문자열의 `현재가 N` 을 정규식 1회 파싱(**엔진 문자열은 바꾸지 않는다** — `bot/trading_analyzer.py:170` 주석·다른 문서가 참조). 실패 시 `-` |
| `lo`/`hi` | `signal.entry_min_price` / `entry_max_price` **직접**(`strategies/base.py:115-116`) — 파싱 아님 |
| `ref`/`dev` | `signal.metadata["close"]`(daytrading `strategy.py:273` · ma5 `:273` · elder `:351`). 없으면 `-` |
| `win`/`vr` | `signal.metadata["vol_ratio"]`(daytrading `strategy.py:272`, 원천 `strategies/books/daytrading_3methods/rules.py:290,301`) · `win` = `vol_lookback`(같은 파일 `:279`, **라이브 배선 없음 → 20 고정**) |
| `z0` | analyzer 가 **이미 읽어 둔** `daily_data`(`bot/trading_analyzer.py:139`, `days=140`)의 마지막 `win` 봉 중 `volume==0` 개수. **DB 추가 조회 0건.** context 경로는 `daily_data` 가 없어 `-` |
| `hit` | ④ 스로틀 카운터의 당일 누계 |

**레벨**: 첫 N회 = **INFO**(파일 레벨이 INFO — `47f0397` 이 고친 바로 그 이유) · 억제분 = **DEBUG**(조용한 손실 금지, 선례 `bot/trading_analyzer.py:177-178`) · 15:35 요약 = INFO.
🟢 **기존 줄은 한 글자도 바꾸지 않는다 — 순수 «추가»다.** 근거: `tests/bot/test_buy_rejection_visibility.py:140` 이 `[매수거절] {사유}` **정확 일치**를 단언한다. 여기에 전략명을 끼우면 그 회귀 테스트와 기존 EOD grep 이 동시에 깨진다.

## ④ 스로틀 규칙

- **키** = `(거래일KST, strat, code, why)` — 거래일이 키에 있어 **자정 자동 회전**.
- **첫 N = 3 회 INFO**, 4회째부터 카운트만(DEBUG). 첫 발생은 반드시 통과(선례 `bot/trading_analyzer.py:91-93`).
- **일일 하드캡 X = 150줄**(태그 전역). 도달 시 `[밴드거절] 일일 상한 150줄 도달 — 이후 억제, 15:35 요약 참조` **1줄** 찍고 정지.
- **15:35 요약**(전략×사유당 1줄 · ≤ 25줄): `[밴드거절요약] strat={} why={} 발화={총}건 인쇄={}건 억제={}건 종목={u}개 top={code}:{n},… since={기동시각}`
- 요약 직후 카운터 dict 를 비운다(메모리). ⚠️ 봇 재기동 시 카운터·요약이 함께 리셋된다 — 그래서 `since=` 를 인쇄한다.

**X 의 근거 (실측에서 유도)**

| 시나리오 | 원 스트림 | N=3 규칙 적용 시 |
|---|---:|---:|
| 상한 축 최다일 09-07 (6종목) | 40줄(이미 10분 스로틀됨) / 엔진진입 244 | **≤ 18줄** |
| 상한 축 09-09 (8종목) | 25줄 | **≤ 24줄** |
| 하한 축 09-09 (6종목) | **324줄(무스로틀)** | **≤ 18줄** |
| 전형 합계 | — | **≈ 45줄/일** |
| 구조적 최악 = 3 × (전략,종목)쌍 47 × 사유 2 | — | 282줄 → **캡 150 이 문다** |

(쌍 47 = 09-09 전략별 `[on_tick] 매수검토` 최대치 합: daytrading 10 · ma5 10 · ma20 9 · elder 7 · rs 6 · minervini 3 · envelope 2 · deep_mr 0.)
⇒ **전형 +45줄/일**(당일 총 7,552줄의 **0.6%**) · **최악 +175줄**(150 + 요약 25). 기존 324줄은 **그대로 남는다**(EOD 연속성 보호).

```sh
grep 'DayTrading3MethodsBreakoutStrategy.*\[on_tick\] 매수신호' LOG | wc -l                     # 분모(종목-틱)
```
「종목-일」로 보려면 분자는 요약줄의 `종목=`, 분모는 `[on_tick] 매수신호` 의 **유니크 종목 수**. 🔑 **두 단위를 섞지 말 것** — 한 신호가 틱마다 재평가된다(09-09 `069540` 엔진진입 11회 → 거절 로그 5줄).

**(2) 패딩봉(D3) 오발화 탐지**
```sh
grep '\[밴드거절\]' LOG | grep -v 'z0=-' | awk -F'z0=' '{split($2,a,"/"); if (a[1]+0>0) print}'
```
`z0>0` 인 줄 = D3 후보. 교차검증 SQL(**읽기 전용 · resolver 경유 `kis_template`**):
```sql
SELECT trade_date, volume FROM daily_prices WHERE stock_code=:code AND trade_date<=:d
ORDER BY trade_date DESC LIMIT 21;   -- volume=0 봉 수가 로그의 z0 와 같은가
```
⚠️ **한계**: `z0` 는 analyzer 가 **자기 140봉 fetch**(`:139`)에서 센 값이라 **전략이 «본» 창과 다를 수 있다.** 계기이지 재현이 아니다 — 판정에 쓰지 말고 **후보 추출**에만 쓴다.

**(3) 하한 축 반사실** — `why=STOP_UNREACHED` 를 `strat=` 별로 집계하면 정-6 의 **집합 교차 추정이 필요 없어진다**(324건의 참 귀속).

**(4) EOD 점검표 추가 2줄**: `[밴드거절요약]` 전 줄 인쇄 · `z0>0` 건수. 🔑 **총건수가 아니라 «집합» 차분으로 본다**(운영 규칙 T5).
