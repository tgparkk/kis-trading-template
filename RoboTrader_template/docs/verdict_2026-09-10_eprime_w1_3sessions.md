### 3-B′. 값 수준 보존(J1 주 판정) — ⚪ **판정 불가 (vacuous)**

사전등록 §4-1 J1 **보강 필수 조건**이 미충족이다. 두 갈래로 각각 확인됐다:

1. **대상 집합이 비어 있다.** 배포 직전 기준선 스냅샷의 `manifest.json` 이 `"targets": []` — J1 이 해시할 「③ 재적용 배치 대상 종목」이 **아직 없다**. 결정 **D-6 (가)** 대로 (E′) 를 ③ «전»에 배포했으므로 **설계된 결과**다.
2. **관측 창 안에 「보정된 과거행」이 하나도 없었다.** 09-09 `W1` 73종목의 과거창에서 `adj_factor ≠ 1` 인 종목은 5개(054940·053950·024850·001510·003350)뿐인데 그 행들의 `close` 는 **여전히 원주가**다 — 054940 은 08-11 `760`(adj 0.2) → 08-12 `3,815`(adj 1) 불연속, 003350 은 04-17 `48,200`(adj 5) → 04-20 `9,400`(adj 1) = 바로 그 **−80.5% 불가능봉**. ⇒ ***「P-a 값 보정이 적용된 과거행」이 W1 집합에 0건.*** [LANE_C §1-e(4) · 보고서 §7-4]

🔑 ***「덮어썼는데 같더라」와 「안 덮어썼다」는 관측이 같다***(사전등록 §9 계열 규칙 2). 값 수준은 **차단이 값을 지켰다는 별도 증거**가 있어야 하고, 이번 창엔 그 증거를 만들 재료가 없었다.
🔴 사전등록 §5-⑦ 은 *「J2 가 실패하면 J1 을 판정하지 않는다」*고 했다. **J2 는 실패하지 않았다**(축 A PASS · 축 B 행 수준 PASS) — J1 이 판정 불가인 이유는 J2 실패가 아니라 **기준점 부재**다. 둘을 섞지 않는다.

## §4. 로그에 대한 «정정된» 진술 (동결)

09-07·09-08 기록의 「덮어쓰기 차단이 `logger.debug` 라 안 찍힌다」는 **부정확했다.** 정확한 진술은 다음 세 줄이다. [보고서 §7-3 · VERIFY_rev1 보-1 · `db/repositories/price.py:128-137`]

1. 🔑 **차단 건수를 «직접» 찍는 문장은 애초에 존재하지 않는다.** `price.py:128-130` 의 `logger.debug` 가 찍는 값은 `len(past_rows)`(제시행)와 `len(today_rows)` 뿐이다.
2. 🟢 **「로그로는 불가능하다」는 과장이다** — DEBUG 를 켜면 종목별 `len(past_rows)` 가 찍히고 INFO 가 `n_filled`(= `cursor.rowcount`, 실제 INSERT)를 찍으므로 **「제시행 − `n_filled`」 뺄셈으로 종목별 차단 수를 로그만으로 유도**할 수 있다. 09-09 의 7,373 − 77 이 바로 그 뺄셈이다.
3. ⚠️ `n_filled` 앞에 **`if n_filled:` 가드**가 있어(`price.py:131-134`) **차단만 일어난 종목(n_filled = 0)에는 INFO 줄이 아예 안 나온다.** 09-09 은 73종목 중 **72종목**이 그 경우였다.

**`updated_at`·`created_at` 은 판별 도구가 못 된다 — 가정이 아니라 실측이다** (사전등록 §4-1 J3 의 금지와 정합):
- `updated_at ≥ 09-09 00:00 AND < 15:00` → **0행**. 15:45 3,051,916행 + 15:46 142,923행 = **3,194,839행 = 표의 100%** 가 저녁에 재스탬프(`collectors/daily_derived.py:69` 가 표 «전체» returns/volatility 재계산). ⇒ **저녁 `updated_at` 차분은 W1 에 대해 판별력 0**.
- `created_at` 도 못 쓴다 — INSERT 든 UPSERT 든 SET 목록에 없어 보존된다(`price.py:19-33`).

## §7. 이 판정문이 «아닌» 것

1. **롤백 권고가 아니다.** 축 A PASS · 축 B 행 수준 PASS 이므로 사전등록 §4-3 의 즉시 롤백 조건(당일 INSERT = 0 / 과거 UPDATE > 0)은 **어느 것도 성립하지 않는다**.
2. **「(E′) 가 N-1 을 해결했다」가 아니다.** 사전등록 §3-7-7 이 미리 못박았다 — *「(E′) 만으로는 DB 의 규약 혼재가 «전혀» 줄지 않는다. (E′) 를 「N-1 해결」이라고 부르면 안 된다.」*
3. **튜닝·문턱 변경이 아니다.** N 을 늘리지 않고, 새 문턱을 만들지 않으며, 판정 후 파라미터를 손대지 않는다(§6-1·§6-5·§6-14).
4. **§9-0 정오와 §9 M-2~M-5 는 여전히 미해소**다. 이 판정문이 닫은 것은 **M-1 의 3세션치 실측**뿐이다.
