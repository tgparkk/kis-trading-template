> 근거: 결정 `decision-2026-10-16-meeting-1017-agenda` 0번③ · XCHECK_2 §③④ · 초안 `DRAFT_` + critic `CRITIC_`(전부 반영). 코드 줄 번호는 10-16 에 직접 열어 확인함(틀린 것은 §11).

## §1 목적·기간
- 목적: 같은 룰의 daytrading 을 페이퍼(가상 체결)와 실전(실주문)이 같은 종목·같은 날 어떻게 다르게 사고 팔았는지, **비용과 체결 품질**을 잰다. 수익률 비교가 아니다.
- 시작 10-19(월) 07:45. 「4주」는 최소 조건: 실전 BUY 짝 n≥30 **그리고** 거래일 ≥15. 둘 다 차면 이르면 11-13 요약. 안 차면 11-13 에 «표본 부족 · 계속».
- **연장 상한**: 12-11 과 «다음 룰 변경 발효 전날» 중 빠른 날. 그날까지도 미달이면 점값만 쓰고 종결.

## §2 단위 = 대응쌍 (지표마다 모집단이 다름 — s8)
- 키 = (KST 매수일, 종목코드). 페이퍼 = `virtual_trading_records`(`source='kis_template'` · strategy='daytrading_3methods_breakout' · is_test=true · action='BUY'). 실전 = `real_trading_daytrading`(action='BUY' · `timestamp >= '2026-10-19'` · **strategy 조건은 걸지 않음** — 실전 열 값이 페이퍼와 같은 폴더키인지 §10-4). 날짜식 `(timestamp at time zone 'Asia/Seoul')::date`(timestamptz 라 맞음).
- **짝**: 같은 키에 양쪽 BUY 가 있으면 시간순 1:1. 남는 건 «짝 없음».
- **분류**: ㉮ 짝(부분체결도 여기, M2) / ㉯ 페이퍼만(실전이 못 산 신호 → 커버리지 사유 §3①) / ㉰ 실전만(표본 제외, 건수·사유만).
- **지표별 모집단**: 지표 1·2·5 = 짝(㉮·㉯) · 지표 3(손절)·4(비용) = 실전 청산 전체(㉰ 포함)를 «실전 전체» 줄로, 짝만 따로 한 줄. 줄을 섞지 않는다.
- **청산쌍**: 짝 BUY 의 `buy_record_id` 로 이어진 SELL 끼리. 매도가 부분체결로 여러 행이면 **수량가중 평균가·마지막 행 시각**으로 1건 집계(s4). 실전 SELL 의 `profit_loss`·`profit_rate` 는 종목 전체 열린 BUY 평균가 기준(`db/repositories/trading.py:141-152`)이라 **쓰지 않는다** — 가격에서 직접 계산.
- 시작 시 보유 구성이 다르므로(실전은 빈 계좌) 포트 합계 비교 금지, 쌍 단위만.

## §3 지표 5개 (부호 있는 값 · 요약 = 중앙값 · 20%절사평균 · 최대/최소 · 거래일 군집 부트스트랩 95% CI)
**CI 방법(s6)**: 단위 = 거래일, 하루 안 쌍은 먼저 평균 → 「일평균의 평균」에 B=10,000 재표집 · percentile 2.5/97.5 · seed=20261113 고정. Wilson 은 쓰지 않는다. 상승일/하락일 구분 = 그날 KOSPI 등락(`daily_prices` 의사티커 `KOSPI`) 부호.
**지표별 최소 n**: 슬리피지·지연 = 짝 15 · 청산 지표 = 청산쌍 15 · 손절 지표 = 손절 건 10. 미달이면 «표본 부족» + 점값만(CI 안 냄).

1. **커버리지** — 두 겹으로 나눈다(M1).
   - 신호 커버리지 = 실전 `매수 주문 시도` 쌍 ÷ 페이퍼 BUY. 집행 커버리지 = 실전 BUY 행 ÷ 실전 시도. **체결 품질 지표(2·5)는 집행 쪽만.**
   - 분모 제외: 실전 미가동 구간(go/no-go 실패·비상 정지·늦은 기동 — 가동 구간 = 실전 로그 첫 줄~마지막 줄)의 페이퍼 BUY 는 «실전 미가동» 으로 빼고 개수만.
   - **사유 매핑표(기계 판정 · 이 순서 · 사후 재분류 금지)**: ① `[캡]…사유=`(`strategies/base.py:611`) · `[shadow]…캡사유=`(`:655`) → 한도 ② `자금 부족: 필요=`(`bot/trading_analyzer.py:225`) · `자금 부족으로 매수 주문 거부`(`core/orders/order_executor.py:144`) → 현금 ③ `매수 주문 차단:`(`order_executor.py:89-115` · 시간대·VI·서킷브레이커·소유전략) → 차단 ④ `매수 주문 API 타임아웃`(`:217`) → API ⑤ `5분 타임아웃 처리`→`타임아웃 취소 성공` → 지연 취소 ⑥ 실전 시도 로그 자체가 없음 → «실전 시도 없음» ⑦ 나머지 → «기타».
   - **수량 충족률** = 체결수량 ÷ 주문수량, 별도 칸(부분체결은 ㉮ 로 두고 여기서 드러냄).
   - 해석 금지: 실전은 종목당 cap×9% · 총투자 90% 상한(`core/fund_manager.py:212-213`)이라 ≈45만원×10 = 상한 그 자체. 페이퍼 ≈107.8만원×10 은 1,000만을 넘는다. **«한도·현금» 비율은 사이징이 만든 구조값**이라 «실전이 못 산다/잘 산다» 로 읽지 않는다. 양쪽 비율을 각각 적기만.
2. **매수 슬리피지 %** — 두 조각으로 분리(M3).
   - 타이밍 = (실전 주문가 − 페이퍼 체결가) ÷ 페이퍼 체결가 ×100. 실전 주문가 = `round_to_tick` 한 값(`order_executor.py:207`).
   - 집행 = (실전 체결가 − 실전 주문가) ÷ 실전 주문가 ×100. 양수 = 실전 불리.
   - **제외 규칙**: 두 BUY 시각 차 |Δt| > 10분 쌍은 슬리피지에서 제외(커버리지엔 포함) · 실전 체결가가 호가 격자 밖이면 «체결가 폴백» 표식(`avg_prvs` 가 비면 반올림 전 `order.price` 저장 — `core/orders/order_monitor.py:383` · `order_timeout.py:275`)하고 제외, 개수만 기록.
   - 교란 표기: 루프 주기가 다르다(페이퍼 8전략 라운드로빈 ≈72초 vs 실전 ≈9초 — `main.py:486` 주석 «9초×전략수»). 타이밍 조각에 섞이는 몫으로 명시.
   - 틱 수 = (실전 − 페이퍼) ÷ 그 가격대 호가 단위(s3). 부분체결 쌍은 수량가중 체결가.
3. **손절 초과폭** — 정의를 로그 기반으로 바꾼다(B1). 실전 BUY·SELL `reason` 은 늘 «실전매매»(`core/orders/order_db_handler.py:153,195`)라 reason 으로는 실전 손절을 못 가른다.
   - 실전 손절 = 로그 `{code} 손절 신호: 손절 실행 (`(`core/trading/position_monitor.py:338`) 뒤 같은 종목 **첫** 실전 SELL 행(여러 행이면 수량가중). 페이퍼 손절 = `reason LIKE '손절 실행%'`(SR1 과 같은 정의). 손절선 = 그 포지션의 stop_loss_rate(페이퍼 DB 열 · 실전 config 값, 지금 0.10).
   - **두 칸으로 분리**(갭 손절이 집행 비용으로 둔갑 방지): ㉠ 감시·갭 몫 = 트리거 시점 수익률(로그 −x%) − (−손절선) · ㉡ 집행 몫 = (체결가 ÷ 트리거 시점 가격 − 1)×100. 합이 «손절 초과폭».
   - 계산은 가격에서 직접(`profit_rate` 금지). 실전 전체 줄 + 짝 줄을 따로. **짝 줄은 §4 같은-날 규칙을 따른다.**
4. **라운드트립 비용 %** = (수수료+세금) ÷ 매수금액 ×100. 출처를 하나로 동결한다(B2).
   - 가정 비용 = 상수식 0.015%×2 + 0.18% = 0.21%(`config/constants.py:182-183`) — 페이퍼와 실전 DB 모두 이 상수로만 net 을 계산(`db/repositories/trading.py:159-167`)하고 실전 `fee_amount`·`net_profit`·`net_profit_rate` 는 NULL. **DB 값은 «실제 비용» 이 아니다.**
   - **실제 비용 출처(고정)**: 매주 목요일 EOD, KIS 체결·매매손익 내역의 **건별 수수료·제세금(원 단위)**. 대상 = 그 주까지의 실전 청산 전부. 대조 키 = (날짜, 종목, 수량). 못 구한 건은 «미측정 N건» 으로 개수를 적고 가정값으로 메우지 않는다. §8 표의 «비용(실전/가정)» 열도 이 출처로 채운다(미수집 주는 «미측정»).
   - **KIS 내역을 «누가·어떻게» 받나 — 사장님이 고를 것(값은 고르지 않음)**:
     - 선택 A: 사장님이 HTS/MTS 에서 체결·매매손익 내역을 매주 목 EOD 내보내기(코드 0줄 · 사람 손 주 1회).
     - 선택 B: 코드로 KIS 조회 — 코드에 이미 있는 TR: 일별주문체결 `TTTC0081R`(`api/kis_order_api.py:264` `get_inquire_daily_ccld_lst`, 운영 중) · 기간별손익일별합산 `TTTC8708R`(`api/kis_account_api.py:239` `get_inquire_period_profit_lst`, **운영 호출처 없음 · 응답에 건별 수수료·세금 필드가 있는지 미확인**) · 잔고조회_실현손익 `TTTC8494R`(`:184`, 같은 미확인). 별도 읽기 전용 스크립트 + 리뷰 필요(라이브 코드 변경 아님).

5. **체결 지연 초** — 둘로 분리(M4).

## §4 수익률 = 관측만 · SR1 봉인 보호(M5)
- 쌍별 수익률 차·포트 수익률은 «관측» 배너에만. 이유: n≈40, 건당 SD≈9.5%p → 표준오차 ≈1.5%p, 같은 날 건은 시장을 공유해 더 큼. 비용·슬리피지는 ±0.2%p 수준이라 잴 수 있다. 수익률로 «낫다/못하다» 결론 금지.
- 🔴 **쌍 비교(청산가 차이 · 손절 짝 줄 · «청산 비대칭» 칸)는 두 청산이 «같은 KST 거래일» 인 쌍만 계산한다.** 기준일 = 각 SELL 행의 KST 날짜(매수일 아님). 나머지(한쪽만 청산 · 청산일이 다름 · 미청산)는 **건수만** 적고, 한쪽 매도 «뒤» 다른 쪽 가격은 어떤 계산에도 쓰지 않는다 — SR1 봉인 표본(D_asof 10-16)과 §11-2 전향 누적을 오염시키지 않기 위함.
- 실전 단독 지표(3㉠㉡·4)는 자기 거래만 보므로 이 제한이 없다.

  - B = 10-29 창구(ma20 수정 · 재기동 한도 수정) → **발효 10-30 07:40**. 이후 쌍 표식. 재기동 한도 수정은 daytrading 한도 동작을 바꾸지만 영향은 «재기동일» 뿐(그날 이미 제외). ma20 수정은 daytrading 지표에 영향 없음을 첫 보고에 명시.
  - 11-05·11-12 창구도 같은 방식으로 등재.
- **tp/sl 해소 실패 표식**: 실전 로그 `[B2-실전]` 경고(`core/trading_decision_engine.py:545~` 근처)가 찍힌 포지션은 표식 — 실패 시 tp 15%·sl 10% 가 7거래일 뒤 5%/5% 로 조여진다(`bot/state_restorer.py:873-876`).
- 부분체결·거절·미체결 취소는 제외하지 않고 커버리지 사유로 센다.
- 수량 차이(≈45만 vs ≈108만): 수량·금액·원 단위 손익은 짝 비교에 쓰지 않는다(가격·% 지표만). 원 단위는 «실전 net 합계» 보고(비교 아님)에만.
- 규칙 변경은 데이터 열람 후 금지. 바꾸려면 동결본에 날짜·이유를 덧붙임(원문 유지).
