## §4. 판정 기준 — 실행 «전»에 동결 (채택안이 (E′) 일 때)

> 🔴 채택안이 (E′) 가 아니면 **이 절 전체를 채택안 전용으로 다시 동결한 뒤** 실행한다. 재동결은 **판정을 보기 전**에 한다.
> 🔴 허용오차는 ② 등록값 **`0.5%`** 하나만 쓴다. **새 문턱을 만들지 않는다**(② §6-1).

### 4-1. 판정식

**J1 (주 판정 — 「보정이 밤을 넘긴다」)** · 대상 = ③ 재적용 배치의 전 종목 · 기준 = **등호**(배율 판정이 아니라 「안 건드렸는가」 ⇒ ② §6-6 예외)

🔴 **해시에 `volume` 을 포함한다 (verifier 지적 B5).** (E′) 는 OHLC 만이 아니라 **`volume` 쓰기도 함께 얼리고**, `W2` 는 `volume` 을 매일 다시 쓴다 [코드 `collectors/daily_writer.py:45-49`]. 가격만 해시하면 **volume 원복이 J1 을 조용히 통과**한다. 그리고 읽기 계층은 `volume × adj_factor` 를 거래대금·거래량비 룰에 쓴다 [코드 `db/repositories/price.py:114-121`] ⇒ **판정 대상이다.**

```sql
-- J1 해시 (동결) — OHLC + volume. adj_factor·updated_at 은 «제외»한다.
--   · adj_factor 제외 사유: 지우개가 매일 재작성하는 파생값이라 판정에 넣으면 항상 실패한다(② §3-5 R2)
--   · updated_at 제외 사유: daily_derived 가 매일 전 행 재도장(② §6-10)
SELECT stock_code, count(*) AS n,
       md5(string_agg(date||':'||open||':'||high||':'||low||':'||close||':'||volume,
                      ',' ORDER BY date)) AS ohlcv_md5
  FROM daily_prices
 WHERE stock_code = ANY(:targets) AND date <= :ASOF
 GROUP BY 1 ORDER BY 1;
```
- **apply 직후 `ohlcv_md5`** 와 **N 번째 EOD 다음날 아침의 `ohlcv_md5`** 가 **전건 동일**.
- **N = 3 거래일**(선정 회전으로 종목이 `W1` 대상에 한 번은 들어가도록). 🔴 **N 은 이 문서에서 고정한다 — 판정 후 늘리지 않는다.**
- 🔴 **보강 필수 조건**: 판정 기간 중 **대상 종목이 실제로 `W1` 목록에 «한 번 이상» 등장**해야 한다 [실측 로그로 확인]. 등장 0회면 **J1 은 「통과」가 아니라 「판정 불가(vacuous)」**로 기록한다. ***P7 이 정확히 이 함정에 빠졌다*** — 「persist」가 실은 no-op 재기록이었다 [산출물 §5].
- ⚠️ **`W2` 사정거리(최근 7봉) 안의 행은 J1 에서 «분리 집계»한다** — 그 행의 변화는 (E′) 의 실패가 아니라 설계된 잔여 채널이다(§2-6·§4-3).

**J2 (양성 대조 — 가드가 «죽어 있지 않다»)**

🔒 **동결 통과 조건 (verifier 지적 B1 반영 — 「INSERT 0」이 아니다)**

| 축 | 배포 전 기준선 (2026-09-03 실측) | (E′) 배포 후 예측 |
|---|---|---|
| 과거 행(`date < 실행일`) **UPDATE** | **7,650행/일** (75종목 × 102) | 🔒 **0행** |
| 당일 행(`date = 실행일`) **INSERT** | **75행/일** | 🔒 **≈ 선정 종목 수** (그날 종목 수만큼) |
| 과거 행 **INSERT**(빈 칸 채우기) | 미측정(§2-4 잔여 오염) | 🔒 **≥ 0 · 값 자체를 기록** |

## §5. 실행 절차 (채택 후)

### ① 사전 스냅샷 (읽기 전용 · 🔴 산출물은 세션 Temp 스크래치 «금지» — 리포 내 경로에 저장)

🔴 **(a)~(d) 는 전부 `W1` 이 도는 07:40 «전»에 뜬다.** 장 마감 후 EOD 완료 뒤가 가장 안전하다 — §2-4 의 자기 오염(B1)이 바로 이 순서를 안 지켜서 생겼다.

```sql
-- (a) J1 기준선: ③ 배치 대상 종목의 OHLCV 해시 (§4-1 J1 의 SQL 과 동일해야 한다)
SELECT stock_code, count(*) AS n,
       md5(string_agg(date||':'||open||':'||high||':'||low||':'||close||':'||volume,
                      ',' ORDER BY date)) AS ohlcv_md5
  FROM daily_prices WHERE stock_code = ANY(:targets) AND date <= :ASOF GROUP BY 1 ORDER BY 1;

-- (b) J6 기준선: 창 안 규약 상이 행                       -- 2026-09-03 기준 52종목 / 2,237행
SELECT count(DISTINCT stock_code) AS codes, count(*) AS rows
  FROM daily_prices
 WHERE date >= to_char(current_date-150,'YYYY-MM-DD')
   AND adj_factor IS NOT NULL AND adj_factor <> 1;

-- (c) J5 기준선: 대상 종목의 창 안 행수 분포
SELECT stock_code, count(*) FROM daily_prices
 WHERE stock_code = ANY(:targets) AND date >= to_char(current_date-150,'YYYY-MM-DD') GROUP BY 1;

-- (d) J7 기준선: W 중 E_j 가 «최근 7 거래일(양끝 포함)» 안인 종목 수   -- 2026-09-03 기준 22
--     🔴 경계는 >= 다. > 로 쓰면 6세션 창이 되어 21 이 나온다(경계 종목 033170).
WITH b AS (SELECT stock_code, date, close, volume,
                  ROW_NUMBER() OVER (PARTITION BY stock_code ORDER BY date) AS rn
             FROM daily_prices WHERE stock_code ~ '^[0-9]{6}$'),
g AS (SELECT b.*, rn - ROW_NUMBER() OVER (PARTITION BY stock_code,(volume=0) ORDER BY date) AS grp FROM b),
r AS (SELECT stock_code, date, close,
             CASE WHEN volume=0
                  THEN ROW_NUMBER() OVER (PARTITION BY stock_code,(volume=0),grp ORDER BY date)
                  ELSE 0 END AS zrun
        FROM g),
p AS (SELECT stock_code, date, close,
             LAG(close) OVER (PARTITION BY stock_code ORDER BY date) AS prev_close,
             LAG(zrun)  OVER (PARTITION BY stock_code ORDER BY date) AS halt_run
        FROM r),
be AS (SELECT stock_code, date, halt_run, close/prev_close AS ratio
         FROM p WHERE date >= '2024-01-01' AND date <= :ASOF
           AND close > 0 AND prev_close > 0
           AND (close/prev_close > 1.45 OR close/prev_close < 0.69)),
J  AS (SELECT DISTINCT stock_code FROM be WHERE ratio > 1.45 AND halt_run >= 9),
X1 AS (SELECT DISTINCT stock_code FROM be WHERE halt_run < 3),
W  AS (SELECT stock_code FROM J
        EXCEPT SELECT stock_code FROM X1
        EXCEPT SELECT unnest(ARRAY['010120','003350','058430','001510'])          -- X2
        EXCEPT SELECT unnest(ARRAY['005930','012210','336060','355150'])          -- X3
        EXCEPT SELECT unnest(ARRAY['001530','006040','036630','053950','086520',  -- X4
                                   '355150','260970','380540'])),
EJ  AS (SELECT stock_code, max(date) AS e_j FROM be
         WHERE ratio > 1.45 AND halt_run >= 9 GROUP BY stock_code),
W7D AS (SELECT min(d) AS w2_start FROM (
          SELECT DISTINCT date AS d FROM daily_prices
           WHERE date <= :ASOF ORDER BY d DESC LIMIT 7) z)   -- 최근 7 거래일의 «첫» 날
SELECT count(*) AS n_w2_exposed,
       string_agg(w.stock_code||'@'||e.e_j, ',' ORDER BY e.e_j) AS detail
  FROM W w JOIN EJ e USING (stock_code), W7D
 WHERE e.e_j >= W7D.w2_start;
```

🔴 (f) **`W1` 실행 «직전» 종목별 창 안 행수 스냅샷** — §2-4 의 잔여 오염(과거 구간 INSERT 규모 미측정)을 여기서 닫는다. 이것 없이는 J2 의 「과거 INSERT」 칸을 채울 수 없다.
