## §3. 보정 설계 — 행 단위 모델 + 화이트리스트

### 3-1. 방식 = **(다) KIS 두 피드 재수집**, 단 **유니버스 전체가 아니라 화이트리스트**

구현은 이미 있다 — `adj_repair.build_repair_rows:57`. ② 가 바꾸는 것은 **대상 집합**과 **`volume` 처리**뿐이다.

**화이트리스트 정의 (동결)**

```
W = ( C1 ∧ halt≥9 로 검출된 점프 보유 종목 240 )
    ∩ ( 합집합 프레임: B6 124 ∪ N-1 240 ∪ M2 101 )     ← ✅ 08-27 사장님 승인
    − ( M1 오염 124종목 )
    − ( partial 4종목: 010120 · 003350 · 058430 · 001510 )
    − ( §2-B 3종목의 해당 15행 · §2-C 005930 3행 )
```

✅ **합집합 프레임 확장은 2026-08-27 사장님 승인 완료**(①:354 의 「별도 승인」 조항 해소).
⚠️ **`W` 의 원소 수 = 「확인 필요」** — 교집합·차집합을 아직 계산하지 않았다. dry-run 첫 산출물이 이 수를 확정한다(§5-2).

### 3-2. 가격 규약 — ✅ **(P-b) 원주가 + `adj_factor` 기입 · 읽기 계층 «나누기» 동반** (확정)

| 안 | 저장 내용 | 읽기 계층 | 절벽 | 내구성 | 판정 |
|---|---|---|---|---|---|
| (P-a) 조정가 저장 | `close` ← 수정주가 피드 | 무변경 | 소멸 | 🔴 없음 — `daily_writer` 가 매일 원주가를 덮어쓴다 | **기각** |
| **(P-b)** 원주가 + `adj_factor` | `close` ← 원주가 피드 · `adj_factor` 채움 | 🆕 **`÷ COALESCE(adj_factor,1)` 추가** | 소멸 | ✅ 있음 — `daily_writer` 와 같은 규약 | ✅ **채택** |

**확정 사항**

1. 저장 = **원주가**(post-2026-04-27 규약으로 통일) + **`adj_factor` 기입**.
2. 읽기 = `db/quant_daily_reader.py:157-159` 에 **가격 나누기**를 «추가»한다. 근거는 §1-5 (d) — 「곱하지 말 것」은 혼재 상태 규칙이었고, 통일 후의 정답은 `adj_close = raw_close / adj_factor` 다.
3. `volume` 은 **지금처럼 곱한다**(`× COALESCE(adj_factor,1)`). ⇒ 저장 `volume` 은 **원본**이어야 한다(§3-3).

🔴🔴 **알고 남기는 위험 — 읽기 계층은 전역, 보정은 화이트리스트다.**
화이트리스트 «밖»에 `adj_factor ≠ 1` ∧ **조정가 저장(S1)** 인 행이 남아 있으면, 나누기를 켠 순간 그 행이 **이중조정**된다. M1 은 그런 경계를 **31개**(S1) 봤다(①:178). 화이트리스트 밖 잔존 규모는 **확인 필요**이며, ***그것을 잡는 장치가 P6 이다***(§4). ⇒ **P6 통과 전에는 읽기 계층 변경을 머지하지 않는다.**
