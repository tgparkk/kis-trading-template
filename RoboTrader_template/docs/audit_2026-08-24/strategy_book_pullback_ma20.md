## §2. 이탈 상세 (증거)

### 2-1. 🔴 `_recent_surge` 는 «급등»이 아니라 «방향 없는 변동폭» — 그리고 ma20 의 함수는 브리프가 가리킨 파일에 없다

**[독해]** `strategy.py:42` — `from strategies.books.haru_silijeon.rules_daily import _ma, rule_daily_ma20_pullback`. `screener.py:9` 도 같은 모듈. 그 룰(`rules_daily.py:108`)이 부르는 것은 **`strategies/books/haru_silijeon/rules_daily.py:52-61`** 의 `_recent_surge` 다:

```python
# strategies/books/haru_silijeon/rules_daily.py:52-61
def _recent_surge(df, lookback, surge_pct) -> bool:
    """직전 lookback 봉(마지막 봉 제외) 내 저점 대비 고점이 +surge_pct 이상 → 급등 이력."""
    seg = df.iloc[-(lookback + 1):-1]
    seg_low = float(seg["low"].min()); seg_high = float(seg["high"].max())
    return (seg_high - seg_low) / seg_low >= surge_pct
```

브리프의 「`trading_legends/rules_daily.py:49`」는 **ma5 의 사본**이다(`grep _recent_surge` 결과: haru 는 `:52` 정의·`:108/:157/:330` 3곳 호출, trading_legends 는 `:49` 정의·`:286` 1곳 호출). 두 함수는 **본문이 글자까지 같지만 별도 정의**다 ⇒ 「ma5 와 공유」는 거짓이고 **「같은 결함이 두 파일에 두 벌」**이 정확하다 — 한쪽만 고치면 다른 쪽이 남는다.

`min()`·`max()` 만 쓰고 시간 순서를 안 본다. **[SQL]** 매수 102건의 신호봉 직전 30봉 창을 재구성(`q3_rule_repro.sql`): 저점 먼저(상승형) **47** · **고점 먼저(하락형) 55 = 53.9%** · 창 평균 고저폭 **85.5%**(문턱 25% 의 3.4배). 기존 문서의 55/47·`119830` 사례(창 05-12~06-24, 고 8,900 / 저 5,750)는 **재현 일치**.

책은 「급등 이후 조정」(`reading_notes.md:76-80`)이다 — 방향이 뜻의 핵심이고, 코드는 그 뜻을 버렸다.
