### 7-2. 🔴 지수 일봉이 «조용히» 안 들어왔습니다 — **이쪽이 진짜 문제**

**한 문단으로 풀어 쓰면 이렇습니다.**

봇은 매일 장 마감 뒤 KOSPI·KOSDAQ 의 그날 지수 일봉을 FDR 에서 받아 DB 에 넣습니다. 그런데 FDR 은 **최근 10일치를 통째로 돌려주는 방식**이라, 오늘처럼 「지난 6일치는 있는데 오늘 것만 아직 없는」 응답이 와도 프로그램 눈에는 **「6행 받았다 = 성공」**으로 보입니다. 받은 행 수만 세고 **«오늘 날짜가 그 안에 있느냐»는 어느 쪽도 안 보기 때문**입니다. 그래서 EOD 요약에는 `지수 {'KOSPI': 6, 'KOSDAQ': 6}` 이라고 멀쩡하게 찍혔고 경고도 오류도 한 줄 안 나왔는데, **실제로 DB 에 들어간 건 어제까지의 지난 6일을 다시 덮어쓴 것뿐이고 오늘(09-08) 지수는 한 줄도 없습니다.** 게다가 2026-08-17 에 지수용 대조(reconcile)를 폐지해 놔서(`collectors/index_collector.py:7-10`) 이걸 잡아줄 안전망도 지금은 없습니다. **한 줄 교훈: 「N행 갱신」은 「오늘 것이 들어왔다」의 증거가 아닙니다.**

**중요 — 지수를 넣는 경로는 «두 개»이고, 오늘 «둘 다» 결손입니다.** 하나가 고장 나면 다른 하나가 메워주는 구조가 아닙니다.

| | ① regime 갱신 | ② EOD 지수 수집 |
|---|---|---|
| 코드 | `core/regime/index_refresh.py` | `collectors/index_collector.py` |
| 쓰는 표 | **`daily_prices` 의사티커**('KOSPI'/'KOSDAQ') | **`index_daily`** |
| 조회 창 | `_DEFAULT_LOOKBACK_DAYS = 10` (**:25**) | `timedelta(days=10)` 하드코딩 (**:30**) |
| 성공 판정 | 「빈 df/예외면 재시도, **행>0 이면 즉시 성공**」이라고 주석에 **명시**(:26-27 · 판정 본체는 **:69-70**) | **판정 자체가 없음** — 받은 행 수를 그대로 반환 |

### 8-3. 「고가 6,923.64 보다 높다」는 근거가 왜 무너지나

어제 논증의 핵심은 「6,995 는 당일 고가 6,923.64 를 넘으니 불가능하다」였습니다. 그런데 **6,923.64 는 실제 고가가 아니라 장중 한때의 값**입니다.

어제 로그의 시장현황 대시보드를 시간순으로 늘어놓으면 바로 보입니다:

| 시각 | 대시보드 KOSPI | 등락률 |
|---|---|---|
| **09:10:42** | **6,923.64** | +3.54% |
| 09:40:44 | 6,888.38 | +3.01% |
| 12:10:57 | 6,896.68 | +3.13% |
| 13:41:09 | 6,952.80 | +3.97% |
| 14:41:11 | 6,972.18 | +4.26% |
| **15:11:15** | **6,978.19** | **+4.35%** |

*(어제 로그 1032·1469·3210·4275·4994·5379행)*

**6,923.64 는 어제 09:10:42 의 장중 스냅샷입니다.** 장 후반에 이미 6,978 을 찍었으니 종가 6,995.39 는 아무 모순이 없습니다. 어제 DB 가 들고 있던 「고가 6,923.64 / 종가 6,885.81」 조합은 **오전 10시 무렵의 값처럼 보입니다** — 즉 **약 5시간 낡은 잠정 봉**이었던 셈입니다.

> ⚠️ 관리자 요약은 이 값을 「10:32경 스냅샷」이라고 적었는데, **로그 실측으로는 09:10:42** 입니다. 원본을 따릅니다.

### 8-4. 진짜 원인 — 「잠정 봉」과 「빈 봉」은 같은 병의 두 증상입니다

지수 수집은 마감(15:30) 직후에 돕니다(어제 15:49:11, 오늘 15:35~15:49). 그런데 FDR 의 지수 일봉은 **마감 직후엔 아직 확정치가 아닙니다.**

- **어제:** 확정 전의 **잠정 봉**이 들어왔다 → 종가가 6,885.81 로 낮게 박혔다.
- **오늘:** 아예 **아무 봉도 안 왔다** → 09-08 행이 통째로 없다.
- **그리고 다음날 EOD 가 자동으로 정정합니다.** 오늘 수집이 받은 6행(08-31~09-07)에 09-07 이 포함돼 있었고, `index_writer.py` 의 UPSERT 가 `ON CONFLICT ... DO UPDATE SET open, high, low, close, volume` 으로 **덮어쓰게** 돼 있습니다(`collectors/index_writer.py:6-8` — `volume` 도 포함입니다). 그 결과 어제 6,885.81 이던 09-07 종가가 **오늘 6,995.39 로 확정 교체**됐습니다.

**한 줄로:** 어제의 「불일치」는 고장이 아니라 **아직 안 굳은 값을 너무 일찍 읽은 것**이고, 시스템은 그걸 **다음날 스스로 고칩니다.** 어제 보고서는 그 자기수복 구조를 몰라서 「DB 가 맞다」고 반대로 판정했습니다.

### 8-5. ⚠️ 이 정정의 한계 — 반드시 같이 읽어야 할 단서

- **어제 시점의 DB 값(KOSPI 6,885.81 / KOSDAQ 826.38)은 지금 직접 재현할 수 없습니다.** UPSERT 가 그 행을 덮어썼기 때문입니다. 「어제 그 값이었다」는 **어제 세션 기록에만 의존**합니다.
- `index_daily.created_at` 도 증거가 못 됩니다. 09-07 행의 `created_at` 은 여전히 `2026-09-07 15:49:11` 인데, UPSERT 의 `DO UPDATE SET` 절에 `created_at` 이 없어서 **덮어써도 안 바뀌기 때문**입니다(`collectors/index_writer.py:4-10`). **즉 「언제 마지막으로 값이 바뀌었나」를 기록하는 컬럼이 이 표에는 없습니다.**
- **어제 보고서 §3-3 의 시장 대비 표(KOSPI +2.97%, KOSDAQ +1.58%)는 틀린 값입니다.** 올바른 09-07 수치는 **KOSPI +4.61%(6,687.21 → 6,995.39), KOSDAQ +1.07%(813.50 → 822.19)** 입니다. 따라서 **어제 계좌의 KOSPI 대비 열세는 3.1%p 가 아니라 약 4.8%p** 였습니다.
