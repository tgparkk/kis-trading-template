## 5. 오늘의 특이사항 2가지

### 5-a. (E-prime) 규칙 첫 발효일 — 발화 **0건 관측** (단, 관측 한계 있음)

**규칙이 켜져 있는 것은 확인됐습니다.**

- 스위치: `config/constants.py:34` -> `W1_PAST_ROWS_INSERT_ONLY = True` (문서상 유일한 롤백 스위치)
- 배선: `core/intraday/data_collector.py:113` -> `past_rows_insert_only=W1_PAST_ROWS_INSERT_ONLY`
- 오늘 그 경로가 실제로 돌았습니다: `core.intraday.data_collector` 가 「일봉 데이터 DB 저장 완료」를 **76회** 기록(07:40 기동분 + 장중 종목추가분).

**발화 로그는 0건입니다.**

- 「과거 구간 빈 칸 INSERT N행 (E-prime)」(`db/repositories/price.py:133-134`, INFO 레벨) -> **로그 전체에서 0회**.
- 지시받은 키워드도 전부 0건: `insert_only` 0 · `insert-only` 0 · `eprime` 0 · `동결` 0 · `freeze` 0 · `w1`/`W1` 0 · `past` 0. (`과거` 는 76건 나왔지만 전부 「과거 데이터 수집 시작…」이라는 무관한 줄이었습니다.)

> **다만 「0건」의 뜻을 정확히 해야 합니다.** (E-prime) 가 하는 일은 두 가지인데 로그에 남는 건 하나뿐입니다.

| 동작 | 로그 레벨 | 오늘 관측 |
|---|---|---|
| 없는 과거 행을 **채움**(빈 칸 INSERT) | INFO | **0건** (이건 확실히 0) |
| 있는 과거 행 **덮어쓰기를 막음** (규칙의 본래 목적) | `logger.debug` (`price.py:128-130`) | **확인 불가** |

봇의 로그 레벨이 INFO 라, 「막은 건수」가 적힌 줄(「E-prime 과거 N행 INSERT-only · 당일 N행 UPSERT」)은 **파일에 아예 안 찍힙니다.** 그러니 「(E-prime) 가 오늘 아무 일도 안 했다」고 말하면 안 됩니다. 정확한 표현은 **「빈 칸 채우기는 0건이었고, 덮어쓰기 차단 건수는 이 로그로는 셀 수 없다」** 입니다.

**추가로 확인한 것:** (E-prime) 를 만들게 한 원인 종목 3개(011090·014990·226340) 중 **오늘 W1 쓰기 대상이 된 종목은 하나도 없습니다.** 011090·014990 는 로그에 0회 등장했고, 226340 은 15:48 EOD 분봉 수집(다른 경로)에만 6회 나옵니다. 즉 **오늘은 규칙을 시험할 기회 자체가 없었던 날**입니다.
