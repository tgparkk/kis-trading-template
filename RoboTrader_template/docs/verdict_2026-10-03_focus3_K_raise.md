### 2-1. P1 — EOD 캡 포화율 < 50% → 🟢 성립

**SQL** — §④ P1 관측 지점 = 「§①-1 과 같은 SQL」. §①-1 의 출처(`scratchpad/eod_20260915/LANE_C_gate_guards.md` §3-b)에는 SQL 이 **「요지」로만** 있다(「`DISTINCT ON (trade_date, strategy) … ORDER BY updated_at DESC` 로 2차 스냅샷만 남기고, 전략별 K 를 VALUES 로 조인해 `n_open >= K` 인 거래일을 센다」). 아래는 그 요지를 그대로 옮긴 **재구성**이고, K 는 §④ P1 이 정한 새 값 10/6/10, 창은 P1 의 09-18~10-05 다.

```sql
WITH k(strategy, k) AS (
    VALUES ('book_pullback_ma20', 10),
           ('minervini_volume_dryup', 6),
           ('daytrading_3methods_breakout', 10)
),
eod AS (
    SELECT DISTINCT ON (trade_date, strategy) trade_date, strategy, n_open
    FROM paper_strategy_equity
    ORDER BY trade_date, strategy, updated_at DESC
)
SELECT e.strategy, k.k,
       COUNT(*)                                             AS n_days,
       SUM(CASE WHEN e.n_open >= k.k THEN 1 ELSE 0 END)     AS n_sat,
       ROUND(100.0 * SUM(CASE WHEN e.n_open >= k.k THEN 1 ELSE 0 END) / COUNT(*), 1) AS sat_pct
FROM eod e
JOIN k USING (strategy)
WHERE e.trade_date BETWEEN '2026-09-18' AND '2026-10-05'
GROUP BY 1, 2
ORDER BY 1;
```

### 2-6. P5 — 대조군 5전략 매수 패턴 변화 = 0 → ⚪ 판정 불가

**왜 판정 불가인가 — 사전등록 문언만으로 든 근거**
1. §④ P5 `:364` 의 예측 = 「포화율·일 매수 건수의 **분포가 발효 전후로 달라지지 않는다**」, §⑤-1 `:490` 의 반증 = 「5전략 매수 패턴이 **변했다**」. **얼마나 달라져야 「변했다」인지(문턱), 무엇으로 재는지(통계량), 발효 전 비교 창이 언제인지가 적혀 있지 않다.** P1 `< 50%` · P2 `≥1건` · P3 `−30%` · P4 `≥6건` · P6 `≥100` 은 숫자 문턱이 있다. (이 근거는 09-18 퀀트 패널 `:182` 근거 ① 「검정통계량·문턱·α 부재」와 **같은 논거**다 — §3-2.)
   - 🔑 **P4′ 와의 비대칭** — P4′ 도 숫자 문턱은 없다(패널 `:182` 「**P5·P4′ 만 없다**」). 그러나 P4′ 는 **통계량**(「3전략 합산 일평균 **매수** 건수」) · **비교 창**(「발효 **전 10거래일** 대비」) · **방향**(「**증가**」 + 「5 를 넘지 않는다」)을 문언에 지정했다(§④ `:363`). 그래서 일평균 두 개를 비교하는 것만으로 새 기준 없이 판정이 된다(§2-5). P5 는 「**분포**」라고만 하고 통계량(평균? 분산? 최대? 포화일?)·창·허용 폭이 없다 ⇒ 같은 방식으로 판정할 수 없다.

### ② daytrading P2 반증 → 「K=10 유지 · 10-06 재확인 · 10-17 결정」

- **10-06 보충 판정 SQL** — 사전등록 `:401-426` 개정 SQL 에서 **날짜 리터럴 2곳만** `'2026-10-05'` → `'2026-10-06'`(밴드·문턱·조인·전략 목록 불변). 판독은 `daytrading_3methods_breakout` 행만 — 6~10위 매수 ≥ 1건이면 보충 판정 성립, 0건이면 반증 유지. 10-06 매수의 순위는 scan_date 10-02 스냅샷(10-06 09:00 저장)이므로 10-06 장 마감 뒤 바로 실행할 수 있다.

```sql
-- 🔧 2026-09-17 개정 — 발효 후 신규 매수의 「스냅샷 순위」 분포
--    매수일 D ⇒ scan_date = D 의 직전 거래일(거래일 달력 = daily_prices 'KOSPI')
WITH td AS (
    SELECT date::date                           AS d,
           LAG(date::date) OVER (ORDER BY date) AS prev_d
    FROM daily_prices
    WHERE stock_code = 'KOSPI'
      AND date BETWEEN '2026-09-01' AND '2026-10-06'
)
SELECT v.strategy,
       s.rank_in_snapshot AS rk,
       COUNT(*)           AS n_buy
FROM virtual_trading_records v
JOIN td
  ON td.d = v.timestamp::date
JOIN screener_snapshots s
  ON s.strategy   = v.strategy
 AND s.stock_code = v.stock_code
 AND s.scan_date  = td.prev_d          -- 원문(결함): s.scan_date = v.timestamp::date
WHERE v.is_test = true
  AND v.action  = 'BUY'
  AND v.timestamp::date BETWEEN '2026-09-18' AND '2026-10-06'
  AND v.strategy IN ('book_pullback_ma20',
                     'minervini_volume_dryup',
                     'daytrading_3methods_breakout')
GROUP BY 1,2 ORDER BY 1,2;
```

- ⚠️ 10-06 실행 전 확인: `daily_prices` 에 `'KOSPI'` 10-06 행이 들어왔는지(없으면 `td` 조인이 10-06 매수를 떨어뜨린다) · 조인 커버리지(10-06 매수 전건에 순위가 붙는지 — §2-2 S2-b 와 같은 LEFT 조인).
- **주 판정과의 관계**: §0 의 P2 daytrading 판정(10-05 리터럴 창 · 반증)은 그대로 둔다. 10-06 결과는 **보충 판정**으로 그 옆에 적는다.
- **K=10 유지** — 10-06 결과와 무관하게 10-17 까지 유지. **원복 여부 = 10-17 안건** `docs/plan_2026-09-26_agenda_1017_limits_removal.md` §10-4 **Q9 「daytrading K 원복 검토」**(`research/candidate-ledger` 워크트리 v0.7 작업본 · 실전 cap·사이징과 함께).
