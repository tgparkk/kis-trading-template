**작성 2026-08-15 (동결 · 실행 전 커밋)**
선행: `backtest/concept_fidelity_audit/`(컨셉 충실도 감사) — 특히 §3-D(유니버스 97% 불일치)·§3-B(보유기간).
🔴 **라이브 8전략 이야기다.** 태쏘 연구와 무관하다.

> 🔴 **오염 고지 — 동결 전에 본 것.**
> ① 라이브 실측(2026-06~08): 보유 중앙 1~2일 · ≤1일 청산 43~69% · 손절 46~73% · deep_mr 월 18.9회
> ② `top_volume:50` 백테스트 실측: 보유 중앙 10~13일 · ≤1일 2~4% · 손절 25~43% · max_hold 24~49%
> ③ 유니버스 겹침: 라이브 매수 646건 중 `top_volume:50` 소속 17건(3%), 우연 기대치 7.2~10.2
> ④ deep_mr 매수의 39%만 `top_volume:300` 소속 ⇒ README 의 "top300 근사"가 성립 안 함
> **🔑 「라이브 유니버스로 돌린 백테스트」는 한 번도 돌리지 않았다.** 결과 변수는 이 문서 동결 후 처음 잰다.

## §0. 왜 재는가

감사 결과 하나로 요약된다: ***라이브 매수의 97%가 백테스트가 검증한 적 없는 종목이다.***
그러므로 README 의 평판 숫자(`Sharpe 1.55` · `+269%` · `MaxDD 20%` 등)는 **지금 도는 것을 설명하지 않는다.**

이 문서가 묻는 것은 하나다:
***같은 룰·같은 청산을, 라이브가 실제로 쓰는 유니버스에 적용하면 무엇이 나오는가?***

그리고 부수적으로, 감사가 남긴 미해결 질문에 답한다:
***라이브의 「하루 만에 손절」은 유니버스 때문인가, 아니면 실행 경로 때문인가?***

🔴 **판돈**: 이게 유니버스 때문이면 고칠 대상은 스크리너다. 실행 경로 때문이면 스크리너를 고쳐도 안 바뀐다.
***두 처방이 정반대이므로 갈라놓지 않으면 아무것도 못 고친다.***

## §1. 대상 전략 (동결) — 8개 중 3개만

| 전략 | 라이브 `base_filter` | 시총 **컷** 사용 | 채택 |
|---|---|---|---|
| `book_envelope_200d` | 거래대금 ≥ 10억 | 없음 | ✅ |
| `rs_leader` | 거래대금 ≥ 10억 + 주가 1천~50만원 | 없음 | ✅ |
| `deep_mr_dev20` | 거래대금 ≥ 100억 | 없음 | ✅ |
| `elder_ema_pullback` | 시총 ≥ 5천억 | **있음** | ❌ 제외 |
| `daytrading_3methods_breakout` | 시총 < 5천억 | **있음** | ❌ 제외 |
| `minervini_volume_dryup` | 시총 ≥ 3천억 | **있음** | ❌ 제외 |
| `book_pullback_ma20` · `book_pullback_ma5` | 시총 ≤ 3조 | **있음** | ❌ 제외 |

**제외 사유**: 과거 시점의 시총을 신뢰할 수 없다. `daily_prices.market_cap` 커버리지 실측 =
2021년 **83.7%** · 2022 **85.5%** · 2023 **82.2%** · 2024 **93.6%** · 2025 **99.7%** · 2026 **99.6%**.
게다가 이 프로젝트의 시총 백필 검증(v2)은 **G1·G2 FAIL 로 폐기**됐고 v3 는 미착수다.
⇒ ***검증 안 된 유니버스 위에 검증을 쌓지 않는다.*** 5전략은 **v3 완료 후 별건**으로 미룬다.

### 🔴 채택 3전략도 시총과 완전히 무관하지는 않다 (동결 전 확인)

`QuantDailyReader.get_universe_snapshot` 은 스냅샷 단계에서 **`market_cap IS NOT NULL` 행만** 반환한다
(운영 부분적재일·지수 유사행 배제 목적). ⇒ 세 전략이 시총 **컷**을 안 써도 **유니버스 «소속» 자격**은
시총 존재에 걸린다. 위 커버리지대로면 **2021~2024 에 유니버스가 6~18% 좁아진다.**

- ⚠️ 이건 **결측 방향이 무작위가 아닐 수 있다**(오래된·소형 종목에 결측이 몰릴 개연).
- ⇒ **모든 결과표에 「그 해 유니버스 크기」를 함께 인쇄한다.** 숨기지 않는다.
- ⇒ 🔴 **연도별 성과 비교는 하지 않는다.** 유니버스 크기가 연도마다 달라 교란된다.

## §2. 처치 — 무엇을 바꾸고 무엇을 고정하는가

**고정**: 진입 룰 · 청산 파라미터(라이브 `config.yaml` 값) · 백테스터(`backtest/book_backtester.py`,
종목당 단일 포지션 순차 · 신호 다음봉 시가 체결 · 슬리피지 동일) · 기간.
**변경**: 유니버스 **하나만**.

| Arm | 유니버스 | 일별 후보 상한 | 의미 |
|---|---|---|---|
| **A** | `top_volume:50` (기간 전체 `SUM(close*volume)` 상위 50, 정적) | 없음 | **기준 셀** — 기존 검증 재현 |
| **B** | 라이브 PIT 스냅샷 + `base_filter` | 없음 | 유니버스 «넓이»만 바꾼 것 |
| **C** | 라이브 PIT 스냅샷 + `base_filter` | **top 10 / 일** (score 내림차순) | **라이브 재현** |

🔑 **A→B 는 「유니버스 넓이」를, B→C 는 「일별 후보 상한」을 분리한다.** 한 번에 둘을 바꾸면 귀속이 안 된다.
***감사에서 이미 한 번 이 실수를 했다*** — 백테스트 드라이버를 안 보고 라이브만 봐서 #5 를 오판했다.

**score 함수는 라이브 스크리너와 동일**(코드 재사용, 재구현 금지):
`envelope` = 당일 `close×volume` · `rs_leader` = 120일 수익률 · `deep_mr` = |MA20 이탈 깊이|.

**기준 셀 검증 (게이트)**: Arm A 는 저장된 산출물과 **거래 수가 일치**해야 한다.
불일치하면 ***재현이 깨진 것이므로 B·C 결과를 해석하지 않고 중단한다.***
(⚠️ `envelope` 은 라이브 config 일치 산출물을 `reports/` 에서 못 찾았다 → **A 를 새로 돌려 기준선을 만든다.**
그 경우 「저장본 대조」 게이트는 성립하지 않으므로 **그 사실을 결과에 명시**한다.)

## §3. 기간 (동결)

| 창 | 구간 | 용도 |
|---|---|---|
| **W-long** | 2021-01-01 ~ 2026-05-31 | **성과**(P1). 라이브 구간을 빼서 표본 외로 유지 |
| **W-live** | 2026-06-01 ~ 2026-08-14 | **거동 재현**(P2·P3). 라이브와 **같은 국면** |

🔑 거동 재현을 라이브와 **같은 국면**에서 재는 것이 핵심이다. 국면이 다르면 보유기간 차이를
유니버스에 귀속할 수 없다.

## §4. 결과 변수 (동결)

거래 단위(매수-매도 짝). **gross**, 슬리피지는 백테스터 기본값 그대로 양쪽 arm 동일.

1. **거래당 수익률** — 평균·중앙
2. **보유기간(거래일)** = `sell.idx − buy.idx` · 중앙 · **≤1일 비중**
3. **청산사유 비중** — 손절 / 익절 / max_hold / 기타
4. **발사 빈도** — 월평균 매수 건수
5. **유니버스 크기** — 연도별(§1 단서)

## §5. 예측 (동결)

**효과크기 문턱을 여기서 못박는다.** 문턱 미달이면 「차이 없음」으로 쓴다.

- **P1 (주 · 성과, W-long)**: Arm C 의 **거래당 평균 수익률**이 Arm A 보다 낮다.
  **문턱 = 1.0%p 이상 낮음.** 3전략 중 **2개 이상**에서 성립해야 P1 지지.
- **P2 (거동, W-live)**: Arm C 의 **≤1일 청산 비중**이 Arm A 보다 높고, 라이브 실측(43~69%) 쪽으로 이동한다.
  **문턱 = 15%p 이상 증가.** 3전략 중 **2개 이상**.
- **P3 (🔑 반증축 · 필수)**: **P2 가 «성립하지 않으면»** — 즉 라이브 유니버스로 돌려도
  보유기간이 Arm A 와 비슷하면(≤1일 비중 차 15%p 미만) — ***짧은 보유의 원인은 유니버스가 아니다.***
  그때 결론은 **「원인은 라이브 실행 경로에 있다」**이고, 그게 다음 연구의 표적이 된다.
  🔴 ***이 경우 P1 이 성립하더라도 「유니버스가 문제다」라고 쓰지 않는다.***
- **P4 (deep_mr 특정, W-live)**: Arm C 의 `deep_mr_dev20` 월 발사 빈도가 게이트 검증치 **월 6.0회**의
  **2.0배 이상**. 성립하면 「라이브 스크리너의 top300 근사 실패」가 확인된다(감사 #3).

### 판정 규칙 (동결)

| 결론 | 조건 |
|---|---|
| **유니버스가 원인이다** | P1 ✅ **그리고** P2 ✅ |
| **유니버스는 성과만 설명한다** | P1 ✅ · P2 ❌ → 거동 원인은 실행 경로(P3) |
| **유니버스는 원인이 아니다** | P1 ❌ · P2 ❌ |
| **판별 불가** | P1 ❌ · P2 ✅ (성과는 같은데 거동만 다름 — 설명 필요) |

🔴 **어떤 결과가 나오든 문턱·창·arm 정의를 갈아끼우지 않는다.** 「판별 불가」가 나오면 그대로 보고한다.

## §6. 🔴 생존편향 — 방향을 «미리» 못박는다

실측: 2021Q1 에 있던 **2,055종목** 중 2026-07 이전에 시세가 끊긴 것은 **10종목(0.5%)**뿐이다.
5.5년간 실제 KRX 상폐는 이보다 훨씬 많다 ⇒ ***`daily_prices` 에는 사실상 생존 종목만 있다.***

🔑🔑 **그리고 이 편향은 Arm 마다 «크기가 다르다».** `top_volume:50`(대형)은 상폐가 거의 없지만
라이브 유니버스(중소형 포함)는 상폐율이 훨씬 높다 ⇒ ***편향은 Arm B·C 를 «위로» 더 많이 민다.***

**따라서 추론이 한 방향으로만 유효하다 — 이걸 결과 보기 전에 확정한다:**

| 결과 | 읽는 법 |
|---|---|
| Arm C < Arm A (**P1 성립**) | 🟢 **강한 결론.** 편향이 C 를 «도와주는데도» 더 나빴다 = 보수적 |
| Arm C ≥ Arm A (**P1 불성립**) | 🔴 **결론 없음.** 생존편향만으로 설명 가능하다. ***「라이브 유니버스가 더 낫다」고 쓰지 않는다.*** |

## §7. 🔴 미리 적어두는 한계

1. 🔴 **생존편향 비대칭** (§6). 이 연구는 **「나쁘다」만 증명할 수 있고 「좋다」는 증명할 수 없다.**
2. 🔴 **유니버스 소속이 시총 «존재»에 걸린다** (§1). 2021~2024 유니버스가 6~18% 좁고, 결측이 무작위라는 보장이 없다.
3. 🔴 **포트폴리오가 아니다.** 백테스터는 종목당 단일 포지션 순차이고 라이브는 K 슬롯이다.
   ⇒ ***거래 «당» 분포만 비교 가능하고 총수익·Sharpe·MaxDD 는 라이브와 대조할 수 없다.***
   Arm 간 비교에는 유효하다(양쪽 동일 백테스터).
4. 🔴 **`top_volume:50` 자체가 룩어헤드다** — 기간 전체 거래대금으로 뽑은 정적 집합.
   ⇒ Arm A 는 「정답」이 아니라 **「기존에 검증했다고 믿었던 것」**일 뿐이다.
5. 🔴 **W-live 는 n 이 작다**(2.4개월, 전략당 수십 건). 거동 분포는 볼 수 있어도 성과는 못 본다
   — 그래서 P1 을 W-long 에, P2 를 W-live 에 나눠 걸었다.
6. 🔴 **라이브 전용 상한(`entry_max = 어제종가×1.03`)은 재현하지 않는다.** 백테스터에 없는 제약이고,
   라이브에서 얼마나 발동하는지 **로그에 0회라 미측정**이다. ⇒ Arm C 도 이 점에서 라이브와 다르다.
7. 🔴 **regime gate·급락게이트·자금 제약·중복 보유 제한을 재현하지 않는다.** 유니버스 축 하나만 본다.
8. ⚠️ **`reports/` 저장 산출물에 지수 의사티커가 0.1~3.0% 섞여 있다**(2026-05-31 생성, `SQL_STOCK_ONLY` 이전).
   Arm A 를 새로 돌리면 이 오염은 사라지므로 ***저장본과의 거래 수 대조에 미세한 불일치가 정상 범위로 생긴다.***
   기준 셀 게이트는 **±3% 이내**를 허용으로 미리 고정한다.
