## §1. 재무 정의 — 판정된 것을 «한 글자도» 바꾸지 않는다

### 1-1. 이진 `F` — 문서 1 §2-2 그대로 전재

```
F(code, D) = TRUE  ⟺
   1) rcept_dt(code, y) ≤ D − 1 인 사업연도 중 «가장 최근» y 를 «하나» 고른다.   ← 선택은 여기서 끝
   2) 그 y 하나에 대해서만 판정한다. 실패하면 F = FALSE (다른 해를 찾지 않는다).
        ② rcept_dt(code, y−1) ≤ D − 1
        ③ operating_income(code, y−1) > 0            (원저작: 흑자 기업만)
        ④ operating_income(code, y) ≥ 1.25 × operating_income(code, y−1)
   rcept_dt NULL = 「그 해 데이터 없음」 = fail-closed (통과시키지 않는다)
```
구현 정본 `backtest/concept_axes/minervini/run.py:292-317`(`f_screen`) · **사유 코드 6종 그대로 계승**
(`no_rows`·`no_visible_year`·`prev_year_invisible`·`oi_missing`·`prev_oi_nonpositive`·`growth_below_25pct`).
🔴 **문턱 25% 를 건드리지 않는다.**

🟢 **정의 재현 검증(2026-09-11)**: 같은 SQL 이 `F1` §0-3 ①(minervini 후보 64 · `F` 19 · 12거래일)과
top-3 교체 **7/34 = 20.59%(6/12일)** 를 **정확히 재현**했다. ⇒ §0-3 의 daytrading 수치는 「같은 자」로 잰 값이다.

**사유 코드 분포(daytrading 후보 232건 · 2026-08-25~09-10 · 인쇄만)**: `growth_below_25pct` 86 ·
`prev_oi_nonpositive` **85** · `no_rows` 7 · `prev_year_invisible` 7 · `no_visible_year` 1 · `oi_missing` **0** · `pass` 46.
🔴 ***`prev_oi_nonpositive`(전년 영업이익 ≤ 0)가 36.6% 로 세 전략 중 가장 높다*** (ma20 27.7% · minervini 5.8%).
**후보 모집단이 다르다** — daytrading 의 `base_filter` 는 **시총 5천억 «미만»**(`screener.py:23`)이라 가장 작은 회사들을 본다.
⇒ 판정문에 병기: ***이 축에서 `F` 는 「성장」보다 「흑자인가」를 먼저 가르고 있다.***

### 1-2. 순위용 «연속값» — **V1(이진 `F` 그대로) 채택**
`F1` §1-2 승계(V2 `g=YoY` · V3 백분위는 판정된 적 없는 함수라 기각).
🔴 **daytrading 고유 주의**: `prev_oi_nonpositive` 가 36.6% 라 **V2 는 정의 자체가 안 되는 종목이 3분의 1**이다 ⇒ V2/V3 는 여기서 더 나쁘다.

### 1-3. NULL(판정 불가) 처리 — **N1(`F=0` 과 같은 칸) 채택**
`F1` §1-3 그대로. 로그·게이트에서는 **따로 센다**.
🔴 단서: 순위에서 fail-closed 는 *「모르면 뒤로」*이고 ***후보가 K 보다 적은 날에는 여전히 산다.***
daytrading 실측: 상위 20 안 후보가 **K=5 미만인 날 0일**(최소 14건) ⇒ 🟢 「뒤로 밀면 실제로 안 산다」가 12/12 일 성립.

### 1-4. 가산 «방식» — **A(사전순 `(F, score)`) 채택**
`F1` §1-4 승계(가중합·백분위합 기각).
🔴🔴 **`score` 가 다른 함수다 — 이 문서 고유의 경고.**
minervini·ma20 의 `score` 는 **거래량 평균**(`volume.iloc[-20:].mean()`)인데
daytrading 의 `score` 는 **거래량 «비율»** `last_vol / mean(volume[-21:-1])`(`daytrading_3methods_breakout/screener.py:51-53`)이다.
⇒ ① 척도가 다르므로 **가중합(B)은 여기서 더 위험**하다(사전순 A 가 더 정당해진다)
② 🔴 ***이 `score` 는 진입 룰과 «같은 양»이다*** — 룰이 `vol_ratio ≥ 2.0` 을 요구하고 랭킹이 그 `vol_ratio` 로 줄을 세운다.
즉 **랭킹이 「룰을 얼마나 세게 통과했나」**다. ma20·minervini 의 「유동성 큰 쪽 우선」과 성격이 다르다. **판정문에 병기.**
③ ma20 랭킹은 (나) 로 판정났지만 **daytrading 랭킹은 판정된 적이 없다**(`docs/ma20_daytrade_3축_쉬운설명_2026-08-23.md` 는 두 전략을 다루나 판정은 ma20 축) ⇒
***「정보가 아닌 것을 고정하니 arm 차이에 기여하지 않는다」는 `F1` 의 논거를 이 문서는 «쓸 수 없다».*** 대신 **「현행 그대로 고정한다」**로만 정당화한다.

### 2-2. 🔴🔴 절단 지점 — 라이브는 «3단»이다

`F1` §2-2 의 유도(백테스터가 선택을 `set` 으로 접어 **순서를 잃는다** — `minervini/run.py:761` · `ma5/run.py:810`
`allowed = {d: set(v) …}` ⇒ ***순위의 효과는 절단 경계에서만 난다***)를 승계한다. daytrading 의 절단은 셋이다:

| 층 | 상한 | 근거 | 관측 12거래일 실측 |
|---|---|---|---|
| **스냅샷 생성** | **20** | `config/constants.py:200` → `bot/liquidation_handler.py:613` | 🟡 **4/12 일 포화** |
| **라이브 소비** | **10** | `config/trading_config.json:29` `max_candidates: 10` → `bot/candidate_loader.py:63-72` → `core/candidate_selector.py:1036` → `_filter_unsafe_stocks(pool, limit=10)`(`:1125`) | 🔴 **12/12 일 걸린다**(후보가 매일 ≥14) |
| **동시 보유** | **5** | `config.yaml` `max_positions: 5` → `strategy.py:79,134` | 🔴 걸린다 |

⇒ **확정: arm 은 «3단 합성»이다** (`F2` §2-2 와 동일 형식):
```
①  그날 트리거 전량 → 현행 score 내림차순 top-20        ← 두 arm «공통»
②  그 20 을  기준선: score 순 / F-arm: (F, score) 순    ← 여기서 갈린다
③  ②의 순서로 상위 5                                     ← 실현되는 절단
```
②③은 **「상위 20 안에서 `(F, score)` 상위 5」**로 접힌다(안정정렬).
🔴 **①을 arm 공통으로 두는 것이 핵심** — ①에 `F` 를 넣으면 포화일(4/12)에 **후보 집합이 바뀌어** §0-2 의 전제가 깨진다.

🔴 **daytrading 고유의 네 번째 제약 — `max_hold 10거래일`.**
minervini 20 · ma20 50 과 달리 daytrading 은 **10거래일**이라 슬롯 회전이 빠르다 ⇒ **「누적 보유가 슬롯을 먹어 순위가 무의미해지는」 정도가 셋 중 가장 작다.**
🟢 순위 층이 실제로 일할 여지는 **daytrading 이 가장 크다.** (실측이 아니라 산술이다 — G8 이 잰다.)

**안 재는 것(인쇄로 남긴다)**: 안전성 필터 **지연 절단**(거래정지·VI·관리종목이 11위 이하를 승격) · **급락게이트**(§6-9) · 진입 밴드. ***셋 다 백테스터에 없다.***

### 2-3. 🔴 희석 — `ε = 0.5%p` 가 arm 수준에서 뜻하는 것

```
arm 수준 차이  ≈  (교체 슬롯 비율) × (교체 종목이 교체 대상을 이긴 폭)
0.5%p          ≈  0.4833 × delta      ⇒   delta ≥ 1.03%p
```
🟢 `F1`(2.43%p) 보다 낫고 `F2`(0.86%p) 보다 나쁘다.
🔴 그러나 **자문 §2 의 daytrading 기대치는 0~+0.2%p** 로 `delta` 가 1%p 를 넘을 근거가 «없다».
⇒ ***이 설계는 검정력이 없을 가능성이 «매우» 높고, 그건 설계 결함이 아니라 이 축의 성질이다.***
그 경우 라벨은 **(마-R3) 구별 불가**가 되고 발효는 **「채택」으로만** 가능하다.

**보조 추정량(인쇄만 · 판정 언어 금지)**: `delta_hat = mean(codes_in) − mean(codes_out)`.

산출물 = `daytrading/GATE_FUND.md`. **여기 인쇄되는 값 중 어느 것도 arm·ε·문턱을 바꾸는 근거가 될 수 없다.**

### 2-5. 판정 (동결 예정)

`ε = 0.5%p` 고정. **결과를 보고 바꾸지 않는다.**
**N1(귀무)**: `#{ R_B5,i ≥ arm } ≤ 4` — **100 시드 중 96 이상**. `p = (1 + #{R ≥ arm})/101` ⇒ N1 성립 시 `p ≤ .0495`.
주 검정 **m=1** ⇒ Holm 1단계 `.05` 에 최소 p `.0099` 도달 가능. `S ≥ 20m−1 = 19` ≤ 100 ✅.

| 라벨 (사전 고정) | 조건 |
|---|---|
| **(가-R3) daytrading 에서도 재무는 순위 층에서 정보다** | `B5+F − B5 ≥ ε` ∧ N1(`B5+F`) ∧ G2a 통과 ∧ 총량 ≥ +10% |
| **(다-R3) 순위 층에서는 해롭다** | `B5 − B5+F ≥ ε` ∧ N1(`B5`) |
| **(나-R3) 순위 층에서 정보가 아니다** | N1(`B5+F`) 불성립 |
| **(마-R3) 구별 불가** | `abs(B5+F − B5) < ε` |

- 🔴 **MDE 를 §2 확정 «직후» 계산해 인쇄.** 쌍대 표준오차(두 arm 이 슬롯의 약 52% 를 공유). **`MDE > ε` 이면 「검정력 없음」 병기.**
- **「없다」 선언은** G2a 통과 ∧ 점추정 `< ε` ∧ `MDE ≤ ε` 일 때만. **그 밖은 전부 「모른다」.**
- 🔴 **기준선 `B5` 도 같은 N1 검정을 받는다.** 못 넘으면 ***현행 라이브 상위 5종목 고르기가 무작위 5개와 구별되지 않는다***는 뜻이고
  **그것 자체가 이 문서의 가장 중요한 결과**다. ⚠️ 계열 관측상 **기준선이 귀무를 못 넘은 일이 다섯 번** 났다.
  🔴 그리고 daytrading 은 자기 소개에 *「탐색·관찰용(약한 Sharpe)」*이라고 적혀 있다(`config.yaml:8`) — **못 넘을 확률이 셋 중 가장 높다.**

### 2-6. 다중검정
주 검정 **1개**(§0-4 (b) 를 고르면 **0개**). 등록부 총계 제안: 6 → `F1` 7 → `F2` 8 → **이 문서 9**
(`1 − 0.95^9 = 0.3698` ⇒ **37.0%**). 🔴 **실행 «전»에 동결과 같은 커밋에서 갱신한다.**
⚠️ 「실행된 N1」 누계(≥23)에 **이 문서가 돌린 arm 2개**를 더한다.

③ **원저작(유지윤 3대 타법)에 재무 조건이 없다** — 이 축은 원저작 유도가 아니다.
④ **`score` 가 룰과 같은 축**이라 `F` 로 줄을 바꾸면 **「룰을 덜 세게 통과한 종목」을 앞으로 당기는** 효과가 섞인다(§1-4 ② · G11 이 잰다) — 부호를 밀 이유가 못 된다.

**P3 의 반대 근거(같은 무게로 적는다)**: ① 🔴 문서 1 의 `(가-F)` 가 **전략과 무관한 유니버스 효과**였다면 여기에도 옮겨온다
(REGISTRY: *「일하고 있는 것이 컷이고 그 위에 얹은 룰이 아니다」*). ② **생존편향이 + 쪽**으로 민다(자문 §6 B).
③ **`prev_oi_nonpositive` 36.6%** — 이 유니버스에는 **적자 기업이 유난히 많다.** 자문의 *「재무가 막는 건 망하는 회사」* 논거가
**셋 중 여기서 가장 잘 들어맞을 수 있다**(단 그건 «꼬리» 효과라 «평균» 수익률로는 안 보인다 — 자문 §5 컷 축).
🔴 순위 층에서 생존편향 논증은 두 arm 에 거의 대칭이라 약하다.

**실패 조건(중단하고 보고)**: G1 위반 · G5 위반 · `F` 판정 불가 비율이 어느 해에서 50% 초과.

### 4-2. 계기 — 하루 1줄(전략당) + 기동 1줄 + 기록 표 1행/종목

```
[fund-rank] mode=shadow strategy=daytrading_3methods_breakout trade_date=2026-09-29
            snapshot=20 consumed=10 K=5 free_slots=3
            with_f=4 f0=15 null=1 src=asfiled src_max_rcept=2026-08-06
            reorder_topK=2 in=005930,000660 out=111111,222222
            old=A,B,C,D,E new=C,A,B,F,D  sector_news_mode=shadow
[fund-rank] mode=shadow strategy=daytrading_3methods_breakout (startup)
```

| 칸 | 뜻 | 왜 «따로» 찍나 |
|---|---|---|
| `snapshot`/`consumed`/`K` | 세 절단 | 🔴 절단이 셋이라 **어디서 갈렸는지**가 사후 재현의 전부 |

| `with_f`/`f0`/`null` | `F=1` / `F=0`(판정됨) / 판정 불가 | 셋을 접으면 **배관 고장이 「그냥 0건」처럼 보인다** |
| `src`·`src_max_rcept` | 원장과 최신 접수일 | **원장이 썩는 것을 소리나게 만든다**(관문 S2) |
| `reorder_topK`·`in=`·`out=` | 교체 종목 수와 코드 | EOD 점검은 **집합 차분**으로 돈다 |
| `old=`·`new=` | 두 순서 모두 | 사후 재현 |
| `sector_news_mode` | 같은 자리 다른 층의 모드 | **2층 충돌을 매일 보이게** |

- **기동 줄** 없으면 「스위치 off」와 「안 돌았다」가 구별 안 된다(rs_leader errata E4 승계).
