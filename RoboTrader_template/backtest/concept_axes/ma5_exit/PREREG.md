## §0. 왜 재는가 — 같은 문제에 대한 «정반대» 두 처방

현행 `ma5` 는 **익절 도달이 16%뿐**이다. 여기에 고전적인 두 답이 있고, 사장님이 둘 다 짚으셨다.

| | 처방 | 지시 |
|---|---|---|
| **고정 %** | 목표를 **가깝게** — 자주 이기고 조금 먹는다 | ① 10/5 · 12/6 |
| **기준선** | 목표를 **없앤다** — 추세가 살아 있는 한 들고 간다 | ②③ 선 이탈로 판다 |

🔑 ***둘은 서로의 반증축이다.*** 한 문서에 대칭으로 넣으면 어느 쪽이 나와도 뜻이 있고,
**둘 다 지면 「청산 축은 답이 아니다」가 확정**되어 종목 선택 축으로 돌아갈 근거가 된다.

🔴 **이 문서는 08-16 에 폐기된 「트랙 A」와 다르다.** 트랙 A 는 *「손절 건만 골라 대안 청산을 적용」*
이라 **표본 정의에서 부호가 이미 결정**돼 있었다. 이 문서는 **청산 규칙을 통째로 갈고 전체를
다시 돌린다** — 조건부 표본이 아니다.

## §1. 대상 (동결)

`book_pullback_ma5` **하나만.** 진입 룰은 **현행 그대로 고정**한다 —
「급등」의 방향 실험은 자매 문서 [`../ma5/`](../ma5/PREREG.md) 의 몫이다.
🔴 ***진입과 청산을 같이 움직이면 차이의 출처가 갈리지 않는다.***

## §2. Arm (동결) — 청산 축 «하나»만 바꾼다

**고정**: 진입 룰 `rule_ma5_pullback` 현행 · `base_filter`(시총 ≤3조 · 거래대금 ≥10억) ·
**`score` = 현행 `df["volume"].iloc[-5:].mean()`** · `max_candidates = 10` · **`max_hold = 30거래일`
전 arm 공통** · 창 · 룰 창 60봉 · 백테스터(`BookBacktester`, `eod_liquidate=False`).

### 2-1. Arm 표 (동결)

| 계열 | Arm | 청산 규칙 (`max_hold 30` 은 전 arm 공통) | 출처 |
|---|---|---|---|
| **FIXED** | **X0** | `ret ≤ −3%` → 손절 · `ret ≥ +15%` → 익절 | **현행 라이브 (기준선)** |
| **FIXED** | X1 | `ret ≤ −5%` · `ret ≥ +10%` | 사장님 ① |
| **FIXED** | X2 | `ret ≤ −6%` · `ret ≥ +12%` | 사장님 ① |
| **LINE** | L5 | `close < SMA5` **OR** `ret ≤ −10%` | ma5 원저작 (`trail_ma 5`) |
| **LINE** | L10 | `close < SMA10` **OR** `ret ≤ −10%` | 라이브 실재 (`rule_daily_ma5_10_follow`) |
| **LINE** | L20 | `close < SMA20` **OR** `ret ≤ −10%` | ma20 원저작 (`trail_ma 20`) |
| **LINE** | L60 | `close < SMA60` **OR** `ret ≤ −10%` | `rs_leader` 라이브 실재 |
| **LINE** | LE13 | `close < EMA13` **OR** `ret ≤ −10%` | `elder` 라이브 실재 |
| **LINE** | LE65 | `close < EMA65` **OR** `ret ≤ −10%` | `elder` 라이브 실재 |
| 🔑 **귀무** | **R_exit** | **무작위 청산** — 진입 후 `U{1..30}` 거래일에 청산, 시드 `0..19` | **§5-2 의 귀무** |
| 참조 | R_sel | X0 청산 · 종목만 **무작위**, 시드 `0..19` | 인쇄만 (sanity) |

- **arm 은 실험 9개(FIXED 3 + LINE 6) + 귀무 `R_exit` + 참조 `R_sel` 뿐이다.**
  선 추가·문턱 스윕·조합(선 ∧ 익절) 전부 금지(§8).
- 🔑 **선 6개는 «이 저장소의 라이브 전략들이 이미 쓰는 선 전부»다.** 데이터를 보고 뽑지 않았다.
- **LINE 계열엔 익절이 «없다»** — 사장님 ③ *「손절도 선 이탈로」* 를 그대로 옮긴 것이다.
- **`−10%` 마지노선**(사장님 ④)은 **LINE 계열에만** 붙는다. FIXED 계열은 손절이 이미 그보다
  타이트(−3 / −5 / −6%)해서 발동할 수 없다.
- 진입이 전 arm 동일하므로 **arm 마다 「같은 거래」를 다르게 판 것**이다(§7-6 단서 참조).

### 2-2. 청산 판정 시점과 체결 (동결)

`BookBacktester` 승계 — **확정 일봉 종가로 판정하고 «다음 봉 시가»에 체결**한다
(`book_backtester.py:118` `fill = bar_next["open"] × (1 − slippage)`).
이동평균은 이미 있는 `window = df.iloc[: i+1]` 로 계산한다(추가 데이터 불필요).

🔴 **이 구조는 라이브의 장중 whipsaw 를 «재현하지 못한다»** — §7-1 에 한계로 적는다.

### 2-3. 우선순위 (동결) — 한 봉에서 둘 이상 성립할 때

```
FIXED : 손절 → 익절 → max_hold          (현행 book_backtester 순서 그대로)
LINE  : 마지노선(−10%) → 선 이탈 → max_hold
```
🔑 **마지노선을 «먼저» 둔다** — 안전장치는 다른 규칙보다 앞선다는 뜻이고, 이렇게 해야
§6-4 의 「마지노선 발동 비율」이 상한이 아니라 실제 발동 횟수가 된다.

## §3. 창과 **홀드아웃** (동결)

창 = **2024-03-13 ~ 2026-05-31**. 가격 로더 `HIST0 = 2021-01-01`. 룰 창 **60봉**(자매 문서 §3-1 승계).
🔴 라이브 페이퍼 구간(2026-06-01~08-14)은 결과 변수에 **넣지 않는다.**

### 3-1. 🔑🔑 종목 홀드아웃 — 사후 선택을 «사전에» 합법화한다

```python
half = int(hashlib.md5(stock_code.encode("utf-8")).hexdigest(), 16) % 2
A반 = (half == 0)   # 탐색·판정
B반 = (half == 1)   # 🔴 봉인
```

- **§4~§6 의 모든 산출은 A반에서만 한다.** 판정도 A반으로 내린다.
- 🔴 **B반은 §10 프로토콜에 따라 «단 한 번»만 연다.** 두 번 열면 홀드아웃이 아니다.
- **종목으로 가르는 이유**: 기간으로 가르면 *「그땐 장이 달랐다」* 는 변명이 남는다.
  종목 분할은 **두 반이 같은 국면을 겪으므로** 그 변명이 성립하지 않는다.
- **md5 를 쓰는 이유**: 종목코드 순서·시장·상장시기와 무관한 결정적 분할이 필요하다.
  코드 정렬 홀짝은 상장 순서와 상관될 수 있다.
- ⚠️ **A반 표본이 절반이 된다.** §6-1 문턱 판정은 A반 기준으로 한다.

## §4. 결과 변수 (동결)

**주 = 거래당 평균 수익률**(gross — 슬리피지 편도 0.1% 반영 · 수수료/거래세 미반영, 승계 원본과 동일).
보조(인쇄만) = 중앙 · 승률 · 거래수 · 보유 중앙 · **청산사유 비중** · **최악 손실 분포**
(최소 · 1% · 5% 분위) · 중앙 주가/시총/거래대금.

## §5. 예측과 판정 (동결)

`ε = 0.5%p` (왕복 비용 0.21%p 의 2.4배). **결과를 보고 바꾸지 않는다.**

### 5-1. 🔑🔑 귀무 — 이 문서는 앞선 두 문서와 «다른» 귀무를 쓴다

🔑 ***진입이 전 arm 동일하므로 「무작위로 «종목» 고르기」는 이 문서의 귀무가 될 수 없다.***
그건 선택 축의 귀무이고, 이 문서가 묻는 것은 **청산**이다. 종목 귀무를 쓰면
`L20 − R` 이 「청산 때문인지 종목 선택 때문인지」 갈리지 않는다 —
***이 저장소가 반복해서 밟은 「귀무가 질문과 안 맞는」 형태다.***

**`N1` (동결)** = 그 arm 이 **`R_exit` 20개 «전부»보다 큰가** (단측 순열검정 p = 1/21 ≈ 0.0476).

**`R_exit`** = 현행 진입·현행 종목 선택은 그대로 두고 **청산만 무작위**로 한다 —
진입 후 `U{1, …, 30}` 거래일째 종가에 청산 신호(체결은 다음 봉 시가, 전 arm 공통).
시드 `0..19`. 🔑 ***「청산 규칙이 정보인가」의 정확한 귀무는 「아무 날에나 파는 것」이다.***

🔴 **`X0`(현행)도 같은 검정을 받는다.** X0 가 N1 을 통과 못 하면
***현행 청산 규칙(−3%/+15%)이 이미 「무작위 날에 파는 것」과 구별되지 않는다*** 는 뜻이고,
**그것 자체가 이 문서의 가장 중요한 결과**다. 눈에 띄게 인쇄한다.
(⚠️ 앞선 두 문서에서 기준선이 귀무를 못 넘는 일이 **이미 두 번** 나왔다 —
`rank_score` 의 `V`, `minervini` 의 `D`.)

**`R_sel`**(무작위 종목 + X0 청산)은 **인쇄만** 한다 — 「전략 전체가 무작위 종목보다 나은가」라는
별개 질문의 sanity 값이고 **§5-2 판정에 쓰지 않는다.**

N1 은 전 arm 에 대해 계산·인쇄하되 **판정에 쓰는 것은 §5-2 가 지정한 계열뿐**이다.

⚠️ **`R_exit` 는 `max_hold 30` 과 상한이 같다** — 즉 무작위 청산은 「30거래일 안에 아무 날」이고,
`max_hold` 만 켠 arm 의 특수 경우가 아니다(그건 항상 30일째). 이 구분을 결과 문서에 적는다.

### 5-2. 주 판정 — 🔴 **주 검정은 이것 «하나»뿐이다**

***「어느 선이 제일 좋은가」를 묻지 않는다.*** 그건 1등을 고르는 일이고 사후적합이다.
대신 **계열 «전체»에게 묻는다.**

```
LINE  = { L5, L10, L20, L60, LE13, LE65 }
FIXED = { X0, X1, X2 }
```

**판정 순서 (동결 — 위에서부터 처음 성립하는 것을 채택):**

| 순서 | 조건 | 결론 |
|---|---|---|
| 1 | `min(LINE) − max(FIXED) ≥ ε` **그리고** LINE 전 arm 이 N1 성립 | 🟢 **(가) 기준선 «방식»이 낫다** — *가장 나쁜 선조차 가장 좋은 고정%보다 낫다* |
| 2 | `min(FIXED) − max(LINE) ≥ ε` **그리고** FIXED 전 arm 이 N1 성립 | **(다) 고정 % «방식»이 낫다** |
| 3 | (그 외) | 🔴 **(나) 「방식」이 아니라 «설정»이 결과를 지배한다** — 두 계열이 겹친다 |

🔑 **1·2 는 문턱이 매우 높다.** 통과하면 ***어느 선/설정을 골랐든 상관없다***는 뜻이라
**선택 문제가 원리적으로 사라진다.** 무작위 arm 에 쓰는 *「20개 시드 «전부»를 이겨야 한다」*
와 같은 논리다.

🔴 **(나) 는 실패가 아니다.** *「이 전략의 성적은 청산 튜닝의 산물이다」* 라는 결론이고,
그때 §10 홀드아웃 프로토콜이 발동한다.

⚠️ **세 라벨은 상호배타적이고 전부를 덮는다. 결과가 어느 쪽이든 새 라벨을 짓지 않는다.**

### 5-3. 전 arm 표 — 🔴 **탐색 지도 (인쇄만 · 판정 언어 금지)**

10개 arm 전부의 §4 지표를 한 표로 인쇄한다. **이 표를 보고 arm 을 «채택»하지 않는다**(§8-4).
REGISTRY 규칙 4 에 따라 **「탐색적 관측 — 다음 사전등록의 표적」**으로만 쓴다.

### 5-4. 사장님 ① 대안의 개별 대조 (인쇄만 · 사전고정 라벨 · 판정 언어 금지)

`X1 − X0` · `X2 − X0` 를 인쇄하고 아래 셋 중 하나로 라벨한다.

| 조건 | 라벨 |
|---|---|
| `X1 − X0 ≥ ε` **그리고** `X2 − X0 ≥ ε` | 「손익비를 2:1 로 낮추는 쪽이 있어 보인다 — **다음 사전등록의 표적**」 |
| `X0 − X1 ≥ ε` **그리고** `X0 − X2 ≥ ε` | 「현행 1:5 쪽이 있어 보인다 — **표적**」 |
| 그 외(둘이 갈림) | 「일관되지 않음」 |

🔑 **둘 «다»** 같은 방향일 때만 라벨한다 — 하나만 보고 말하면 그게 1등 고르기다.

### 5-5. 다중검정 (동결)

주 검정 **1개**(§5-2) ⇒ Holm 1단계 문턱 = α/m = **.05**.
REGISTRY 공통 제약 `S ≥ 20m − 1` ⇒ m=1 이면 **필요 시드 19**, 이 문서는 **20** 이다.
최소 순열 p = 1/21 = **.0476 < .05** ⇒ **✅ 도달 가능.**
🔑 문서 1(minervini)은 m=2 에 시드 20 이라 **구조적으로 기각 불가**였다. 반복하지 않는다.

§5-3·§5-4 는 **기술 통계이므로 보정 대상이 아니고 판정 언어를 쓰지 않는다.**
🔴 가족 FWER 은 `../REGISTRY.md` 가 관리한다. 이 문서 등재 후 **가족 m = 4 · FWER ≈ 18.5%** —
판정문에 병기한다. ***보정을 안 거는 것과 위험이 없는 것은 다르다.***

🔴 **어떤 결과가 나오든 ε·창·arm·시드·문턱·`score`·홀드아웃 분할을 갈아끼우지 않는다.**

## §6. 🔑 1단계 게이트 — PnL 을 보기 «전»에 확정한다 (필수)

산출물은 `GATE.md` 로 **PnL 관측 전에 커밋**한다.

1. **진입 트리거 수 · 선택 종목-일 수 · 고유 종목 수** (전 arm 공통값 1개) ·

2. **연도별 쏠림** — 원시 비중과 **거래일 수 정규화 비중** 양쪽. **양쪽 모두 50% 이하일 때만 ✅.**

4. **1 arm 실행 시간 실측** → 10 arm + 20 시드 전체 추정치. 🔴 추정이 과대하면 **진행 전에 보고**한다.

## §10. 🔴🔴 홀드아웃 프로토콜 — B반을 «언제·어떻게» 여는가 (동결)

**§5-2 가 (나)로 나왔을 때만 발동한다.** (가)·(다)면 방식 수준에서 답이 나온 것이므로
B반을 열지 않는다 — 열 이유가 없다.

```
0) 🔴 A반 1등이 **X0(현행) 자신이면 B반을 «열지 않는다»** — 검정할 «선택»이 없기 때문이다.
   그 경우 결론은 「(나) + 현행이 A반 최고」로 끝내고, B반은 다음 문서를 위해 봉인된 채 남긴다.
1) A반 §5-3 표에서 «거래당 평균이 가장 높은 arm» 하나를 고른다.        ← 여기서 고르는 것이 허용된다
   동점이면 arm 이름 사전순으로 가장 앞선 것. (동점 규칙을 미리 고정한다)
2) 그 arm «하나»와 X0 «하나»만 B반에서 돌린다.  ← 다른 arm 은 B반에서 «돌리지 않는다»
3) 판정:  B반에서도  (선택 arm − X0) ≥ ε  이고  N1 성립  →  🟢 재현됨
                                       그 외                →  🔴 재현 실패 = A반 1등은 우연이었다
4) 결과가 무엇이든 B반은 «다시 열지 않는다». 이 문서는 여기서 끝난다.
```

🔑🔑 ***A반에서 1등을 고르는 것은 사후 선택이 «맞다». 그래서 그 선택을 B반이 «검정»한다.
사후 선택을 합법화하는 방법은 이것 하나뿐이고, 그러려면 분할이 «결과를 보기 전»에
정해져 있어야 한다 — §3-1 이 그 일을 한다.***

⚠️ **B반 재현 성공도 「라이브 채택」이 아니다.** §7-1(whipsaw 미재현)이 그대로 남는다.
채택은 여전히 **별도 결정**이다.

## §11. 🔴 개정 (2026-08-17, **백테스터 구현 직후 · 어떤 PnL 도 관측하기 «전»**)

> **§0~§10 은 한 줄도 삭제하지 않았다. 어긋나는 곳은 §11 이 우선한다.**
> 문서 1 의 §10 과 같은 성격 — **동결본이 「잘못 적은 측정량」을 바로잡는 것**이고 **결과와 무관하다.**
> 발견 경위: 백테스터 확장 작업자가 §6-3 을 구현하다 **「그 조건은 발동할 수 없다」**고 신고했다.

### 11-1. 🔴 §6-3 의 측정량이 틀렸다 — 「결측」이 아니라 「수렴 부족」이다

동결본 §6-3 은 *「EMA65 는 60봉에서 워밍업이 부족하다 ⇒ **결측률**을 인쇄하고 5% 를 넘으면
창을 130봉으로 올린다」*고 적었다. **틀렸다.**

`ewm(span=N, adjust=False)` 는 **첫 봉부터 값을 낸다**(`EMA₁ = close₁`). ⇒ **`NaN` 이 원리적으로
안 생기고 결측률은 «항상 0%»** 다. ***그 조건은 어떤 데이터에서도 발동하지 않는다.***

🔑🔑 ***가드를 달아놓고 그 가드가 재는 양이 상수라면, 그건 가드가 아니라 장식이다.***
이 저장소가 반복해서 잡아온 형태(`max_capital_pct` 이중 미결선 · DROP 게이트 부재 ·
`foreign_flow` INFO 한 줄)와 **같은 계열**이다. ⇒ [[reusable-rules]] 에 올린다.

### 11-2. 올바른 측정량 — **초기값 잔존 가중치**

`adjust=False` 의 EMA 는 `n` 봉째에 **첫 종가가 `(1−α)^(n−1)` 만큼 남아 있다** (`α = 2/(span+1)`).

| 선 | α | **60봉에서 초기값 잔존** | **130봉에서** |
|---|---|---|---|
| EMA13 | 0.14286 | 0.011% | ~0% |
| **EMA65** | 0.03030 | 🔴 **16.3%** | **1.89%** |

⇒ ***60봉에서 EMA65 는 「첫날 종가가 6분의 1을 차지하는 값」이다.*** 결측이 아니라 오염이다.

### 11-3. 확정 — **룰 창을 무조건 130봉으로 올린다** (조건부 아님)

**기준 (동결)**: `초기값 잔존 가중치 ≤ 2%`. EMA65 에 대입하면
`n ≥ 1 + ln(0.02)/ln(1−α) = 1 + 127.1 = 129` ⇒ **130봉.**

🔑 **130 은 동결본 §6-3 이 이미 적어둔 숫자다.** 관측 후에 새로 고른 값이 아니다 —
바뀐 것은 **「언제 올리나」(조건부 → 무조건)**뿐이고 **숫자는 그대로**다.

**불변 확인** (자매 문서 §3-1 과 같은 형식):

| 참조 | 사용 구간 | 60 → 130 에서 |
|---|---|---|
| `rule_ma5_pullback` 진입 (전 arm 공통) | 마지막 22봉 | ✅ **불변** |
| `score` = `volume.iloc[-5:]` | 마지막 5봉 | ✅ **불변** |
| SMA5 / SMA10 / SMA20 / SMA60 | `rolling(N).mean().iloc[-1]` = 마지막 N봉 | ✅ **불변** |
| **EMA13 / EMA65** | 창 시작부터 경로 의존 | 🔴 **바뀐다 — 그것이 이 개정의 목적이다** |

🔑 ***SMA 는 꼬리만 보므로 창을 늘려도 값이 같지만, EMA 는 경로 의존이라 값이 바뀐다.***
그래서 이 개정은 **LINE 계열 중 EMA 두 arm 에만** 영향을 준다. 다른 arm 은 산술적으로 불변이다.

🔴 **`D`(=X0) 를 포함한 FIXED 계열 전부와 진입은 창과 무관하다** ⇒ 기준선이 흔들리지 않는다.

### 11-4. 실행부 확인 사항 (§9 에 인쇄)

- 60봉 / 130봉 두 설정에서 `X0` 의 거래 기록이 **완전히 동일**함을 실측으로 인쇄한다.
  (같아야 정상 — 다르면 위 표가 틀린 것이므로 **진행을 멈추고 보고**한다.)
- EMA13·EMA65 의 초기값 잔존 가중치를 **실제 실행 창 길이로 계산해 인쇄**한다.

### 11-5. `R_exit` 의 단위 (동결본 미명시 → 확정)

§5-1 은 「거래일」이라 적었고 구현은 **봉 수**(`hold_bars = i − entry_idx`)로 센다.
**이 문서는 일봉만 쓰므로 둘은 같다.** ⇒ **확정: 봉 수로 센다.**
⚠️ 같은 백테스터를 분봉에 쓰면 뜻이 달라진다 — 이 문서 밖의 이야기다.
