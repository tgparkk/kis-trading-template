> 조사일 2026-08-21 · 발단: TT shadow 승격 판정 중 «후보는 매일 10건인데 매수가 0» 관측

## 2. 근본 원인 — `on_init` 이 복원분을 지운다

```
main.py:267  bot_initializer.initialize_system()  → StateRestorer → sync_positions 주입
main.py:271  _initialize_strategy()               → on_init() → self.positions = {}   ← 지움
```

`BaseStrategy.sync_positions`(`base.py:753`)는 `self.positions.update(...)` 로 **실제로 채운다**.
그러나 `MinerviniVolumeDryupStrategy.on_init`(`strategy.py:119`)의 `self.positions = {}` 가
**그 뒤에** 실행돼 복원분을 통째로 지웠다.

⇒ 장 시작 시 `len(self.positions) == 0` ⇒ K 게이트(`strategy.py:157`
`if len(self.positions) >= self._max_positions: return None`, `max_positions=3`)가
**아무것도 막지 않았다** ⇒ **K 를 넘겨 샀다.**

### 로그 증거 — 순서가 그대로 보인다

**8/11 (수정 전)** — `sync_positions` 가 `초기화 완료` «앞»에 있고 그것뿐이다:
```
07:40:34  [sync_positions] 포지션 동기화 완료: 7종목 (['003280','006800','001740','403870','093370','088350','018880'])
07:40:34  MinerviniVolumeDryupStrategy v1.0.0 초기화 완료          ← self.positions = {}

```
🔑 그날 산 3종목은 **복원 7종목 집합에 하나도 없다** — 게이트가 0 에서 세기 시작했다는 뜻이다.

**8/20 (수정 후)** — `sync_positions` 가 **두 번**이고 두 번째가 초기화 «뒤»다:
```
07:40:20  [sync_positions] 포지션 동기화 완료: 3종목
07:40:20  MinerviniVolumeDryupStrategy v1.0.0 초기화 완료          ← self.positions = {}
07:40:20  전략 초기화 완료: MinerviniVolumeDryupStrategy
```

호출 횟수는 **8/13 을 경계로 1 → 2 로 바뀐다**(8/03~8/12 전부 1회 · 8/13~8/21 전부 2회).

## 4. 🔴🔴 기록되지 않은 것 — 그 수정의 «매수 쪽» 효과

`8238f91` 커밋 메시지는 **청산 경로만** 논한다(제목 「전략측 청산이 죽어 있었다」).
본문엔 심지어 **「🟢 매매 동작은 아직 바뀌지 않는다」**고 적혀 있다(별건 D2 가 신호를 버리므로).

**그 진술은 매수 쪽에서 거짓이었다.** 복원분이 살아나자 **K 게이트가 비로소 물리기 시작했고
매수가 멈췄다.** 8/03~8/12 는 8거래일 중 6일에 매수가 있었고, 8/13~8/20 은 **6거래일 연속 0건**이다.

🔑🔑 ***고장을 고치면 「고장 덕분에 돌던 동작」도 함께 멈춘다. 그 두 번째 효과는 커밋이 스스로 말하지 않는다.***

### 결정적 증거 — 8/21 자연실험
```
09:27:07  📤 매도 체결 042660 (수익률 -7.9%)   ← 3 → 2, 슬롯 하나 비움
09:28:25  📥 매수 체결 475150 x 59주            ← 78초 뒤
```
78초 사이에 바뀐 것은 **보유 수뿐**이다. 신호가 없던 게 아니라 자리가 없던 것이다.

## 5. 파급 — 두 가지

### 5-1. 🔴 8/03~8/12 라이브는 «설정된 전략»이 아니었다
minervini 는 K=3 설정으로 **최대 8종목**을 들고 있었다(**2.67배**). `book_pullback_ma20` 도 K=5 에 8종목.
⇒ ***그 기간 라이브 성과를 백테스트(K=3)와 비교하면 다른 전략을 비교하는 것이다.***
K 는 이 전략에서 측정으로 고른 값이다(`config.yaml:34` — `_REtest_minervini_Ksweep`:
「volume_dryup capacity 작아 K=3만 생존, K=5는 BULL서도 PnL 음전」).

### 5-2. 🔴 TT 승격 실험에 직접 걸린다
`on` 승격은 **후보 명단을 10건 → 3건으로 교체**하는 결정이다. 그런데 **보유가 K 에 붙은 날은
후보가 무엇이든 매수가 0**이므로, 승격 효과는 **슬롯이 비는 날에만** 관측된다.

**8/13~8/21 9거래일 중 매수가 가능했던 날은 1일(8/21)뿐이다.**
(8/18 은 매도 3건이 있었으나 보유 6 → 3 이라 여전히 K 에 붙어 슬롯이 안 비었다.)

⚠️ 즉 ***승격 후 「매매가 어떻게 달라지는가」는 5거래일 관측으로는 표본이 거의 안 쌓인다.***
승격 판정(체크리스트 ①②③)은 **후보 선정 단계**를 보는 것이므로 그대로 유효하지만,
**성과 비교를 기대하면 안 된다** — 그건 훨씬 긴 기간이 필요하다.
