## 2. (4) 열 — 「같은 것을 재는가」 상세

### 2-1. 🔴 dry-up 룰에 **가격 조건이 하나도 없다**

```python
# strategies/books/minervini_vcp/rules.py:318-332
vol = df["volume"].astype(float)
recent_avg = vol.iloc[-10:].mean()
base_avg   = vol.iloc[-40:-10].mean()
if recent_avg / base_avg <= 0.7:   # <- 이게 전부다
    return RuleResult(triggered=True, ...)
```

`close` · `high` · `low` 를 **한 번도 읽지 않는다.**

> **쉬운 예시** — 두 종목이 오늘 똑같이 통과한다.
>
> - 갑: 3개월 상승 후 고점 부근에서 조용히 눌리는 중, 거래량 30% 감소 → **Minervini 가 찾는 것**
> - 을: 두 달째 −45% 흘러내리는 중, 팔 사람이 다 팔아 거래량 30% 감소 → **Minervini 가 절대 사지 않는 것**
>
> 룰은 둘을 **구별하지 못한다.** 「매집」과 「관심 소멸」이 같은 숫자를 낸다.

원저작에서 dry-up 은 **VCP 베이스의 마지막 수축 안에서** 일어나는 현상이다. 베이스(= 가격 구조)를
떼어내면 남는 건 「거래량이 줄었다」뿐이고, 그건 상승·하락 어느 쪽에서도 일어난다.

🔑 **`ma5` 의 `_recent_surge` 와 같은 계열이다** — 개념은 방향을 포함하는데 구현은 크기만 잰다.

### 2-2. 🔴 TT c6·c7 — 52주 고저를 **종가**로 잰다

```python
# rules.py:63-64   <- df 에 high/low 컬럼이 «있는데» 안 쓴다
high_52w = float(close.iloc[-252:].max())
low_52w  = float(close.iloc[-252:].min())
```

52주 고저는 관례상 **장중 고가·저가**다. 종가로 재면 범위가 좁아지고, 두 조건이 **반대 방향으로** 틀어진다.

| 조건 | 식 | 종가 기준의 효과 |
|---|---|---|
| c6 | `(고점 − 종가) / 고점 ≤ 25%` | 고점이 낮아짐 ⇒ **통과하기 쉬워진다**(완화) |
| c7 | `(종가 − 저점) / 저점 ≥ 30%` | 저점이 높아짐 ⇒ **통과하기 어려워진다**(강화) |

> **쉬운 예시** — 1년 전 장중 10,000원을 찍고 종가는 9,000원으로 끝난 종목. 오늘 종가 7,500원.
>
> - 실제 기준: (10,000 − 7,500) / 10,000 = **25.0% → 아슬아슬하게 탈락**
> - 코드 기준: (9,000 − 7,500) / 9,000 = **16.7% → 통과**

상쇄가 아니라 **각각 다른 방향으로 어긋난다.** 두 문서(`PREREG.md` · `GATE.md`)는 `close.iloc[-252:]` 를
「몇 봉이 필요한가」 맥락에서만 언급했고, **「종가 기준이라 원저작과 다르다」고 적은 곳은 없다.**

### 2-3. 🔴 RS — 이름은 같고 재는 기간이 **4배** 다르다

| | 원저작(IBD RS Rating) | 코드 `compute_rs_percentile_12w` |
|---|---|---|
| 기간 | **12개월**, 최근 분기 40% 가중 | **12주(60거래일)**, 가중 없음 |
| 모집단 | **전 시장** | 그날 `base_filter` 통과 집합(시총 ≥ 3천억 · 거래대금 ≥ 30억) |
| 형태 | 백분위 1~99 | 백분위 0~99 |

모집단 차이는 **PREREG §10-5 항목 11 에 이미 선언돼 있다**(🟢 정직하게 적혀 있음).
**기간 차이(12개월 → 12주)는 어느 문서에도 없다.** 코드 docstring 에만 「12주」라고 적혀 있다.

⚠️ **백분위라는 성질 자체는 원저작도 같다** — IBD RS 도 백분위이므로 `RS ≥ 70` 은 양쪽 다 상위 ~30% 를 뜻한다.
이건 결함이 아니다. **다른 건 「무엇의 상위 30%인가」다.**

### 2-4. ⚪ TT 8조건의 실제 선택력 (분해 — 판정 언어 아님)

`RESULTS_raw.md:33` 실측 · 적격 **211,929** (code, date):

| 조건 | 통과 | 비율 |
|---|---|---|
| `dryup` | 55,239 | **26.1%** |
| `TT`(c1~c8 전부) | 38,638 | **18.2%** |
| `F`(재무) | 51,753 | 24.4% |

백분위 성질상 **c8 단독은 항상 ~29.8%** 를 통과한다(실측 검증: 유니버스 50 / 200 / 627 / 1000 종목 전부 29.8~30.0%).
⇒ `P(c1~c7 | c8) = 18.2% / 29.8% =` **61.2%**.

🔑 **「8개 조건」이라는 이름이 주는 인상보다 c1~c7 의 선택력은 약하다** — c8(RS 상위 30%)을 통과한 종목의
**5분의 3이 나머지 7조건도 통과한다.** 고 RS 종목이 대개 정배열 상승 추세라 조건들이 서로 겹치기 때문이다.
⚠️ **관측이지 검정이 아니다** — REGISTRY 규칙 2에 따라 판정 언어를 쓰지 않는다.

### 2-5. 🔴 청산이 원저작의 **수익 구조를 원리적으로 배제**한다

| | 원저작 | 코드 |
|---|---|---|
| 손절 | 7~8% | **−8%** ✅ |
| 손익비 | 평균이익 ≥ 평균손실 × **2** | tp +12% / sl −8% = **1.5 : 1** |
| 승자 관리 | 트레일링으로 **큰 승자를 끌고 간다** | **trail 없음** · `max_hold` **20거래일** |

> **쉬운 예시** — Minervini 방법의 수익은 「10번 중 4번 맞고, 그 4번 중 1번이 +80% 나서
> 전체를 먹여살리는」 구조다. 그런데 이 구현은 **거래당 이익이 +12% 에서 «잘린다».**
> +80% 짜리가 나올 수 있는 경로가 코드에 없다.
> 손절은 −8% 로 원저작대로 두고 이익만 잘랐으므로, **원저작이 이익을 내는 메커니즘만 골라서 제거**한 형태다.

⚠️ 단 이건 **Variant B 라는 이름으로 «의도된» 선택**이다(`config.yaml` 주석: variant B Sharpe 0.64 vs A 0.03).
**「몰라서 안 한 것」이 아니라 「알고 바꾼 것」**이므로 결함이 아니라 **개념 이탈로 분류**한다.

## 3. (3) 열 — 배선 구멍

### 3-1. 🔴 `minervini_vcp` 인데 **VCP 가 라이브에 없다**

grep 전수 결과 `rule_vcp_contraction_breakout`(주석에 *「책 핵심 VCP」*) · `rule_vcp_breakout` · `rule_tight_closes`

### 3-2. 🔴 매수 방아쇠의 **방향이 반대**다

| | Minervini 의 매수 시점 | 라이브의 매수 시점 |
|---|---|---|
| 가격 | 피벗 **돌파** | 조건 없음 |
| 거래량 | **확대**(평균 대비 급증) | **감소**(직전 30봉의 70% 이하) |

원저작은 dry-up 을 **「사도 되는 상태」의 표시**로 쓰고, 실제 매수는 **돌파 봉**에서 한다.
이 구현은 **dry-up 자체를 매수 신호로** 쓴다 ⇒ **셋업을 사고 방아쇠를 안 기다린다.**

🔑 이것이 `D` arm 이 무작위를 못 넘은 것(RESULTS §3, p = 1.0000)과 **정합하는 그림**이다 —
방아쇠가 없으면 「언제 오를지」에 대한 정보가 신호 안에 없다.
⚠️ **정합할 뿐 인과를 검정한 것은 아니다.**

### 3-3. 🔴 매수 시점에는 TT 를 **물리적으로 못 돌린다**

README 는 *「`evaluate_entry()` 는 dryup 만 재검사하고 TT 는 재검사하지 않는다」* 라고 적었다. 맞다.
**그런데 이유가 하나 더 있고, 그게 더 무겁다.**

| 경로 | 싣는 일봉 | TT 요구 |
|---|---|---|
| EOD 스크리너 | `lookback_days = 260` (`screener.py:49`) | 220봉 ✅ |
| **매수 시점** | `OHLCV_LOOKBACK_DAYS = 120` **달력일 ≈ 85봉** (`config/constants.py:19`) | 220봉 ❌ |

⇒ **`evaluate_entry()` 에 TT 를 «추가하기만» 하면 항상 False 가 되어 매수가 0건이 된다.**
그리고 `rule_trend_template` 은 봉이 부족하면 **로그 없이 False** 를 반환한다(`rules.py:52`) ⇒ **조용히 멈춘다.**

🔑 **「TT 를 매수 시점에도 재검사하자」는 한 줄 수정이 아니다** — 데이터 적재 경로를 함께 바꿔야 한다.
(현재는 `accepts_volume_fallback = False` 로 외부 유입을 막아 이 구멍을 우회하고 있다.)

### 3-4. 🟡 재무는 「정보다」로 판정됐는데 라이브에 없다

`F`(연간 영업이익 +25%, `rcept_dt` PIT)는 `backtest/concept_axes/minervini/run.py:290` 에만 있다.
판정은 **(가-F) 재무는 정보다** (`DF − D` = **+1.26%p**). **라이브 배선 0줄.**

## 7. 이 감사가 답하지 «못한» 것

- **구성비 미측정** — 위 (4)열 항목들이 실제 후보 집합을 얼마나 바꾸는지 **한 건도 재지 않았다.** 코드 독해뿐이다.
- **`ma5` 에서 배운 교훈**: 하루치 표본만 보면 오진한다(충실도 4.2% vs 실제 16.4%).
