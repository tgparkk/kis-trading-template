## §0. 왜 재는가 — 「연결 안 한 것」의 정체가 둘이고 처방이 정반대다

라이브 minervini 의 진입 조건은 **한 줄**이다: *최근10봉 평균거래량 ≤ 직전30봉 평균의 70%.*
Minervini 의 SEPA 는 그 앞에 **두 개의 전제**를 둔다 — ①**Trend Template**(추세 위치)
②**펀더멘털 스크린**(이익 성장). 둘 다 라이브에 없다.

| | 설명 | 처방 |
|---|---|---|
| **(가)** | **결함** — 구현해놓고 배선을 안 했다 | 연결한다 |
| **(다)** | **결정** — 붙이면 나빠져서 뺀 것이다(기록만 없다) | 그대로 둔다. 오히려 뺀 게 옳다 |
| **(나)** | **무의미** — 붙이든 말든 무작위와 구별 안 된다 | 이 축을 접고 다른 축으로 간다 |

🔴 **판돈**: (가)면 *「라이브가 원저작을 실행하고 있지 않다」* 가 확정된다.
`concept_fidelity_audit` 와 `PAPER_STRATEGIES §0.7`(*「평판 숫자는 지금 도는 것을 설명하지 않는다」*)
이 가리키던 지점이고, **8전략 전체에 같은 질문이 걸린다.**

🔑 ***이 설계의 요점: 「일부러 뺐는지」를 기록에서 찾을 필요가 없다.*** 일부러였다면 (다)가,
결함이었다면 (가)가 나온다. **arm 이 그 질문을 대신 답한다.**

## §2. Arm (동결) — 진입 룰 축 «하나만» 바꾼다. 2×2 요인설계 + 2

**고정**: `base_filter`(시총 ≥3천억 · 거래대금 ≥30억) · 청산(**sl −8% / tp +12% / max_hold 20거래일 ·
트레일링 없음 · trend_flip 없음**) · **`score` = 현행 `df["volume"].iloc[-30:].mean()`** ·
`max_candidates=10` · 창 · OHLC 보정 · 백테스터(`BookBacktester`, `eod_liquidate=False`).

🔴 **`score` 를 현행으로 «고정»한다.** 랭킹 축은 `rank_score_counterfactual` 의 질문이다.
***한 번에 한 축만 움직인다*** — 랭킹 실험 결과가 무엇으로 나오든 이 문서에서는 안 건드린다.

| Arm | 진입 룰 | 역할 |
|---|---|---|
| **D** | `rule_volume_dryup` (현행 라이브) | **기준선** |
| **DT** | `dryup` ∧ `rule_trend_template` | TT 복원 |
| **DF** | `dryup` ∧ `F`(펀더멘털, §2-2) | 재무 복원 |
| **DTF** | `dryup` ∧ `TT` ∧ `F` | 완전 복원 |
| **T** | `rule_trend_template` **만** | 🔑 **분해** — 알파가 TT 에서 오나 dryup 에서 오나 |
| **R** | 그날 적격 풀에서 **무작위**, 시드 `0..19` | 🔑 **귀무** |

- **arm 은 이 여섯뿐이다.** 문턱 스윕·가중 혼합·부분 조건(8조건 중 k개) 전부 금지(§8).
- 룰 평가는 **(code, date) 캐시를 1회** 만들어 전 arm 이 공유한다(사다리 §2 승계).
- **R 은 다른 arm 과 같은 방식으로 매일 갱신**하고 `max_candidates` 도 10 으로 맞춘다.
  R 적격 풀 = 그날 `base_filter` 통과 집합(**진입 룰 조건 없음** — 「고르는 행위」 자체의 귀무).

### 2-1. `rule_trend_template` 은 코드를 «그대로» 쓴다

`strategies/books/minervini_vcp/rules.py::rule_trend_template` 을 **파라미터 기본값 그대로**
(`rs_threshold=70` · `high_52w_drawdown_max=0.25` · `low_52w_advance_min=0.30`) 호출한다.
🔴 **한 글자도 고치지 않는다.** 고치면 「원저작을 연결했을 때」가 아니라 「내가 만든 룰」이 된다.

`ctx['rs_value']` 는 `compute_rs_percentile_12w(universe_close)` 로 **그날까지의 데이터만** 써서
산출한다(60거래일 수익률 횡단면 백분위). 유니버스 = 그날 `base_filter` 통과 집합.
⚠️ **220봉 요구**가 있으므로 워밍업(`HIST0`)이 필수다.

### 2-2. 재무 스크린 `F` (동결) — 문턱은 «원저작»에서, 데이터에서 유도하지 않는다

```
F(code, D) = TRUE  ⟺  다음을 «모두» 만족하는 가장 최근 사업연도 y 가 존재한다:
   ① rcept_dt(code, y)   ≤ D − 1        (PIT — 접수 «다음» 거래일부터 가시)
   ② rcept_dt(code, y−1) ≤ D − 1
   ③ operating_income(code, y−1) > 0     (원저작: 흑자 기업만)
   ④ operating_income(code, y) ≥ 1.25 × operating_income(code, y−1)
```

- **문턱 25% 는 Minervini 원저작의 이익 성장 기준**이다. 우리 데이터 분포에서 뽑지 않았다.
- 🔴 **`operating_income` 은 EPS 의 «대리변수»다.** 원저작은 분기 EPS 성장을 요구하는데
  분기 재무가 713종목뿐이라 **연간 영업이익으로 대체**했다. §7 한계에 적는다.
- 🔴 **③ 을 안 걸면 적자→흑자 전환이 무한대 성장률로 통과한다.** 원저작이 흑자 기업만
  보므로 개념에 맞고, 동시에 산술 사고를 막는다.
- **`rcept_dt` 가 NULL 인 행은 「그 해 데이터 없음」으로 처리**(fail-closed). 통과시키지 않는다.

## §5. 예측과 판정 (동결)

`ε = 0.5%p` 로 고정한다(왕복 비용 0.21%p 의 2.4배). **결과를 보고 바꾸지 않는다.**

### 5-1. 🔑 귀무 N1 — 이게 없으면 arm 차이는 뜻이 없다

각 arm A 에 대해 **`A > R 20개 전부`** 를 요구한다(단측 순열검정 p = 1/21 ≈ 0.048).
🔴 **기준선 `D` 도 같은 검정을 받는다.** `D` 가 N1 을 통과 못 하면
***현행 진입 룰이 이미 「무작위로 10개 고르기」와 구별되지 않는다*** 는 뜻이고,
**그것 자체가 이 문서의 가장 중요한 결과**다. 눈에 띄게 인쇄한다.

### 5-2. 주 판정 — Trend Template (동결)

| 결론 | 조건 |
|---|---|
| **(가) TT 는 정보다 — 연결 안 한 것이 결함** | `DT − D ≥ ε` **그리고** N1(DT) 성립 |
| **(다) 빼는 것이 옳았다 — 연결 안 한 것이 결정** | `D − DT ≥ ε` **그리고** N1(D) 성립 |
| **(나) TT 는 정보가 아니다** | N1(DT) 불성립 |
| **(마) 구별 불가** | `\|DT − D\| < ε` |

### 5-3. 보조 판정 — 재무 (동결, Holm 보정 후)

| 결론 | 조건 |
|---|---|
| **(가-F) 재무는 정보다** | `DF − D ≥ ε` **그리고** N1(DF) 성립 |
| **(다-F) 재무는 해롭다** | `D − DF ≥ ε` |
| **(나-F) 재무는 정보가 아니다** | N1(DF) 불성립 |
| **(마-F) 구별 불가** | `\|DF − D\| < ε` |

### 5-4. 🔑 분해 — 알파는 어디서 오는가 (인쇄 + 판정)

| 관측 | 결론 |
|---|---|
| `T ≈ DT` (차 < ε) **이고** `DT − D ≥ ε` | **dryup 이 기여하지 않는다** — TT 만으로 같은 결과 |
| `DT − T ≥ ε` | **둘 다 필요하다** — dryup 이 TT 위에서 값을 더한다 |
| `T − DT ≥ ε` | 🔴 **dryup 이 «해롭다»** — TT 단독이 더 낫다 |

### 5-5. 상호작용 (인쇄만 · 판정 아님)

`DTF − DT − DF + D` 를 인쇄한다. 🔴 ***이 값을 보고 조합을 «고르면» 사후적합이다.***
채택은 별도 사전등록에서 한다.

### 5-6. 다중검정 (동결)

이 문서의 **주 검정은 2개**(§5-2 TT · §5-3 F). **Holm 보정을 문서 «안»에서 적용**한다
(α = .05 → .025 / .05 순).
§5-4 분해와 §5-5 상호작용은 **기술 통계이므로 보정 대상이 아니고, 판정 언어를 쓰지 않는다**
(단 §5-4 의 세 라벨은 사전 고정이므로 인용 가능).
🔴 가족 전체(4문서)의 검정 수는 `../REGISTRY.md` 가 관리한다.

🔴 **어떤 결과가 나오든 ε·창·arm·시드·문턱·`score` 를 갈아끼우지 않는다.**

## §6. 🔑 1단계 게이트 — PnL 을 보기 «전»에 확정한다 (필수)

`stop_vol_fit_gate` 실패의 직접 승계. ***게이트를 설계했으면 「무엇이 걸리는지」를 «먼저» 세어라.***

1. **arm 별 진입 트리거 수 · 선택 종목-일 수.**
   ⚠️ TT 는 8조건 AND 라 트리거가 «크게» 줄 것으로 예상된다. **얼마나 주는지를 먼저 인쇄한다.**
   🔴 **arm 의 트리거 수가 `D` 의 10% 미만이면 그 arm 은 「표본 부족 → 판별 보류」** (사전 고정).
2. 🔴 **배제 집합의 구성비 — 이게 이 게이트의 핵심이다.**
   `D` 는 통과했는데 `DT` 에서 «빠진» 종목-일, `DF` 에서 빠진 종목-일 각각에 대해
   **①시총 10분위 ②주가 10분위 ③거래대금 10분위 ④월별** 분포를 잔류 집합과 나란히 인쇄하고
   **KS 거리**를 낸다.
   ⚠️ **KS > 0.20 은 여기서 «자동 판별불가»가 아니다** — TT·F 는 «의도적으로» 추세·수익성으로
   거르는 축이므로 분포가 달라지는 것이 정상이다. **크기를 기록**하는 것이 목적이다.
   🔑 ***같은 지표라도 축이 의도한 것이면 게이트가 아니라 기술 통계다*** —
   이 비대칭을 사전에 구분해 적어두는 것이 §6 의 요점이다.
3. **`F` 커버리지** — 연도별로 ①`rcept_dt` 결측률 ②전년 영업이익 ≤0 비율 ③25% 통과율.
   🔴 **정정공시로 `rcept_dt` 가 «늦게» 찍힌 행의 수**를 별도로 센다(§7-4).
4. **연도별 쏠림** — 원시 비중과 **거래일 수 정규화 비중** 양쪽. **양쪽 모두 50% 이하일 때만 ✅.**
   한쪽이라도 넘으면 「국면 특이 → 판별 보류」 병기.
5. **`rs_value` 산출 건전성** — 날짜별 유니버스 크기 최소/중앙, `rs_value` 결측률.
   🔴 유니버스가 2종목 미만인 날은 `compute_rs_percentile_12w` 가 예외를 던진다. 그런 날 수를 인쇄.
6. **arm 간 선택 종목 겹침 행렬.**

## §7. 🔴 미리 적어두는 한계

1. 🔴 **`operating_income` 은 EPS 의 대리변수다.** 원저작은 **분기 EPS 성장 가속**을 요구하는데

## §10. 🔴 개정 (2026-08-16, **1단계 산출 후 · PnL 관측 «전»**)

> **§1~§9 는 한 줄도 삭제하지 않았다.** 어긋나는 곳은 §10 이 우선한다.
> 세 항목 모두 **동결본이 «명시하지 않아 생긴 빈칸»을 메우는 것**이고, 결과와 무관하다.

### 10-1. 룰에 넘기는 **봉 창 = 260봉** (동결본 미명시 → 확정)

라이브 스크리너는 `lookback_days = 90` 인데 `rule_trend_template` 은 **220봉을 요구**하고
52주 고저에 `close.iloc[-252:]` 를 쓴다. ⇒ **90봉으로 부르면 TT 가 항상 False** 가 되어
`DT`·`DTF`·`T` arm 이 전부 0이 된다. 동결본 §2-1 은 *「220봉 요구가 있으므로 워밍업이 필수」*
라고만 적고 **창 길이를 명시하지 않았다.**

**확정: 전 arm 에 260봉을 넘긴다.** 근거 — 이 선택은 `D` arm 과 `score` 를 **바꾸지 않는다**:

| 참조 | 실제 사용 구간 | 260봉에서 불변? |
|---|---|---|
| `rule_volume_dryup` | `iloc[-10:]` · `iloc[-40:-10]` = 마지막 **40봉** | ✅ |
| `score` | `iloc[-30:]` = 마지막 **30봉** | ✅ |
| `rule_trend_template` MA200 + 20일 전 | **220봉** | ✅ (260 ≥ 220) |
| `rule_trend_template` 52주 고저 | `iloc[-252:]` | ✅ (260 ≥ 252 ⇒ **정확히 252봉**) |

🔑 ***260 이상이면 어떤 길이를 줘도 네 참조가 전부 같은 값을 낸다*** — 슬라이스가 상한을 씌우기
때문이다. 따라서 260 은 「최소이면서 충분한」 값이고, **`D` arm 은 라이브와 동일하게 동작한다.**

### 10-2. 🔴 `F` 의 수량사 확정 — 「가장 최근 가시 연도 «하나»」

동결본 §2-2 의 *「다음을 «모두» 만족하는 가장 최근 사업연도 y 가 «존재한다»」* 는 **∃ 로도 읽힌다.**
그렇게 읽으면 ***과거 아무 해나 한 번 +25% 성장했으면 영원히 통과***해 PIT 의미가 사라진다.

**확정 (동결본의 의도)**:
```
1) rcept_dt(code, y) ≤ D−1 인 사업연도 중 «가장 최근» y 를 «하나» 고른다.   ← 선택은 여기서 끝
2) 그 y 에 대해서만 ②③④ 를 판정한다. 실패하면 F = FALSE (다른 해를 찾지 않는다).
```
🔑 ***조건을 만족하는 해를 「찾아다니면」 그건 필터가 아니라 탐색이다.***
2026-08-13 태쏘에서 *「「전부」가 미정 행을 포함하는지 안 정해놔서 라벨이 갈렸다」*와 **같은 형태** —
***수량사는 결측·복수 후보가 있을 때만 뜻이 하나가 아니다. 사전등록에서 반드시 고정할 것.***

### 10-3. `rs_value` — 이력 절단 최적화를 **쓰지 않는다** (확정)

`compute_rs_percentile_12w` 의 `pct_change(60)` 은 pandas 기본 `fill_method='pad'` 라
**입력을 자르면 채울 앞값이 사라져 값이 달라질 수 있다.** 표본 3일 실측 차이는 0 이었으나
**보장이 없으므로** 날마다 전체 이력을 넘긴다. 🔑 ***「실측해보니 같더라」는 불변식이 아니다.***

### 10-4. `DTF` 가 §6-1 문턱에 걸렸다 — 판정 구조에 미치는 영향 (명시)

1단계 실측: `DTF` 트리거 2,434 = `D` 의 **4.4%** < 사전 고정 문턱 **10%**
⇒ **「표본 부족 → 판별 보류」 발동.**

🟢 **주 판정 2개는 영향을 받지 않는다** — §5-2(TT)는 `DT` vs `D`, §5-3(F)는 `DF` vs `D` 를 쓰고
둘 다 문턱을 통과했다(16.1% · 24.1%). **`DTF` 는 §5-5 상호작용(인쇄만)에만 쓰인다.**
⇒ **§5-5 는 「판별 보류」로 인쇄**하고 어떤 결론에도 인용하지 않는다.

### 10-5. §7 한계에 «추가»

12. 🔴 **arm 마다 「신호 → 실현 거래」 전환율이 다를 수 있다.** 1단계 실측: `D` 는 트리거 55,239 에
    **고유 종목 243**, `DT` 는 트리거 8,915 에 **고유 종목 414** — ***`D` 는 소수 종목을 반복
    선택하고 `DT` 는 넓게 흩뿌린다.*** `BookBacktester` 가 종목당 단일 포지션이므로
    **`D` 쪽 신호가 「이미 보유 중」으로 더 많이 버려질 수 있다.**
    ⇒ 실현 거래는 신호의 **비무작위 부분집합**이 되고, 그 비율이 arm 마다 다르면

    🔴 **2단계에서 arm 별 「신호 수 · 실현 거래 수 · 폐기율」을 반드시 인쇄**하고,
    **폐기율이 arm 간 2배 이상 벌어지면 판정문에 병기**한다.
