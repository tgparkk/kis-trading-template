## §1. 재무 정의 — 판정된 것을 «한 글자도» 바꾸지 않는다

### 1-1. 이진 `F` — 문서 1 §2-2 + `F1` §1-1 그대로 전재

```
F(code, D) = TRUE  ⟺
   1) rcept_dt(code, y) ≤ D − 1 인 사업연도 중 «가장 최근» y 를 «하나» 고른다.   ← 선택은 여기서 끝
   2) 그 y 하나에 대해서만 판정한다. 실패하면 F = FALSE (다른 해를 찾지 않는다).
        ② rcept_dt(code, y−1) ≤ D − 1
        ③ operating_income(code, y−1) > 0            (원저작: 흑자 기업만)
        ④ operating_income(code, y) ≥ 1.25 × operating_income(code, y−1)
   rcept_dt NULL = 「그 해 데이터 없음」 = fail-closed (통과시키지 않는다)
```

구현 정본은 `backtest/concept_axes/minervini/run.py:292-317`(`f_screen`)이고 **사유 코드 6종**
(`no_rows`·`no_visible_year`·`prev_year_invisible`·`oi_missing`·`prev_oi_nonpositive`·`growth_below_25pct`)을
**그대로 계승**한다. 🔴 **문턱 25% 를 이 문서에서 건드리지 않는다**(자문 §6-B · 반기 축적 후 별도 축).

🟢 **정의 재현 검증(2026-09-11)**: 위 정의를 SQL 로 옮겨 `F1` §0-3 ①(minervini 12거래일)에 돌린 결과
**후보 64 · `F` 통과 19 · 12거래일**이 나와 `F1` 의 인쇄값과 **정확히 일치**했다. 같은 SQL 로 `F1` 의 top-3 교체
**7/34 = 20.59%(6/12일)** 도 재현했다. ⇒ ***§0-3 의 ma20 수치는 「같은 자」로 잰 값이다.***

**사유 코드 분포(ma20 후보 260건 · 2026-08-25~09-10 · 인쇄만)**: `growth_below_25pct` 110 · `prev_oi_nonpositive` 72 ·
`oi_missing` 10 · `prev_year_invisible` 6 · `no_rows` 2 · `no_visible_year` 0 · `pass` 60.
🔴 minervini(같은 창: pass 22 · low 41 · prev_np 4 · oi_missing 1 · no_rows 1)와 비교하면
***ma20 후보는 「전년 영업이익 ≤ 0」 탈락이 27.7% 로 minervini(5.8%)의 4.8배***다 —
**후보 모집단이 다르다**(ma20 = 시총 ≤3조 전체 · minervini = dryup∧TT). 판정문에 병기한다.

### 1-2. 순위용 «연속값» — **V1(이진 `F` 그대로) 채택**

`F1` §1-2 의 표와 근거 셋을 **그대로 승계**한다(V2 `g=YoY` · V3 백분위는 **판정된 적 없는 함수**라 기각).
🔴 **ma20 고유의 추가 근거**: 해상도 2계단이 ma20 에서 «충분하다»는 실측이 `F1` 보다 훨씬 강하다 —
2계단만으로 **K=5 에서 12거래일 중 11일** top-5 집합이 바뀐다(§0-3 ②). 더 높은 해상도가 사는 종목을 더 바꿀 여지가 작다.

### 1-3. NULL(판정 불가) 처리 — **N1(`F=0` 과 같은 칸) 채택**

`F1` §1-3 그대로. 로그·게이트에서는 **따로 센다**(§4-2).
🔴 **`F1` 과 같은 단서가 붙고, ma20 에서 «더 세게» 붙는다** — 순위에서 fail-closed 는 *「모르면 뒤로」*이고
***후보가 K 보다 적은 날에는 여전히 산다.*** ma20 실측: 상위 20 안에 후보가 K=5 보다 적은 날 **0일**(항상 20건).
🟢 즉 ma20 에서는 「뒤로 밀면 실제로 안 산다」가 **12/12 일 성립**한다 ⇒ ***순위가 컷에 더 가깝게 «작동»한다.*** §2-3·§3 P2 가 이것을 잰다.

### 1-4. 가산 «방식» — **A(사전순 `(F, score)`) 채택**

`F1` §1-4 그대로(B 가중합·C 백분위합 기각). 🔴 **ma20 의 `score` 는 `df["volume"].iloc[-20:].mean()`**
(`strategies/book_pullback_ma20/screener.py:43`)로 **minervini 의 `score`**(`volume.iloc[-base_window:].mean()` ·
`minervini_volume_dryup/screener.py:156`)와 **같은 계열**이다 ⇒ `F1` 의 근거(척도를 섞지 않는다 · 원장 `score` 를 오염시키지 않는다)가 그대로 유효하다.
🔑 동률 깨기를 현행 `score` 로 두는 것은 「`score` 가 쓸모 있다」는 주장이 «아니다» —
ma20 랭킹은 이미 **(나) 랭킹은 정보가 아님**으로 판정났고(`docs/ma20_daytrade_3축_쉬운설명_2026-08-23.md` §1-3 ·
`V` −1.23% · `T` −0.76% · `P` +0.28% · `R` 최대 −0.05%), **정보가 아닌 것은 arm 차이에 기여하지 않으므로 고정하기 좋다.**

대체율 인쇄 · 추출 풀에서 arm 자신을 빼지 않음)를 **그대로** 쓴다. ***새로 유도하지 않는다.***

### 2-2. 🔴🔴 절단 지점 — 라이브는 «3단»이다. minervini 는 1단이었다

`F1` §2-2 는 백테스터가 선택을 `set` 으로 접어 **순서 정보를 잃는다**는 사실
(`minervini/run.py:761` · 같은 병이 `ma5/run.py:810` 에도 있다: `allowed = {d: set(v) …}`)에서
***순위의 효과는 절단 경계에서만 난다***를 유도하고 절단을 **K=3** 으로 내렸다. 그 논리는 여기서도 유효하다.
🔴 **그러나 ma20 의 라이브 절단은 «셋»이고 «셋 다» 걸린다:**

### 2-3. 🔴 희석 — `ε = 0.5%p` 가 arm 수준에서 뜻하는 것

```
arm 수준 차이  ≈  (교체 슬롯 비율) × (교체 종목이 교체 대상을 이긴 폭)
0.5%p          ≈  0.5833 × delta      ⇒   delta ≥ 0.86%p
```
🟢 **`F1` 보다 검정력이 «훨씬» 낫다** — minervini 는 교체율 20.6% 라 `delta ≥ 2.43%p` 를 요구했는데,
ma20 은 **58.33%** 라 **0.86%p** 면 된다. 🔑 ***순위 층의 검정력은 「재무가 센가」가 아니라 「후보가 많은가」가 정한다.***
🔴 그러나 **자문 §2 의 ma20 기대치는 +0.1~0.3%p** 라 `delta` 가 1%p 를 넘을 근거는 없다.
⇒ **여전히 검정력이 없을 가능성이 높다. 그건 설계 결함이 아니라 이 축의 «성질»이다.** MDE 를 §2-5 대로 인쇄한다.

**보조 추정량(인쇄만 · 판정 언어 금지)**: 교체 쌍 직접 비교 `delta_hat = mean(codes_in) − mean(codes_out)`.

### 2-5. 판정 (동결 예정) — 라벨은 «지금» 짓고 나중에 고르기만 한다

`ε = 0.5%p` 고정(왕복 비용 0.21%p 의 2.4배 · REGISTRY 공통 제약). **결과를 보고 바꾸지 않는다.**

**N1(귀무)**: `#{ R_M,i ≥ arm } ≤ 4` — **100 시드 중 96 이상을 이긴다**(계획서 §7 결정 0 = 96/100).
단측 순열 `p = (1 + #{R_M,i ≥ arm}) / 101` ⇒ N1 성립 시 `p ≤ 5/101 = .0495`.
🟢 주 검정 **m=1** 이므로 Holm 1단계 문턱 `.05` 에 최소 p `1/101 = .0099` 가 **도달 가능**하다.
REGISTRY 공통 제약 `S ≥ 20m − 1 = 19` ≤ 100 ✅.

| 라벨 (사전 고정) | 조건 |
|---|---|
| **(가-R2) ma20 에서도 재무는 순위 층에서 정보다** | `M5+F − M5 ≥ ε` **∧** N1(`M5+F`) **∧** G2a 통과 **∧** 총량 ≥ +10% |
| **(다-R2) ma20 순위 층에서는 해롭다** | `M5 − M5+F ≥ ε` **∧** N1(`M5`) |
| **(나-R2) ma20 순위 층에서 정보가 아니다** | N1(`M5+F`) 불성립 |
| **(마-R2) 구별 불가** | `abs(M5+F − M5) < ε` |

- 🔴 **MDE 를 §2 확정 «직후» 계산해 인쇄한다.** `MDE ≈ (z_.95 + z_.80) × SE_diff`,
  `SE_diff` 는 **arm 간 겹치는 거래를 반영한 쌍대 표준오차**(독립 가정 금지 — 두 arm 은 슬롯의 약 42% 를 공유한다).
  **`MDE > ε` 이면 판정문에 「검정력 없음」 병기.**
- **「없다」 선언은** 노출 통과(G2a) ∧ 점추정 `< ε` ∧ `MDE ≤ ε` 일 때만. **그 밖은 전부 「모른다」.**
- 보조 `delta_hat`(§2-3) — 부호만 인쇄. **「유의」·「기각」 금지.**
- 🔴 **기준선 `M5` 도 같은 N1 검정을 받는다.** 못 넘으면 ***현행 라이브 상위 5종목 고르기가 무작위 5개와 구별되지 않는다***는 뜻이고,
  **그것 자체가 이 문서의 가장 중요한 결과**다. ⚠️ 계열 관측(REGISTRY)상 **기준선이 귀무를 못 넘은 일이 다섯 번** 났다.

### 2-6. 다중검정 — 등록부 총계

이 문서의 **주 검정은 1개**. 문서 안 Holm 은 m=1 이라 `α` 그대로다.
등록부 갱신 제안: 현재 **6** → `F1` 등재 후 **7** → **이 문서(`F2`) 등재 후 8** (`1 − 0.95^8 = 0.3366` ⇒ **33.7%**) →
`F3`(daytrading) 등재 후 **9**(**36.98%**). 🔴 **REGISTRY 규칙 3 — 실행 «전»에, 동결과 «같은 커밋»에서 갱신한다.**
⚠️ 「실행된 N1」 누계(현재 ≥23)에 이 문서가 **실제로 돌린 arm 수**(기준선 1 + F-arm 1 = **2**)를 더한다 —
***자유도는 「판정에 쓴 것」이 아니라 「돌린 것」으로 센다.***

(b) 섹터뉴스 «앞»에 두어 **섹터뉴스가 이긴다** / (c) 한 번에 한 층만 `live` — **다른 층은 강제 `off`**.
🔑 ***관리자 권고 = (c).*** *「한 번에 한 축만 움직인다」*(REGISTRY)가 이 문서군의 규칙이고,
두 층을 겹쳐 켜면 **어느 층이 무엇을 했는지 영원히 못 가른다.** 단 **shadow 는 둘 다 동시 기록 가능**하다(둘 다 순서를 안 바꾸므로).

### 4-2. 계기 — 하루 1줄(전략당) + 기동 1줄 + 기록 표 1행/종목

```
[fund-rank] mode=shadow strategy=book_pullback_ma20 trade_date=2026-09-29 snapshot=20 consumed=10 K=5
            with_f=4 f0=15 null=1 src=asfiled src_max_rcept=2026-08-06
            reorder_topK=3 in=005930,000660,005380 out=111111,222222,333333
            old=A,B,C,D,E new=C,A,F,B,G  sector_news_mode=shadow
[fund-rank] mode=shadow strategy=book_pullback_ma20 (startup)
```

| 칸 | 뜻 | 왜 «따로» 찍나 |
|---|---|---|
| `snapshot` / `consumed` / `K` | ①20 / ②10 / ③5 — **세 절단을 한 줄에** | 🔴 `F1` 은 절단이 하나라 안 찍었다. ma20 은 셋이고 **어느 층에서 갈렸는지**가 사후 재현의 전부다 |
| `with_f` / `f0` / `null` | `F=1` / `F=0`(판정됨) / **판정 불가** | 🔑 ***한 규칙의 두 축은 따로 판정한다***. 셋을 접으면 **배관 고장이 「그냥 0건」처럼 보인다** |
| `src` · `src_max_rcept` | 읽은 원장과 그 원장의 최신 접수일 | 🔴 **원장이 썩는 것을 소리나게 만든다**(§6-1). 며칠째 그대로면 그게 경보다 |
| `reorder_topK` · `in=` · `out=` | top-5 집합에서 **교체될 종목 수와 코드** | EOD 점검은 **건수가 아니라 집합 차분**으로 돈다(운영 규칙) |
| `old=` · `new=` | 현행 순서 / `(F, score)` 순서 **둘 다** | 한 줄에 둘 다 있어야 사후 재현이 된다 |
| 🆕 `sector_news_mode` | 같은 자리 다른 층의 모드 | 🔴 **§4-1 의 2층 충돌을 매일 보이게 만든다.** 이 칸이 없으면 「`F` 가 옮겼다」와 「섹터뉴스가 옮겼다」가 섞인다 |

- **기동 줄**이 필요한 이유: 스캔·소비 줄은 파이프라인이 죽으면 **통째로 사라진다** ⇒ 「스위치가 off」와 「안 돌았다」가 구별이 안 된다(rs_leader errata E4 승계).
  **실패 조건 = 「기동 줄이 있는데 소비 줄이 없는 날」.**
- 기록 표 `fundamental_rank_log` — `sector_news_rerank_log` 와 **같은 칸 구조**(PK `(trade_date, strategy, stock_code)` · `f_value·f_reason·orig_rank·new_rank·applied·mode·reason·src_max_rcept`).
  🔑 ***형식을 복제하면 EOD 점검 쿼리도 복제된다.***
- 관측표는 `backtest/concept_axes/ma20/SHADOW_LOG_FUND.md` 에 매일 1행.
  🔑 ***「N거래일」은 날짜가 아니라 «채워진 행 수»다.***

### 4-3. 「순위가 바뀌었을 종목」 집합

매일 `in=` / `out=` 을 누적해 **집합 차분**을 만든다. 🔴 **그 종목들의 이후 수익률은 「인쇄만」** 하고 **판정하지 않는다**(사후적합 방지).
⚠️ ***반사실이 아니다*** — 실제로 산 것은 `old=` 쪽이다.

### 4-4. 발효 판단 규칙 — 네 관문 + 하나의 인쇄

| 관문 | 조건 | 미달이면 |
|---|---|---|
| **S1 배관** | `null / consumed` 가 **20% 초과인 날 ≤ 2** · `with_f + f0 + null == consumed` 가 «매일» 성립 | 발효 보류. 원장·매핑을 먼저 고친다 |
| **S2 신선도** | `src_max_rcept` 가 관측 창 안에서 **한 번이라도 전진**한다 | 🔴 발효 보류 — ***배선하면 조용히 썩는다***(§6-1) |
| **S3 노출** | `reorder_topK ≥ 1` 인 날이 **20% 이상** | 순위 층이 하는 일이 없다 ⇒ 보류 |

| 🆕 **S5 층 분리** | §4-1 의 2층 충돌 처리가 **결정·기록돼 있다** | 🔴 발효 보류 — 두 층을 동시에 켜면 원인 귀속이 불가능하다 |
| (인쇄) | 컷 축 관문(자문 §5-B) — `with_f` 일평균 ≥ 2K(=10) ∧ `with_f = 0` 인 날 ≤ 4 / 20거래일 | 🔴 **순위 층의 조건이 «아니다».** 실측 일평균 **4.42 < 10** ⇒ **컷 축은 열지 않는다** |

🔑 **관문이 전부 통과해도 그것은 「발효해도 된다」이지 「발효하면 좋아진다」가 아니다.**

## §6. 🔴 미리 적어두는 함정 (전부 · 축약 금지)

### 6-1. 판정된 `F` 의 원장이 «동결된 원장»이다

🔴 **원장 전환은 별도 축이다.**

### 6-2. as-filed PK 덮어쓰기
PK = `(stock_code, bsns_year)` ⇒ 정정공시가 as-filed 를 덮어쓴다. 🟢 방향은 보수적(덮어쓴 행의 `rcept_dt` 는 미래라 안 보인다) ·
🔴 커버리지 구멍이 생기고 정정하는 회사는 무작위가 아니다. G3-④ 로 센다.

### 6-3. 분기는 「없는」 게 아니라 「안 받은」 것
***「SEPA 펀더멘털 스크린을 검정했다」고 쓰지 말 것.*** 🔴 **ma20 에서는 그 말조차 성립하지 않는다** — A-07 원저작에 재무 조건이 «없다».
⇒ 이 문서가 재는 것은 ***「원저작에 없는 축을 얹으면 나아지나」***이고, 그건 REGISTRY 규칙 5 의 **「이론 주도 가설」 면제 요건을 만족하지 못한다**(문서 5 와 같은 처지). **가족 Holm 면제 유지 여부는 사장님 판단 사항.**

### 6-4. 문턱 +25% 는 대리변수
자문 §6-B. 🔴 **이 문서에서 문턱을 건드리지 않는다**(§7 금지 1).

### 6-5. 생존편향 — 부호는 같지만 논증이 약해진다
`daily_prices` 에 상폐가 사실상 없다(0.5%). 순위 층에서는 두 arm 에 거의 대칭이라 **컷 때의 문장을 복사하지 말 것.**

### 6-6. 🟢 `base_filter` 분모 위험 — **ma20 에는 «없다»**
minervini 는 `base_filter` 통과 집합이 RS 백분위의 분모라 컷을 넣으면 TT 판정이 오염됐다(`F1` §6-6).

### 6-7. 「모른다」를 「안전」으로 접으면 그 종목이 통과한다
§1-3 참조. ma20 에서는 후보가 항상 K 보다 많아 **「뒤로 밀면 실제로 안 산다」가 12/12 일 성립**한다.

### 6-8. 🆕 백테스터가 순서를 못 본다 · 절단이 «셋»이다
`ma5/run.py:810` `allowed = {d: set(v) …}` — 선택이 `set` 이 되는 순간 순서가 소멸한다. §2-2 의 3단 합성으로 이것을 피한다.

### 6-9. 🆕 소비 자리의 «다른» 장치 셋
① **섹터뉴스 재정렬**(§4-1 · shadow) ② **안전성 필터 지연 절단**(거래정지·VI·관리종목이 11위 이하를 승격시킨다) ③ **`max_daily_trades` 가 매도도 센다**

### 6-10. 라이브 유니버스 ≠ 백테스트 유니버스
라이브 매수의 **97% 가 백테 미검증**. **arm 간 «상대» 비교만 유효**하고 **라이브 기대치로 인용 금지.**
