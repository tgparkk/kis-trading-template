## 2. ✅ 급등봉의 정체 = 거래대금 폭증 (28.8배)

```sql
SELECT date, close, volume, round(close*volume/100000000.0) AS val_eok
FROM daily_prices WHERE stock_code='064260' AND date BETWEEN '2026-07-16' AND '2026-07-24' ORDER BY date;
```

| date | 거래대금(억) |
|---|---|
| 2026-07-16 | 15 |
| 2026-07-20 | 21 |
| 2026-07-21 | 24 |
| 2026-07-22 | 28 |
| **2026-07-23** | **807** |
| 2026-07-24 | 150 |

28억 → 807억 = **28.8배**. 블로그 툴팁 "거래대금 830억, +2,695.76%"(≈28.0배)와 정합한다(툴팁은 체결 기준, 우리는 종가×거래량이라 소폭 차이).

**⇒ 급등봉 판정축 = 거래대금 배수.** 실행계획 Task 4 의 `find_segments` 가 `volume` 만 쓰고 있다면 `trading_value`(또는 `close*volume`) 기준으로 바꿔야 다날 케이스를 재현한다.

## 4. ✅ 「레벨 부분집합의 가중평균」 모델 검증 통과 — 사다리 재구성 전체의 교차검증

다날 레벨 `4,452 / 4,371 / 4,289 / 4,208 / 4,126` + 비중 `10/13/17/25/35` 에 **접두(prefix) 가중평균**을 적용:

| 차수 | 예측 평단 | 태쏘 실측 평단 | 오차 |
|---|---|---|---|
| 1~2차 | 4,406.2 | **4,404.36** | −0.042% |
| 1~4차 | 4,299.3 | **4,297.96** | −0.032% |

두 건 모두 오차 0.05% 미만이고 **부호가 일정하다(실측 < 예측)** — 갭하락 시 지정가보다 유리하게 체결되는 방향과 일치한다. 레벨 5개·비중·평단 계산이 한 쌍으로 동시에 교차검증됐다.

⚠️ 채점은 **접두 부분집합으로만** 한다. 체결은 얕은 레벨부터 순서대로 일어나므로 임의 부분집합은 물리적으로 불가능하고, 자유도만 늘려 오답 정의를 통과시킨다. (설계 §5 의 "단일 레벨 최근접으로 채점하면 정답 규칙을 탈락시킨다"의 반대편 함정이다.)

### 4.1 🔧 구현 주의 — 반올림은 half-up

레벨 2차 `5,100 × (1−0.1430392) = 4,370.5` 는 화면에 **4,371** 로 찍힌다. 파이썬 `round(4370.5)` 는 뱅커스 반올림이라 **4,370** 을 준다. `math.floor(x+0.5)` 를 써야 A급 실측 5수치가 재현된다. 4차 `4,207.5 → 4,208` 도 같은 경우다.

## 5. 🔴 설계 정정 — 시작점·최고점은 **자동탐지가 아니라 사용자 수동 입력**이다

| 종목 | 태쏘 최고점 | 우리 DB `max(high)` | 차 |
|---|---|---|---|
| 삼성전자 005930 | 380,000 | 374,500 (2026-06-19) | **+1.47%** |
| SK하이닉스 000660 | ≈3,001,700 (−58.49% 로 역산) | 2,987,000 (2026-06-25) | +0.49% |
| 다날 064260 | 5,100 | 5,100 | **0** |

**그의 계산 자체는 우리 데이터와 정합한다.** 07-29 글의 "삼성전자는 최고점 대비 −50.21%로 빠진 상황(7.29 장중)" 은 우리 DB `2026-07-29 low = 189,200` 으로 정확히 재현된다:

```
189,200 / 380,000 = 0.497895  →  −50.2105%   (그의 표기 −50.21%)
```

어긋나는 것은 계산이 아니라 **최고점 입력값**이다. 380,000·3,000,000 은 둘 다 반올림된 값이고, 가장 최근·단기인 다날만 정확값이다. 블로그 판매 문구 "**숫자만 입력하면** 최적의 매수 타점이 나옵니다"와 합치면 결론은 하나다.

> **그의 프로그램에는 상승구간 자동탐지 규칙이 없다. 사람이 차트를 보고 시작점·최고점을 입력한다.**

### 5.1 이 발견이 바꾸는 것 3가지

1. **설계 §5 캘리브레이션의 목적을 재정의해야 한다.** "후보 규칙이 그의 시작점·최고점을 재현하는지"는 *존재하지 않는 규칙*을 복원하는 과제다. 백테스트에는 기계적 규칙이 반드시 필요하므로 캘리브레이션은 그대로 하되, 목적을 **"그의 규칙 복원"이 아니라 "그의 실제 타점을 가장 잘 재현하는 기계적 대리규칙 선택"** 으로 바꾼다. 채점표의 해석도 "정답과의 거리"가 아니라 "대리규칙 간 상대 서열"이 된다.

2. **1급 채점은 절대가격이 아니라 하락률로 한다.** 최고점 입력값이 1.47% 어긋나므로 절대가 대조는 정답 규칙도 탈락시킨다. 다날은 완전일치라 절대가로도 되지만, 삼성은 반드시 비율 기준이어야 한다.

3. **🔴 설계 §10 의 기대가 성립하지 않는다.** 설계는 *"FAIL이면 「정의를 잘못 복원해서 FAIL」이라는 잔여 가설이 처음으로 닫힌다. 이건 계열 종결의 값어치가 있다"* 고 적었다. 그러나 복원할 정의가 애초에 없으므로 **이 잔여 가설은 4차로도 닫히지 않는다.** 4차의 값어치는 "레벨 생성 규칙(§2 A·B급)이 판독으로 확정된 상태에서의 검정"으로 축소된다. 사전등록 §7(알려진 한계)에 이 항목을 반드시 추가할 것.

## 6. 🔧 외생 상수 판본(설계 §7 대조판본)의 계수 — 유도 완료

A급 2점을 `x = ln(1+rally)` 로 로그보간한 결과:

| | rally | x | center | width |
|---|---|---|---|---|
| 다날 | 0.29771 | 0.26060 | 0.159020 | 0.063922 |
| 삼성 | 6.14286 | 1.96611 | 0.456250 | 0.166000 |

```
center(x) = 0.113603 + 0.174276 · x
width(x)  = 0.048325 + 0.059852 · x        # c 민감도는 width × (c/0.8)
```

- 삼성 `center`·`width` 는 화면 반올림값(45.63 / 16.60)이 아니라 **레벨 5수치에서 역산한 정확값 0.45625 / 0.16600** 을 썼다. 이 값이라야 `238,165 / 222,395 / 206,625 / 190,855 / 175,085` 가 정수로 정확히 떨어진다.
- 검산: `center=0.45625` vs `(Q1+Q3)/2=(0.353+0.560)/2=0.4565` (차 0.00025) · `width/IQR = 0.166/0.207 = 0.8019` ⇒ 설계 §2.2 의 B급 규칙 두 개 모두 성립.
- ⚠️ **2점 보간이므로 rally < 29.8% 와 > 614% 는 외삽**이다. 결과표에 외삽 건수를 별도로 찍을 것.

## 8. 🔧 실행계획 결함 1건 — OHLC 가드가 범위정합 채널을 안 본다

실행계획 Task 2 의 `drop_bad_ohlc` 는 **NaN 과 `<=0` 만** 검사한다. 설계 §4 는 "OHLC **전체**에 가드"를 요구하는데, 범위정합(`high<low`, `close>high`, `close<low`, `open` 범위 이탈) 채널이 빠져 있다.

실측한 잔존 건수:

```sql
SELECT count(*) FILTER (WHERE NOT(open<=0 OR high<=0 OR low<=0 OR close<=0)
                          AND (high<low OR close>high OR close<low OR open>high OR open<low))
FROM daily_prices;
-- 2650
```

**`<=0` 검사를 통과하는 범위위반 행이 2,650건(전체의 0.093%) 남는다.** 표본:

| stock_code | date | open | high | low | close |
|---|---|---|---|---|---|
| 317770 | 2022-08-09 | 2243 | 2307 | 2236 | **2308** |
| 330590 | 2021-07-06 | 6032 | 6032 | 5983 | **6033** |
| 334890 | 2022-07-28 | 4594 | 4700 | 4594 | **4701** |

전부 `close = high + 1` 패턴 — 수정주가 환산의 1원 반올림 잔차다. 규모는 작지만(1원, 0.02% 수준) **체결·청산 시뮬이 `low ≤ level` 로 사고 `close` 로 파는 구조**라 정확히 이 경로를 탄다.

권고: 가드를 3차 `sweep3.py` 와 같은 형태로 맞춘다.

```python
bad = (o<=0)|(h<=0)|(l<=0)|(c<=0)|(h<l)|(c>h)|(c<l)
```

⚠️ 부수 논점 — 실행계획은 불량행을 **삭제**(`drop`)한다. 3차는 삭제 대신 **누적 불량건수(`badcs`)로 「읽는 구간에 불량봉이 하나라도 있으면 그 이벤트를 통째로 제외」** 했다. 삭제 방식은 시계열 중간에 구멍을 내서 "20거래일 후 종가"가 조용히 다른 날을 가리키게 만든다. 어느 쪽이든 **선택을 사전등록에 명시**하고 제외 건수를 산출물에 넣을 것.
