## 1. 왜 4차를 하는가

1~3차는 전부 FAIL이었고, 그 중 3차가 이미 "진입 트리거·분할관리" 축이었다. 그럼에도 4차를 여는 근거는 **증거의 성격이 달라졌다**는 것 하나다.

1~3차의 최대 약점은 저자의 규칙을 **추측으로 복원**해야 했다는 점이다(1차는 cos 0.975까지 맞췄지만 여전히 복원이었다). 이번에는 07-29 글에 **그의 프로그램 화면이 그대로 노출**되어 매수 규칙이 수치까지 역설계된다. 복원이 아니라 판독이다.

부수적으로 처음 들어오는 축이 둘 있다. **상승폭에 조건부인 하락폭 분포**라는 정량 규칙, 그리고 **60분봉 타임프레임**이다.

⚠️ 단, 3차의 검정력 결론("거래당 1.7%p 이상의 엣지 없음")은 그대로 유효하다. 4차도 같은 벽에 부딪힐 수 있으므로 **MDE를 실행 전에 산출해 사전등록에 적는다**(§8).

## 5. 상승구간 정의 — 스윕이 아니라 캘리브레이션으로 닫는다

1차에서 정의공간 576셀을 훑고 배운 것은 **정의가 결과를 지배한다**는 것이었다. 이번에는 자유도를 격자로 풀지 않고 라벨로 닫는다.

**후보 규칙 계열**
```
시작점  = lookback W일 내 최저가를 기준으로, 다음 3변형 중 하나
          (a) 그 최저가 자체
          (b) 최저가 이후 첫 급등봉(거래량 급증 봉)의 시가
          (c) 그 급등봉 직전 봉의 종가
최고점  = 시작점 이후 최고 고가
활성화  = 상승폭 ≥ R%
유효기간 = 최고점 이후 D거래일 이내
```

변형 (a)는 다날에서 이미 반증된다(최저 3,805 ≠ 시작점 3,930). 그래도 기준선으로 남겨 채점 대조에 쓴다. 다날의 3,930은 급등 직전 구간의 가격대이므로 (b)/(c)가 유력 후보다.

**캘리브레이션 셋**

- **1급 (2건)** — 삼성 `53,200 → 380,000 (+614.3%)`, 다날 `3,930 → 5,100 (+29.8%)`.
  후보 규칙이 이 시작점·최고점을 재현하는지 직접 대조. 다날의 `시작점 3,930 ≠ 최저 3,805`가 강한 판별 조건이다.
- **2급 (23종목)** — 07-30 글의 체결표 실제 매입가와 차트 최고/최저 라벨.
  예: 가온칩스 42,260 / 47,040 / 50,000 (최고 83,200(04/27), 최저 34,950(07/03)), 동신건설 13,726, 다날 4,290 / 4,297.96 / 4,404.36.
  후보 규칙이 만든 5레벨과 실제 매입가의 거리로 채점한다.

  ⚠️ 2급 라벨은 **평균단가**다. 다날에서 4,404.36 ≈ 1·2차 가중평균(4,406), 4,297.96 ≈ 1~4차 가중평균(4,299)로 검산되므로, 채점 시 **단일 레벨이 아니라 "레벨 부분집합의 가중평균"과 대조**해야 한다. 단일 레벨 최근접으로 채점하면 정답 규칙을 탈락시킨다.

**진출 규칙**: 채점 상위 **1~3개 정의만** 본검정에 올린다. 탈락 정의도 사전등록에 전부 기록한다(사후에 정의를 갈아끼우는 경로를 봉쇄).

## 6. 매수 레벨 생성

```
center = (Q1 + Q3) / 2
width  = c × IQR                       # c = 0.8 고정, 민감도 {0.6, 0.8, 1.0}
p[k]   = center + (k - 3) × width / 4  # k = 1..5  →  center + {-2,-1,0,1,2}×width/4
level[k] = peak × (1 - p[k])
weight[k] = [10, 13, 17, 25, 35] %     # 고정, 하방가중
```

**부호 검산(필수 회귀 가드).** 삼성 `center=45.63, width=16.60` → `p = 37.33 / 41.48 / 45.63 / 49.78 / 53.93` → `level = 238,165 / 222,395 / 206,625 / 190,855 / 175,085`. **1차가 최고가, 5차가 최저가**이며 비중은 최저가 쪽에 35%가 붙는다. 구현 시 이 5개 값을 단위테스트로 못 박는다 — 부호를 뒤집으면 사다리가 거꾸로 서고 하방가중이 상방가중이 되는데, 총 체결금액은 비슷해서 합계 검증으로는 잡히지 않는다.

**체결 규칙(일봉)**
- 당일 `low ≤ level[k]` 이면 `level[k]` 가격에 체결
- 갭하락(`open < level[k]`)이면 `open` 체결
- 미체결 레벨은 유효기간 만료 시 소멸, 부분 체결 포지션은 체결분만 보유

## 7. 분포 생성 — 2판본 병행

**본검정: PIT 자체추정.** 각 진입 판정 시점 t에서 **t 이전 데이터만으로** 상승폭 버킷별 하락폭 분포를 추정한다. 기본값은 다음과 같이 두고 사전등록에서 확정한다.

- **버킷**: 상승폭 로그 스케일 5구간 — `20~50 / 50~100 / 100~200 / 200~400 / 400%+`
- **최소표본**: 버킷당 30건 미만이면 해당 시점 진입 금지(밴드 미생성)
- **극단값 제외**: 상하 각 2.5% 절단(= 95% 범위)

절단 규칙은 그의 화면과 정합한다 — 표본 119개 중 6개 제외는 5.04%이고, 이는 "95% 전체 분석(범위 20.3~68.0%)" 표기와 일치한다. look-ahead 차단이 이 판본의 존재 이유다.

**대조판본: 외생 상수 고정.** 삼성(상승 614.3% → 중심 45.63%)·다날(상승 29.8% → 중심 15.90%) 2점을 로그-보간해 밴드를 고정한다. 우리가 파라미터를 고르지 않으므로 과최적화·생존편향이 진입 규칙에 스며들지 않는다. 단 **2점 보간이라 외삽 구간은 취약**하며, 상승폭 29.8% 미만과 614% 초과는 외삽임을 결과에 표기한다.

두 판본이 갈리면 그 자체가 정보다 — 우리 추정이 문제인지 규칙 자체가 문제인지 분리된다.

## 8. 대조군·통계·판정

**대조군.** 같은 날, 같은 활성화 종목 풀에서 **진입 가격만 무작위**로 5분할한다. 비중(10/13/17/25/35)과 청산은 전략과 완전히 동일하게 부착한다. 이래야 "그 자리에 정보가 있는가"만 남는다.

**청산(고정, 양쪽 동일).** 보유 **20거래일** 후 종가 청산 1점 고정(사전등록에서 확정). 마지막 분할 체결일을 기산점으로 하며, 전략·대조군 모두 같은 기산 규칙을 쓴다 — 기산점을 달리 잡으면 3차의 기한 비대칭이 그대로 재발한다.

⚠️ **절단 건수를 양쪽 다 센다.** 3차에서 전략만 13.1% 절단되고 대조군은 구조적 0건이라 헤드라인 4수치가 뒤집혔다. `bt_tasso.py` 기한 비대칭과 같은 클래스의 2번째 재발이었으므로, 이번엔 **양쪽의 보유기간 완주 가능성을 실측**해 산출물에 넣는다.

**통계량과 판정**
- 거래당 초과수익 Δ, t 통계량
- 판정: **White Reality Check max-t, p < 0.05**. 정의 후보 × 분포판본 × c 민감도 3점이 모두 격자에 들어가므로 보정 없이는 최대값이 발견처럼 보인다(1차에서 양수 142/564·최대 +10.59%p가 보정 후 소멸한 전례).
- 비용: 왕복 **0.21%**(거래세 0.18% + 수수료 0.015% 양방향) 반영
- **MDE를 실행 전에 산출해 사전등록에 기록.** 3차가 "1.7%p 미만은 탐지 불가"로 끝났으므로, 이번 표본에서 몇 %p까지 잡히는지 먼저 적고 시작한다.

**필수 산출물**
1. 연도별 분해 (2026 포함/제외 양쪽)
2. 양쪽 절단 건수
3. 셀별 표본수
4. 상승폭 버킷별 분해 (조건부 구조가 실제로 작동하는지)
5. 캘리브레이션 채점표 (정의 후보별 1급·2급 점수)

## 10. 예상 결과와 그 근거

**예상: FAIL.** 근거는 세 가지다.

1. 같은 계열 1~3차가 전부 FAIL이었고, 그 중 3차가 이미 분할관리 축을 다뤘다.
2. 이 규칙은 본질적으로 "급등 후 되돌림 매수" = 평균회귀이며, 발굴 프로그램 종결 결론("이 데이터에 접근 가능한 선별 알파 없음, 찾아온 엣지는 시장 베타")과 같은 공간에 있다.
3. 그의 7월 실적(500만원·약 20%)은 **2026년 합성 불장 한 달, 표본 1개월**이다. 통계적 근거로 쓸 수 없다.

**그럼에도 검정하는 이유**: 규칙이 추측이 아니라 판독으로 확정된 첫 사례이므로, FAIL이면 "정의를 잘못 복원해서 FAIL"이라는 잔여 가설이 처음으로 닫힌다. 이건 계열 종결의 값어치가 있다.

⚠️ FAIL은 "엣지 없음"이 아니라 **"MDE 이상의 엣지 없음"**으로만 서술한다.
